# v0.20.0 M0：真实 Scion 提案试验

后续实验比较任务的代码与真实浏览器提案对照另见 [comparison/experiment.md](comparison/experiment.md) 和 [收据清单及最终失败记录](comparison/review.json)。该批仍是已暴露开发输入，不能与本页记录合并成未见案例的成功率。

这是实现者编写的三个开发输入，以及在同一批已暴露输入上的一次协议修订。它们不是独立盲测，也不计入路线图要求的十二个新教学单元最终验收。原始失败保留，不以修订后的检查结果覆盖第一次结果。

## 环境和方法

- 本机 macOS 26.5.1、Apple M4 Max、48 GiB 内存、16 核；Chrome 152。
- 在应用 localhost runtime canary 上运行实际 Scion/Gemma 4 权重，base-only；没有训练或激活 adapter，没有在线推理请求。
- 复用一个 Chrome 页、同一个模型实例，六次调用串行。第一轮模型下载与加载耗时 69,767 ms，不能称为暖缓存加载成绩。
- 上下文 8192；temperature 0、topK 1、topP 1、seed 7、thinking false。第一轮输出预算 1536 tokens，第二轮 1024 tokens。完整配置、输入、原始输出与运行身份保存在 JSON 收据中。

首次三项都因 Markdown JSON 围栏被严格探针记为 `invalid-json`。生产解析器已有单层围栏兼容，这部分是传输格式差异，不能夸大为模型完全不懂 JSON。但读出围栏内对象后，三项 `unknowns` 都是字符串而不是要求的数组，中文 `studentWork` 也是错误字段类型；上述语义问题也依然存在。

第二轮三项都是无需去围栏的有效 JSON，摘录能在来源中找到，检查器返回零结构问题。该检查器没有验证角色是否正确、必需信息是否完整或推理前提是否成立，因此零问题不等于教学提案合格。不能把 3/3 格式通过写成 100% 教学正确率。

第二轮同时缩小任务、缩短输出并更改提示；耗时降低只能描述这三个输入上的整个协议变化，不能归因于某个单独变量，也不能据三次调用估计可靠的 P95。

## 对实现计划的影响

1. 不直接把模型生成的答案和 rubric 当作权威。让模型先提出来源绑定和未知项，再由支持的确定性操作推导，并保留教师审阅。
2. 下一步按任务族定义窄字段：数量任务需要分别定位数值、单位、被观察群体与排除范围；日期任务需要事件、归属与日期；实验任务需要组别、基线、干预、时长、测量和重复。不能把“任意角色＋整句摘录”当成可执行结构。
3. 提取字段需引用来源和明确片段；类型、数值、单位、重复/遗漏、操作前提都要验证。语义歧义返回具体待确认项，不能仅修复 JSON 后继续编译。
4. 先用开发输入完善协议和教师修正路径，再冻结并运行未参与修复的新输入；保留第一次结果。现有两轮不足以冻结模型质量门槛或宣称三类任务的自动提取已经可用。
5. 已确认结构的编辑、求解和材料投影继续争取零模型调用。这个实验没有改变生产模型调用或激活新自动路径。

这份审读由实现者完成。它支持继续进行有边界的工程试验，不证明学生学习收益、独立评分公平性或竞争优势。
