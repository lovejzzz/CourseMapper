# V0.17.10 Roundtable Output-Quality Audit

Date: August 1, 2026

Audited base: `46671c99` (`v0.17.09`)

Evidence package: `Python for Public Policy - Course Materials (6).zip`
Method: six Roundtable rounds / 18 participant turns, direct repository inspection, full representative DOCX/PPTX rendering, package-manifest inspection, and targeted executable regressions.

## Goal

Make EDUTOOL's generated course materials materially more coherent while making every automated score disclose the exact kind of evidence that earned it.

## Lane

Compiler composition, assessment-modality classification, rubric evidence alignment, deterministic defect detection, evidence-score decomposition, and score-ledger verification.

## Release Boundary

V0.17.10 fixes the reproduced deterministic defects and the audited score-reporting integrity gaps. It does not activate semantic grounding or assessment-coherence credit, certify pixel-perfect rendering, claim instructor approval, or change the Scion model weights.

## Verdict

V0.17.09's fixed 100-point ledger was arithmetically honest, but its presentation still overstated what the 59 points meant. The production package was not publication-ready even though it reported 89/B encoded-defect conformance and passed the existing slide checks.

The observed 59/100 decomposed into:

- 44/45 from narrow positive metrics: ordered lesson-title token matching and masked visible-unit variation.
- 15/15 from negative-evidence-only conformance: no registered structure, format, or identity defect fired.
- 40/100 unobserved: rendered-claim grounding and objective-task-rubric coherence were not evaluated.

V0.17.10 keeps the fixed 100-point potential and keeps both semantic constructs unobserved. It corrects the package-specific attainable ceiling, publishes the evidence polarity, derives the qualitative band from narrow positive metrics, and makes the score-ledger verifier reject forged ceilings, bands, decomposition fields, and rule polarity.

The first pushed V0.17.10 implementation was then subjected to a separate three-round / nine-turn adversarial Roundtable code audit at exact commit `a1226931`. That audit correctly rejected the initial description of the ledger as tamper-resistant: its arithmetic checks were sound, but an attacker could rewrite the rule schema, component projection, or cached quality block while preserving balanced totals. The release was reopened and hardened.

A third three-round / nine-turn room then audited exact commit `5756a04a`. It also refused certification. It reproduced a coherent deletion of a real P1 deduction, showed that texture findings made an honest shipped ledger fail replay, and found remaining modality, concept-map, article, DOCX, and readiness-receipt boundaries. Those findings define the final predeploy repair below. No audited commit is called a checkpoint merely because CI is green.

## Production defects reproduced

1. A policy-memo assessment titled `Evidence explanation: Python and pandas for public datasets` was classified as a code lab solely because its topic contained `Python`. The assignment then demanded a computing environment, computation, and a verification milestone, while the rubric's generic performance bands graded policy organization and format.
2. Native authoring composed `Audit a practical the pandas ...` by inserting a determiner-led lesson title into an article-bearing template.
3. Compact source labels removed internal conjunctions, producing `Python pandas for public evidence brief`.
4. Concept-map hubs used a character-bound prose truncator, producing the incomplete identity `Python and pandas for public`.
5. The package manifest contained zero admitted sources, zero trusted concept-linked sources, and no rendered claim receipts. Grounding therefore remained genuinely unobserved.
6. Rectangle/OOXML checks passed while the rendered deck still showed an awkward final-slide footer and semantically broken labels. Existing fit checks are structural evidence, not pixel-render or teachability evidence.

## Changes implemented

- Narrowed code-lab classification. `Python` alone is now a topic, not a modality signal; genuine computational, notebook, script, code, or contextual Python-lab titles still take the lab path.
- Added code-lab-specific performance bands for computation correctness, code clarity, verification evidence, and feedback-informed revision.
- Rephrased native authoring slots so determiner-led titles cannot collide with template articles.
- Preserved internal `and` / `or` in compact evidence labels.
- Restricted concept-map hubs to complete admitted candidates that fit the visual budget; character-truncated prefixes are not identities.
- Added a score-bearing narrow grammar detector for framing-adjective/determiner collisions such as `a practical the`.
- Added explicit user-facing construct names: ordered lesson-title sequence match, masked visible-unit variation, rendered claim support, objective-task-rubric coherence, and encoded package-defect conformance.
- Added polarity-aware evidence totals and package-specific evaluated coverage. For the audited shape, the expected disclosure is `44/45 narrow positive metrics · 15/15 negative-evidence-only conformance · 40/100 unobserved`.
- Updated score-ledger verification to recompute coverage, polarity totals, attainable ceiling, evidence ceiling, and band from the rule rows.

## Post-push adversarial hardening

The second Roundtable room inspected code rather than release prose and found four consensus blockers plus several classifier and language boundaries. The accepted repairs are:

- Pin the exact five-rule deterministic evidence protocol: version, rule IDs, constructs, operators, maxima, dependencies, evidence paths, statuses, and evidence polarity. Missing, extra, renamed, reweighted, or demoted rules now fail verification.
- Replay each rule from its independently bound observations. Predicate results, points, statuses, evidence fingerprints, and anti-gaming fingerprints must match the canonical replay; balanced arithmetic is not sufficient.
- Validate the five user-facing component rows as an exact bidirectional projection of the canonical rule ledger.
- Pin and replay the conformance ledger's nine dimensions, weights, statuses, negative deductions, texture metric, severity caps, and aggregate metadata.
- Replace the cached-quality prose regex with a structured, canonical package-readiness binding. Current status, blocker/warning counts, issue IDs, affected surfaces, and relevant values must match before cached grading is reused.
- Classify explicit programming labs, Python labs, Jupyter notebooks, scripts, and debugging work as computational; reject memo, brief, report, essay, proposal, plan, reflection, and presentation genres unless they also require executable artifacts.
- Reject dangling concept-map hubs and fail over to an honest `concept definition panel` instead of emitting an incomplete map identity.
- Detect generic adjacent article collisions, not only the originally observed `a practical the` shape.
- Remove a vacuous band assertion and replace it with exact producer-reachable band expectations.
- Strip a duplicated answer-key prefix at the DOCX rendering boundary, preventing `ANSWER — A A ...` and the article-corrected `ANSWER — A An ...` without weakening answer-position admission checks.

Adversarial regression coverage now includes forged predicates, dropped and unknown rules, reweighting, integrity-rule demotion, component divergence, conformance-schema mutations, mutually rewritten cached blocks, policy/computing modality boundaries, dangling hubs, adjacent articles, and answer-key rendering.

## Exact-commit checkpoint repair

The `5756a04a` room found that the preceding hardening was still not sufficient. The accepted final repair adds these constraints:

- Export `QUALITY_FINDINGS.json` as the independent, reason-bearing receipt for every P0/P1/P2 result. Its exact bytes, count, path, and SHA-256 digest are bound into `SCORE_LEDGER.json`.
- Require every negative conformance deduction to match one canonical finding by rule/version, finding identity, points, severity, evidence tier, reason, action, file, and quote. A deleted deduction can no longer be hidden by coherently rewriting the score and display.
- Keep the texture metric as a positive-and-negative metric row while projecting texture finding severities from the independent receipt. Honest texture P1/P2 findings now drive the displayed counts and severity cap without masquerading as one-to-one negative deductions.
- Cross-check structure, format, and identity scores between the deterministic package-integrity rule and the conformance ledger.
- Export `PACKAGE_READINESS.json`, bind its exact bytes in the ledger, and make the public verifier validate the receipt directly. Readiness is no longer only a same-process cache comparison.
- Replay the exact predicate operator, expected value, and actual value for both evaluated and unobserved rule states. This closes the thin-package curriculum/texture variants missed by the hand-built fixture.
- Give documentary genres precedence over incidental programming-topic language; a `Python assignment: policy memo` is not a code lab without an executable artifact.
- Fall back to a concept-definition panel whenever fewer than two valid concept-map spokes survive.
- Detect every adjacent `a` / `an` / `the` pair in either position.
- Strip a DOCX explanation prefix after bare whitespace only for the single-letter A–D answer-key form. Phrase answers such as `Elastic` remain intact unless followed by an explicit key delimiter.

Real-producer regressions now exercise a genuine `deepQualityGrader.grade()` result containing both P1 and P2 texture findings and require its emitted ledger to self-verify. Extracted DOCX text proves phrase-answer explanations retain their opening words.

The guarantee remains intentionally bounded. These receipts make the unsigned package internally replayable and make each score explainable. They do not establish origin or resist an attacker who rewrites every artifact, receipt, ledger, and hash together. That stronger guarantee requires trusted regrading from artifact bytes or an external signature/transparency service.

## Pre-commit code audit corrections

A separate three-round, nine-turn Roundtable room then challenged the live working tree rather than this report. It found additional release-blocking trust defects, all reproduced before repair:

- verified-download recovery accepted a passed label with zero completed checks and did not enforce receipt-v2 `downloadSafety`;
- manifest export warnings used `warnings` while receipt v2 read `warningCount`, so the Export handoff erased warning evidence that belonged in Agent;
- Export rebuilt warning/blocker domains without the canonical schema version, causing the trust reader to ignore them;
- the source-leak blacklist could delete legitimate in-discipline PRISMA, Alzheimer, CES-D, and similar material because its topical escape excluded the course's own scope tokens;
- a rejected cached score could survive in the returned readiness receipt when fresh grading timed out;
- the legacy assessment repair changed prose references while preserving the old sentence-shaped definition, creating an identity mismatch;
- whole-sentence source cleanup could empty a required title, note, objective, or single-item list;
- the adjacent-article detector misread `a priori`, uppercase answer/grade `A`, and `A/B`, while the initial predicate-based fix was incompatible with the release gate's regex-tuple contract;
- the first subtitle rule dropped valid instructional clauses containing serial lists.

The accepted corrections require positive export-check counts, zero failures, zero download blockers, and receipt-v2 verification; preserve canonical Agent warning domains; replace rejected cached scores with `not-graded`; use immutable request/course-map scope plus explicit offender-to-discipline hints across repair, grading, kernel admission, and reading attachment; normalize legacy assessment identity definitions and references together; preserve non-empty review placeholders when an entire required field is unsafe; and share one tuple-compatible article regex across the release gate and live grader. The content-grade gate remains intentionally fail-closed. `downloadSafety` proves structural preparation and file-export verification; it does not authorize bypassing a missing or timed-out quality proof. Export and `downloadCourseMaterialsZip()` therefore keep the same release policy.

## What was deliberately not done

- Grounding points were not activated from source-ledger booleans. The current producer runs before rendering, supplies no rendered locations, and uses order-insensitive lexical overlap. Those receipts cannot prove rendered-claim entailment.
- Assessment-coherence points were not activated from broad conformance checks. The new regression fixes the reproduced contradiction, but one fixed classifier does not establish a calibrated objective-task-evidence-rubric measurement protocol.
- The score was not rewritten as `59/60 = 98%`. That headline would mix narrow positive metrics with absence-of-defect credit and recreate inflation.
- A global article-deletion rewriter was rejected. It could damage legitimate reduced relative clauses. The repair stays at the owning composition slots with a conservative detector as a safety net.
