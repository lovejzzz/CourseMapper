# v0.19.1：数量推理与作业答案隔离

本轮保持 0.18.7 界面、本地 Scion、十类材料和导出选项。改动集中在 compiler 的明确数量关系与材料投影；没有更换模型权重、训练或启用 adapter，也没有启用共享在线推理。

## 修复的实际问题

v0.19.0 的数量任务常依赖来源直接包含 `7/12` 之类分数。新的小型数量操作模块记录每个操作数的来源位置，检查条件后才计算：

| 操作             | 已暴露的原失败案例                                    | 新的参考结果                           | 要求学生展示的理解                                             |
| ---------------- | ----------------------------------------------------- | -------------------------------------- | -------------------------------------------------------------- |
| 两组合并比例     | 两个仓库分别退回 9/10、45/90 件物品                   | `(9+45)/(10+90)=54%`；非加权平均为 70% | 分母代表组规模，合并物品不能直接平均两组百分比；数值不解释原因 |
| 重叠集合的界限   | 80 名会员中，30 人参加讲座、25 人参加工作坊，交集未知 | `30/80` 至 `55/80`，即 37.5% 至 68.75% | 减去重复计数；解释上下界何以可达，以及需要补充哪项观察         |
| 计数与计量的区别 | 20 户中 8 户用雨水桶，只有总用水量，没有分组水量      | 已知 40% 的户数；不知道用水量占比      | 给分子和分母标注单位；户数不能代替水量；总量不提供分组量       |

独立练习使用另外的虚构来源包。重叠练习进一步要求处理两组人数之和超过总人数的情形；合并练习更换分母、分子及情境；计量练习从户数/水量改为设备数/能耗。答案、错误反馈和评分档位跟随各自的练习，不能使用主例题的答案。

在实际 Word 导出中发现：作业第一页的“学生自查”直接复制了 rubric 的最高档描述，包含完整答案。已改成过程检查；完整解答保留在后面的教师参考页。原回归检查在三个样例上失败，修复后通过；浏览器 PDF 检查同时验证答案页之前不出现新样例的计算结果。这个修复也应用于已有共享任务的自查投影。课程包中的教师版 rubric 和学习指南仍按用途包含答案，不能当作无答案的考试卷发放。

线上导入后又发现一次反馈错配：针对“组别导致更好结果”的错误，提示却解释了非加权平均何时成立。已让提示直接要求识别组间差异及隔离因果关系所需的证据，并验证主任务、学习指南和评分反馈一致。新增回归先失败再通过；这项发现没有被计入盲测成绩。

## 每类材料的检查

| 材料               | 本轮检查重点与结论                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------- |
| Course Map         | 学习目标、来源及评估指向同一任务；实际 XLSX 保留完整文本                                    |
| Syllabus           | 任务与评估对齐，不把 rubric 的 100 分当作课程总评权重；机构政策仍需教师确认                 |
| Lesson Plans       | 45、35、40 分钟的课程安排与输入一致；示范、练习和反馈使用同一个任务                         |
| Slide Decks        | 三套分别为 16、15、15 张；示范推理在独立练习之前，来源和新练习分开；实际 PPT 渲染无可见裁切 |
| Assignment Briefs  | 任务和来源完整；学生自查不提前提供计算结果；教师答案另起页                                  |
| Rubrics            | 三项标准按 30/40/30 分计分；四档明确区分运算、解释、边界及具体错误                          |
| Discussion Prompts | 围绕计数与推理的不同解法，而非只要求泛泛“讨论重要性”                                        |
| Quiz & Exam Bank   | 主任务、错误诊断、新情境和反馈重做具有对应答案；导出的答案页独立                            |
| Study Guides       | 完整示范、错误解释、独立题和答案；实际 Word 为三页，信息较密集，需教师按学习者程度选择使用  |
| Course FAQ         | 说明课程目标、需要准备的材料、任务标准和反馈方式；不填造机构政策                            |

三套完整 Office 包包括 24 份 Word、3 份 PPT、3 份 Course Map XLSX；另检查 CSV 和 ZIP。全部 100 页 Office 渲染做了排版总览，重点放大复看作业和 rubric；三套新案例的 27 份真实浏览器 PDF 检查页面边界、数学符号及答案分离。内容审读是本实现者的判断，不是独立教师评分。

## 可复核的验证与边界

- 35 项新增自动测试覆盖正确计算、60 组程序生成的算术组合、错误计数、不同单位、近似数、重复或额外组、矛盾的交集材料、完整 finalizer 和九类衍生材料的源编辑同步。原有冻结案例及首次失败记录不变。
- 18 个开发案例仍为 0 个自动缺陷。首次 12 个留出案例原有 11 个不支持、24 个自动缺陷；现在作为**已暴露回归**运行，4 个任务受支持、8 个仍不受支持，共 18 个自动缺陷。没有更改答案或降低检查器要求，也没有把这些案例重新称为未见测试。
- 新操作只覆盖有明确条件的英文来源句式。现阶段只合并两组；不解析任意自然语言、不补猜重复身份、不自行推断实验因果关系。其他复杂历史来源、实验设计和中文操作的原失败仍然保留。
- 1013 项必需软件测试和 14 项独立 benchmark 检查器测试通过。浏览器验收包括原有编辑/导出/移动布局、三个新增 PDF 案例及生产构建的失败重试路径；精确提交的 CI 和部署记录随 GitHub Release 发布。
- 没有本轮模型质量提升、教师间评分一致性或学生学习增益的证据。这是一次可验证的 compiler 改进及答案隔离修复，不是通用“课堂就绪”认证。

复现：`npm run check`；`npm run test:e2e`（单 worker）；`npm run test:production`（先 build）；`npx vite-node scripts/benchmarks/runClassroomAcceptance.ts --split exposed --out .audit-work/quantity-regression`。已暴露复查结果保存在 `benchmarks/classroom/v2/results/v0.19.1-exposed.json`。
