# V0.14.3 Roadmap — The Quality Surface: receipts in the product, breadth in the net, depth in the content

**Source analysis:** the v0.14.2 Crucible loop (4 live rounds, baseline 51–59 F
→ 100/100/100/100 zero-P0/P1, ~$1.70 total). The loop proved two things at
once: (1) the deterministic grader is trustworthy enough to _ship_ — it found
eleven live-only bugs and never drifted into noise after calibration; (2) a
score of 100 now means "no detectable defects," not "nothing missing." The
decks still carry ~3 content slides in a 12-slide frame, rubrics grade process
more than task, weekly quizzes stop at 6 items, and five genome disciplines
(econ, stats, psych, nursing, astro) have never been through a live round.

**Thesis:** quality measured but invisible is half its value. V0.14.3 turns
the quality system _outward_ (every package ships its own audit), turns the
net _wider_ (10 reference courses + a stranger slot, nightly), turns the bar
_upward_ (substance thresholds raised, content upgraded to meet them — all
deterministic), and starts deleting the compiler heuristics the registry made
redundant. Plus a standing workstream: the Crucible is a tool we keep sharp.

**Target (acceptance):**

- Every generated package contains `QUALITY_REPORT.md` and a
  `manifest.quality` block; the export panel shows the badge ("Quality 98 · A
  · 0 issues"); the in-app score agrees with the Crucible's on the same
  artifacts (within the documented dimension exclusions).
- A 10-course Crucible round runs green: the 4 audit courses ≥ today's 100s
  under the RAISED thresholds, the 6 genome-covered courses each genome-link
  > 0 lessons live (first live exercise of the genome path at breadth).
- Depth slice live: ≥5 of 12 deck slides carry teachable content per lesson;
  rubric criteria quote their assignment's actual parameters; weekly quizzes
  reach 8 items when kernel banks have unused items — at zero new AI calls
  and per-course cost within $0.08–0.15.
- Compiler diet phase 1: every provably-dead legacy branch instrumented,
  proven unreached across the fixture matrix + a live round, then deleted —
  with the golden harness green and a measured line count reported.
- Crucible: parallel generation (round wall-clock ≤ 8 min for 4 courses),
  spend guard, verdict-ledger calibration, history trend report.

**Principle:** unchanged — deterministic code does the work, the model is
paid only for disciplinary authorship; and code must not assert what it did
not check. New corollary: **a grade the user can't see is overhead; a grade
they can see is a product.**

## WS-A — The quality badge: the package grades itself (flagship)

**A1. Make the grader app-loadable.** Move `tests/lib/deepQualityGrader.js`
and `tests/lib/artifactDefectPatterns.js` to `src/lib/quality/` (they are
already plain ESM with no vitest imports — by design). `tests/lib/` keeps
one-line re-export shims so the Crucible, the gate, and existing imports stay
stable. Refactor the fs-bound extraction (`extractPackage`) behind a
`FileProvider` interface: `{ list(): paths, readBinary(path), readText(path) }`
— Node implementation for the Crucible (fs), browser implementation reading
the in-memory file map that `packageZipExporter.js` already builds before
zipping (the export verifier at `packageExportVerifier.js` walks the same 38
files in-browser today; reuse its access pattern).

**A2. Grade at finalize.** In the deterministic package finalizer flow (after
`export_verify_done`, before the digest), run the grader against the
just-built file map + the in-memory budget/digest objects. Dimension
adjustments for in-app mode, documented in the module: the honesty
dimension's console-log scan is replaced by direct budget/digest object
checks (same assertions, better source); everything else runs identically.
Async and non-blocking: grading ~116 files with jszip costs 1–3s — run it
behind the existing finalizer spinner, never block the download on it
(timeout 10s → badge shows "not graded" rather than delaying export).

**A3. Surface it in three places.**

- `PACKAGE_MANIFEST.json` gains `quality: { score, grade, graderVersion,
findingCounts: {p0,p1,p2}, dimensions, gradedAt }`.
- `QUALITY_REPORT.md` (the existing `renderReportMarkdown` output) ships
  inside the zip root — the package carries its own audit.
- UI: ExportSidePanel badge chip ("Quality 98 · A") next to the existing
  trust strip, click → modal rendering the report (markdown renderer already
  exists for chat). P0s found at this stage also surface as finalizer
  warnings through the existing readiness channel (they should be impossible
  — the gates run earlier — which is exactly why showing them is cheap
  honesty).

**A4. Bundle discipline.** The grader becomes its own lazy chunk loaded with
the export flow (not in AppFlow): add a `quality-` budget entry to
`scripts/checkBundleBudgets.mjs` (measure first; expect ~40–60 KiB raw). The
landing bundle must not grow at all.

**A5. Tests.** (1) Browser-mode FileProvider grades the same fixture package
byte-identically to fs mode (minus excluded checks — assert the exclusion
list explicitly); (2) output-artifact gate asserts `QUALITY_REPORT.md` +
`manifest.quality` present and score ≥ 85 on the healthy fixture; (3) a
seeded-defect fixture surfaces its P0 in `manifest.quality.findingCounts`
AND the readiness warning channel; (4) Crucible cross-check: the round
report includes an `inAppScore` column read from each downloaded package's
manifest — drift > 3 points between in-app and Crucible scores fails the
round (the two graders must never diverge silently).

## WS-B — Breadth: 10 reference courses, the genome under live fire, nightly

**B1. Six genome-covered courses join `scripts/crucible/courses.mjs`**, each
prompt built so lesson titles hit shard concepts (the live genome path has
NEVER been exercised at breadth — 0 of 4 current courses link more than 3
lessons):

- `econ-intro` — Principles of Microeconomics, 14 lessons (econ shard: 16
  kernels with real prerequisite edges — the judgment layer's first live
  workout: include one deliberately out-of-order lesson pair so the
  prerequisite-gap diagnosis MUST fire and render a primer).
- `stats-intro` — Introductory Statistics, 14 (stats shard; p-value,
  sampling, regression lessons).
- `psych-101` — Introduction to Psychology, 15 (psych shard).
- `nursing-fundamentals` — Foundations for Nursing Practice, 14 (nursing
  shard; cardiac output worked example should surface).
- `nutrition-101` — Human Nutrition, 14 (nutrition shard; kcal worked
  examples).
- `astro-101` — Introduction to Astronomy, 12 (astro shard; the v0.13.1
  live-proof course returns as a permanent regression resident).

**B2. Grader learns the genome bar.** New honesty checks: for a course whose
inferred discipline has a shard, `manifest.pipeline.genomeLinker` must show
at least one linked lesson (else P1 "shard exists but never linked — resolver
or alias drift"); genome-linked lessons must carry cited key terms (the v0.14
displacement bug's regression net, now live); for econ-intro's seeded gap,
the judgment line must show the bridged gap and the lesson plan must carry
the primer (P1 if silent). Per-discipline vocab packs for the six new
courses (mirror the existing four).

**B3. The stranger slot.** `--stranger` adds one course from a rotating
pool (art history, business ethics, K-12 earth science, intro philosophy,
music theory, public speaking) — graded on generic dimensions only
(discipline probes off). Strangers exist to break assumptions, not to pass:
their findings file separately as `stranger-findings.md` and don't gate.

**B4. Cadence.** Full 10-course round ≈ $1.10–1.40, ~30 min sequential (≤15
with WS-E parallelism). Releases: full round required before tag (the
"Round-N" protocol becomes documented policy in the roadmap's release
checklist). Nightly: `crucible-nightly.yml` (cron + workflow_dispatch) doing
smoke (2 courses, ~$0.25) nightly and the full 10 weekly, API key from a
repo secret, round report uploaded as an Actions artifact, P0 fails the run.
**Open decision for the user:** putting an OpenAI key in repo secrets spends
~$10–15/month autonomously — confirm before B4 lands; B1–B3 don't depend on
it (local runs cover releases).

## WS-C — Compiler diet, phase 1: delete what the registry made dead

The V0.13 P6 gate ("retire compiler inference heuristics only after live
four-course proof on the graph path") is now satisfied four times over.
Phase 1 is conservative: instrument → prove dead → delete. No rewrites.

**C1. Instrument.** Add a dev-only `legacyPathTelemetry` counter (module-level
Map, logged by the Crucible driver and the test harness) at the entry of
each suspect branch:

- `buildStudentArtifactLabel`'s fusion path (registry path bypasses it since
  Phase 3; legacy-only).
- `deriveBlueprintForCompiler.shouldRebuildAssessmentAnchors`'s legacy
  rebuild branch.
- `compiledLanguageFinalizer`'s ARTIFACT_KIND title-pattern inference where
  registry `kind` is available on the target.
- `splitConceptValues`' comma-split fallback + `OBJECTIVE_STEM_LEAD_RE`
  stripping for graph-derived lessons (graph concepts arrive typed).
- The quiz `criterionObjectiveAlignment` strategy-label matcher where
  registry/outcome ids could key directly.

**C2. Prove.** Run the full fixture matrix (blueprint-quality-matrix, golden
harness, all v0141 suites) + one live 10-course round with telemetry on.
Since v0.13.1, `adoptCourseGraph` runs in all four project-open paths and
restore derives graphs for legacy projects — the hypothesis is that several
branches are UNREACHABLE in any current flow. Every branch with zero hits
across matrix + live round is certified dead.

**C3. Delete** certified-dead branches outright (no flags, no comments
pointing at history — git remembers). Branches with hits get a one-line
note in the phase-2 backlog instead. Report the measured deletion (target:
1,500+ lines from `courseBlueprintCompiler.js`'s 16k) and compile-time
delta. Golden harness must stay byte-green throughout; any byte change
means the branch wasn't dead — restore and move it to the backlog.

**C3 — SHIPPED RESULT (honest finding, not the hoped-for deletion):** the C2
matrix + the 11-course live round proved that **no branch is independently
deletable**, and the conservatism paid for itself by catching a real bug:

- `student-artifact-fusion` was hypothesized dead on the graph path —
  **FALSIFIED** by the matrix (it still fused lesson-level artifact labels
  and shipped them into prose ~1,300×/course). Fixed the same day:
  `registryStudentArtifactTitle` overrides `studentArtifact` from the
  verbatim registry title in `extractLessonBlueprint`; the telemetry now
  pins **zero** registry-path hits as the permanent net. This single find
  justified the whole instrument-before-delete discipline.
- `finalizer-kind-inference` — **FALSIFIED**, load-bearing (supplies the
  short-reference noun); rekey to registry-kind+title-head is **v0.14.4 D1**.
- `objective-stem-strip`, `quiz-strategy-label-match` — alive on the graph
  path; rekey candidates for **v0.14.4 D2**.
- `legacy-anchor-rebuild`, `concept-comma-split` — **zero on every
  graph-path class** but exclusively exercised by the _legacy (no-graph)_
  compile path, so they cannot be deleted in isolation without breaking
  map-only projects. The real deletion target is therefore the **legacy
  compile path itself** (~3–5k lines), which requires completing the V0.13
  P5 derive-graph-on-open migration — scoped as **v0.14.4 D3**.

So C3 deletes nothing this release _by design_: the matrix reclassified
every candidate as either load-bearing (rewire, not delete) or legacy-path-
exclusive (the legacy-endgame, deferred). The instrumentation, the fusion
fix, and the permanent regression test ARE the WS-C deliverable.

**C4. Regression net.** The telemetry stays in the tree (cheap), and the
Crucible round report gains a `legacyPathHits` line — if a future change
resurrects a deleted pattern's need, the counter shows it before an audit
does.

## WS-D — The depth slice: raise the bar, then meet it (all deterministic)

Calibration rule for every threshold below: measure Round 4's actual values
first, set the new bar halfway between measured and ideal, never beyond what
the upgraded compiler provably produces on fixtures.

**D1. Decks: from 3 content slides to 5+.** The kernel data already paid for
more than the deck shows. Add two deterministic slides when data exists:

- "Common pitfalls" slide: the lesson's misconception/corrective pairs
  (today rendered only in study guides + warm-up polls) become a 2–3 bullet
  slide with the corrective framing ("It's tempting to think X — in fact
  Y").
- Second worked-example/application slide: unused kernel mcBank items
  recast as a worked multiple-choice walkthrough (stem + why the right
  answer is right — the explanation text already exists in the answer key).
  Deck length becomes 12–14 data-driven; the PPTX audit line should stop
  reading uniform.
- Grader: content-slide counter (slides whose body carries domain tokens vs
  meta/scaffold text) — P1 below 5 per deck.

**D2. Rubrics: criteria quote the task.** The registry gives every brief its
assessment identity, and the brief's `parameters` list is structured (Phase
1C). Rubric criterion 1 becomes parameter-derived: "Include at least one
nested structure" → criterion "Nested structure present and correct (per
brief parameter 2)". One criterion per parameter (cap 3) + the existing
evidence/communication criteria trimmed to 2. Grader: rubric
task-specificity check — ≥1 criterion sharing ≥2 content tokens with its
brief's parameters; P1 otherwise.

**D3. Quiz banks: 6 → 8 items where the bank affords it.** Two more MC
slots filled from unused kernel mcBank items (course-level offsets from
v0.14.1 4.6 already prevent cross-lesson duplication; the review-week and
exam draws already dedupe). No new frames — slots stay empty (bank
exhausted) rather than meta-filled. Grader: item-count check conditional on
bank size (never punish thin-shard courses).

**D4. Threshold raises** (after D1–D3 land, calibrated per the rule):
boilerplate P1 at >50% for rubrics/FAQ/discussions (from 60%), meta-MCQ
share >15% (from 20%), sample-answer engagement <60% (from 50%). Each raise
lands in the same commit as the content upgrade that makes the four
reference courses pass it — the bar and the jump move together.

## WS-E — Sharpening the Crucible (standing workstream, this release's slice)

- **E1. Parallel generation:** two browser contexts per round (the app is
  stateless across tabs; API rate limits allow 2 concurrent generations).
  4-course round 12→~7 min; 10-course ~30→~16 min. Sequential fallback flag.
- **E2. Spend guard:** `--max-spend <usd>` (default 2.50): the driver sums
  per-course digest costs and aborts the round past the cap — a runaway
  generation can never become a bill.
- **E3. Retry-once:** a course whose generation fails (network, provider
  5xx) retries once before the round reports it failed; failure screenshots
  - console saved either way (already) plus the failing phase in the round
    table.
- **E4. The verdict ledger:** `verification-output/crucible/verdicts.json` —
  every finding ever confirmed true or false-positive, keyed by
  (pattern/check, course, evidence-hash). `--calibrate` reruns the current
  grader across ALL stored rounds and diffs against the ledger: any
  known-TRUE finding now missed = regression; any known-FP resurfacing =
  regression. This formalizes the manual stash-and-compare archaeology from
  rounds 1–2 into one command that gates grader edits.
- **E5. History:** `crucible:history` prints the per-course score trajectory
  across all stored rounds (the table from the release notes, generated);
  ROUND_REPORT gains the trend line automatically.
- **E6. Round diffing:** `--diff <roundA> <roundB>` — per-course,
  per-deliverable-type content diff summary (changed/added/removed sections
  by heading), so "what actually changed in geology L8 between rounds" is
  one command instead of manual extraction.
- **E7 (optional, off by default): `--judge`** — an LLM pass on 3 sampled
  artifacts per course scoring the axis the deterministic grader can't:
  would a professor teach from this as-is? (1–10 + two sentences). Advisory
  only, never gates, ~$0.05/course, requires explicit flag. This encodes
  the manual deep-read I performed each round — the human-taste axis —
  without ever letting a model veto deterministic receipts.
