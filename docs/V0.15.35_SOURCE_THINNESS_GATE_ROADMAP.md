## Goal

Make CourseMapper distinguish sourceRef bookkeeping from meaningful research
grounding. A package should not look almost perfect merely because every atom
has a sourceRef when those refs collapse onto one ambiguous metadata row and
review-only course-map fallback proof.

## Lane

Narrow grader and audit-helper correction. This release does not build the full
ResearchSession planner, does not claim genome coverage, and does not turn the
current package into 100/100. It makes the current quality gates tell the truth
about thin source proof.

## Fix Plan

1. Add a source-thinness check.
   - Count sourceRef-covered atoms from `courseIR.sourceRefCoverage`.
   - Treat coverage of many atoms against one thin row as P1 citation debt.
   - Keep ambiguous-license and review-only fallback rows as separate P2s.

2. Keep AI-governance export audits domain-aware.
   - Model-card/model-documentation language is legitimate for AI governance,
     privacy, procurement, and policy-memo courses.
   - Notebook/IPYNB and locally co-occurring data-science lab asset references
     still fail without a bundled asset or Required Assets marker.

3. Add focused regression coverage.
   - The source-ledger grader must flag the exact pattern: 56 covered atoms,
     one OpenLibrary row, one CourseIR review row.
   - The ZIP helper must accept AI-governance model-card documentation while
     preserving the missing-lab-assets blocker for actual ML lab packages.

## Non-Goals

- Do not weaken the source-ledger grader.
- Do not inflate package scores or hide source review debt.
- Do not synthesize fake OpenAlex rows from digest text.
- Do not claim the full source-grounded ResearchSession architecture is done.
- Do not claim live 100/100 quality until a deployed package honestly regrades
  100/100 with no hidden caveats.

## Release Boundary

Ship only if focused regressions, release-history audit, format, lint, full
test suite, gold smoke, build, bundle check, and browser verification pass
locally. After push, Fast verification and GitHub Pages deploy must complete
before the release is claimed.
