# V0.15.118 TDM License Trust Gate Roadmap

## Goal

Close the license-truth gap exposed by the fresh deployed v0.15.117 User
Experience Design Studio ZIP/log audit: a Wiley `tdm_license_1.1` URL was
exported as trusted sourceLedger proof even though it is a publisher
text-and-data-mining policy, not a reusable teaching-material license.

## Evidence

- App version: `0.15.117`
- Run ID: `run-1782707619178`
- Visible package result: `Quality 99`, `Texture 92`
- Local regrade before this patch: `99/A`, no P0/P1/P2 findings
- Local regrade after this patch: `99/A`, one citation P2
- Problem row: `sf3`, `Test Plans`, DOI `10.1002/9780470316795.ch6`
- Ambiguous license evidence: `http://doi.wiley.com/10.1002/tdm_license_1.1`

## Lane

1. Treat `tdm_license` URLs as ambiguous license proof.
   - This includes Wiley-style `tdm_license_1.1` URLs and similar TDM policy
     tokens, not only `/tdm/` path pages.

2. Apply the rule in production source-ledger assembly.
   - Source-finder rows with TDM policy/license URLs must not become trusted
     bibliography rows.

3. Apply the rule in local regrade.
   - Existing packages that already trusted those rows must receive citation
     findings instead of staying falsely source-clean.

4. Preserve explicit reusable licenses.
   - Creative Commons, Wikipedia CC BY-SA, OpenStax/OER, and other explicit
     reusable-license rows remain trusted when URL/DOI-backed and concept-linked.

## Release Boundary

- This release changes source-license trust accounting only.
- This release does not weaken source standards, hide review rows, or inflate
  scores.
- This release does not solve the remaining texture target.
- This release does not claim clean provider output until a fresh deployed
  v0.15.118 audit verifies the rule in real output.
