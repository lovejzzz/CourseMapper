# v0.15.66 Concept-Linked SourceRef Proof Roadmap

_Written June 26, 2026. Target app version: `0.15.66`._

## Evidence

v0.15.65 stopped metadata-only source rows from replacing CourseIR review proof,
but the bridge and source-quality checks still had one loose edge: a source row
could be accessible, licensed, and provider-trusted while carrying no lesson or
concept linkage.

That row is useful review metadata, but it is not sourceRef proof for course
atoms. Counting it can make coverage look stronger than the exported teaching
evidence really is.

This is CourseMapper-side export and grader accounting, not an AI-model issue.

## Goal

SourceRef coverage should count exported source proof only when the row is:

- accessible by URL or DOI,
- non-ambiguous in license,
- from a trust-eligible provider,
- linked to a course concept.

Unlinked source metadata should remain visible in `SOURCE_REPORT.md`, but it
must not inflate `courseIR.sourceRefCoverage.sourceLedgerRows` or satisfy the
deep quality sourceRef proof checks.

## Lane

Package export and source-quality truth. This release tightens accounting for
the source/research bridge. It does not change provider retrieval, lower source
standards, or claim a fresh deployed package is 100/100.

## Changes

1. Source-ledger summaries now report `conceptLinkedCount` and
   `trustedConceptLinkedCount`.
2. Package export only bridges CourseIR sourceRef proof to trusted,
   concept-linked source rows.
3. Deep source-ledger checks use trusted concept-linked rows for sourceRef
   coverage strength and wiring findings.
4. Focused regressions prove trusted but unlinked OpenAlex rows stay exported
   for review without inflating sourceRef coverage.

## Release Boundary

In scope:

- Align sourceRef bridge eligibility with trusted concept-linked source proof.
- Keep generic source metadata review-visible.
- Make source-quality findings explain the difference between trusted metadata
  and trusted concept-linked source proof.

Out of scope:

- Claiming a fresh v0.15.66 package is 100/100 without a deployed ZIP/log audit.
- Changing source-finder provider ranking or model behavior.
- Fixing slide-deck depth or whole-package texture.
