# v0.8.61 Agent Cost and Trust Roadmap

## North Star

The agent should feel like a colleague who already did the work: instant on reads, one provider call (or zero) on routine edits, escalating to expensive models only when a cheap pass measurably failed, and always able to show — in the workspace, not in audit files — what was compiled, repaired, assumed, and what still needs the instructor's eyes.

v0.8.6 made generation cheap and provenance visible. v0.8.61 does the same for the agent loop, which is now the largest remaining provider spend, and turns the trust strip from a status line into a navigable surface.

Predecessors: `docs/V0.8.6_COMPILER_EFFICIENCY_ROADMAP.md`, `docs/NEXT_STEPS_AUDIT_2026-06-09.md`.

## Agent Vision

Where the agent is going across v0.8.61 and the releases after it:

1. **Local-first by default.** Anything `inspect_workspace`, readiness checks, or the blueprint compiler can answer deterministically never reaches a provider. The model is reserved for interpretation, judgment, and source-grounded writing — the same boundary the compiler enforces for generation.
2. **A visible cost ladder.** Every agent run can explain its own spend: which steps were local, which ran on the cheap model, which escalated and why. Receipts gain a cost line; the usage panel gains a routed-vs-escalated split. Instructors should trust the agent partly because they can see it being frugal.
3. **Edits as cascades, not conversations.** A targeted edit triggers deterministic stale regeneration of affected compiled deliverables (already shipped), and the agent narrates the cascade in one receipt: changed, recompiled, verified, skipped — typically with zero additional provider calls.
4. **Memory that compiles.** Learned preferences and the institution profile stop being prompt text and become compiler knobs (tone, difficulty, slide-note density, feedback style, naming). The agent's "I'll remember that" should change deterministic output, not just future prompts.
5. **The boundary stays hard.** Missing deliverables are refused, destructive work is confirmed, official facts (dates, weights, policy) are never invented. Every cost optimization ships inside the existing red-team and real-browser gates so frugality never buys back unsafe behavior.

The end state, aligned with ROADMAP's "consider it done" direction: an instructor asks for a change, the agent applies it locally where safe, recompiles what it touched, verifies by reading state back, and hands over a receipt — fast enough and cheap enough that nobody thinks about tokens.

## 1. Lean Course-Map Default-On Gate

Goal: flip `generationPlan.leanCourseMapAtoms` to default after proving no quality loss.

Implementation slices:

1. Add a lean-mode pass to the 34-course sweep (`audit:v085:sweep` profile flag) compiling from lean-expanded course maps.
2. Run `audit:gold` and confirm no sample exceeds the 60-family copy-variety budget.
3. Run a private live A/B (one small, one standard fixture) with the `API-dontComit` key pattern; record output-token deltas and examine-trigger rates in `verification-output/lean-course-map-ab/`.
4. Port continuation prompts (`continueForMissingLessons`) to the lean contract so completion chunks stop paying verbose-prose costs.
5. Flip the default; keep the verbose contract behind a flag for one release as rollback.

Definition of done:

- Sweep 34/34, gold 40/40, variety budget respected, measured output-token reduction documented, default flipped.

## 2. Agent Model Routing Proof

Goal: cost-efficient models first; escalation only on measured failure (ROADMAP v0.7 item 7).

Implementation slices:

1. Audit `agentModelRouting.js` call sites; ensure routing decisions are actually applied to agent loop calls, not just computed.
2. Record `routedModel`, `escalated`, and `escalationReason` on every agent loop call in `apiUsageCost` events.
3. Surface a routed-vs-escalated counter in agent receipts and the developer usage panel.
4. Add escalation triggers: failed validation after an edit, malformed tool plan, response-quality scorecard failure.
5. Extend the real-browser agent harness with scenarios asserting cheap-first behavior and at least one forced escalation.

Definition of done:

- A standard 25-scenario browser proof shows the majority of calls on the routed cheap model with zero response-quality regression, and receipts show the split.

## 3. Agent History Compaction

Goal: stop mid-conversation token growth from dominating agent cost in the 20-iteration loop.

Implementation slices:

1. Measure: log per-iteration input-token estimates for a long browser-harness conversation; record the baseline curve in `verification-output/agent-history-compaction/`.
2. Compact tool results older than N turns: keep tool name, target ids, and receipt-grade outcome; drop raw payloads (the agent can re-read state with read tools if needed).
3. Never compact: safety confirmations, pending proposals, the current task's working set, and user messages.
4. Keep the static prompt byte-stable so provider prefix caching keeps hitting.
5. Add regression tests for multi-turn flows (change-of-mind, undo, verify-after-edit) against compacted history.

Definition of done:

- Long-conversation input tokens flatten instead of growing linearly, with the multi-turn agent suite and 25-scenario browser proof still green.

## 4. Trust Strip Phase 2

Goal: from status chips to a navigable trust surface.

Implementation slices:

1. Persist `repairsApplied` and last finish-run summary into the project snapshot so restored projects keep their trust state (today it resets with the session).
2. Add a review-required chip derived from blueprint local-review/source-review flags (count of lessons needing instructor eyes).
3. Make chips clickable: compiled → provenance summary, auto-fixed → repair list from the finalizer summary, review → the flagged lessons.
4. Mirror the strip in the Export side panel so trust state is visible at the moment of handoff.
5. Extend `tests/package-trust-strip.spec.js` for persistence-across-restore and click-throughs.

Definition of done:

- A restored project shows the same trust state it was saved with, and every chip answers "show me" in one click.

## 5. Phase 5 Repair Library Completion (carried from v0.8.4)

Goal: deterministic repairs before any model retry.

Implementation slices:

1. Inventory current finalizer retry triggers; classify each as deterministic-repairable vs genuinely semantic.
2. Implement compiler/finalizer recipes for the deterministic class: scoring math, coverage gaps, placeholder language, stale titles/artifact names, FAQ category gaps.
3. Gate model retries on "deterministic repair attempted and insufficient"; record both in the proof bundle.
4. Reduce `REPAIR_RETRY_CALL_LIMITS` once the sweep shows repairs absorbing the load.

Definition of done:

- The 34-course sweep passes with measurably fewer reserved model retry calls, and receipts show repair-before-model ordering.

## 6. External Proof Collection (parallel track)
