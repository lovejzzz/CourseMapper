# v0.15.41 Source Proof Fallback Roadmap

_Written June 20, 2026. App version: `0.15.41`._

## Goal

Fix the fresh v0.15.40 Genetics and Society audit without weakening the quality
bar: when CourseMapper says a source-backed, CurriculumV1, or knowledge-backbone
pipeline ran, the downloaded ZIP must include source proof. If trusted source
rows are missing, the package must say so through review proof instead of
silently omitting `SOURCE_REPORT.md`.

## Lane

ZIP export truth and source-proof fallback. This lane stays inside package
assembly, manifest proof, and source-report generation. It does not change model
prompting, source retrieval, source scoring, or quality thresholds.

## Release Boundary

In scope: source-backed export proof recovery, CourseIR review fallback proof,
release manifest, release contract, roadmap, and focused exporter regression
coverage. Out of scope: claiming trusted bibliography when no URL/DOI/license
proof exists, changing source-thinness scoring, resolving license ambiguity, or
completing the broader research-once source ledger architecture.

## Evidence

The 20260620T230414Z EduTool.dev audit ran against deployed v0.15.40
(`3ade0e2`). Fast verification and Pages deploy were green before the run. The
fresh Genetics and Society package exported successfully and downloaded as:

- `verification-output/edutool-audit-loop/20260620T230414Z/Genetics and Society - Course Materials (6).zip`

Local regrade reproduced the package report:

- quality: `99/100` (`A`)
- texture: `94/100`
- findings: `0 P0`, `1 P1`, `0 P2`
- export verification: passed

The P1 was an export truth failure, not a model-content issue:

- `source-backed pipeline did not export sourceLedger, sourceRef coverage, or SOURCE_REPORT.md proof`

The run digest showed why the package should have carried proof:

- `nativeAuthoring`: CurriculumV1 repaired four lessons/four assessments
- `native_c1_repaired` stats: `sourceLedgerRows: 1` and source-linked outcomes,
  activities, worked examples, assessments, and rubric criteria
- `knowledgeBackbone`: `5 open resources (openlibrary: 1, source-finder: 4)`

The ZIP still shipped no `SOURCE_REPORT.md`, no `sourceLedger`, and no
`courseIR.sourceRefCoverage`. That left the instructor with a strong grade but
no source receipt for the source-backed claims.

## Fix

Package export now checks the pipeline state before writing the manifest. When
the pipeline expects source proof and the export graph has no source rows, the
exporter derives a CourseIR source-proof fallback from the exported course map.

This fallback is deliberately conservative:

1. It does not invent trusted bibliography.
2. CourseIR rows without URL/DOI/license proof are written as
   `sourceReviewRows`, not `sourceLedger`.
3. `SOURCE_REPORT.md` explains the review status and lists sourceRef coverage.
4. Existing trusted source rows still win; the fallback only fires when the
   exported source-ledger bundle is empty.

## Verification

Focused regression coverage recreates the live failure shape:

1. `buildCourseMaterialsZip` receives source-backed pipeline state, a sparse
   export graph, and a normal course map.
2. The ZIP includes `SOURCE_REPORT.md`.
3. The manifest carries `sourceReviewRows`, `sourceReport`, and
   `courseIR.sourceRefCoverage`.
4. The manifest does not promote the fallback row into trusted `sourceLedger`.

## Carry Forward

This release fixes silent export proof loss. It does not yet make every
CurriculumV1 atom backed by a semantically strong trusted source. The broader
research architecture still needs the planned research-once source ledger:
trusted retrieval adapters, concept-linked source rows, compiler-time sourceRef
use, source-license policy, and stronger source relevance checks for all
generated atoms.
