# V0.15.178 Source Review Truth Roadmap

## Evidence

- Fresh deployed v0.15.175 GPT-5.4-mini Python ZIP/log evidence:
  `verification-output/edutool-audit-loop/20260701T042053Z-v015175-fresh/`.
- The audit found a real, licensed, but off-topic `Session (software)` source row linked to the
  artifact label `Quiz,Assignment`.
- Fresh deployed v0.15.176 browser evidence later completed visibly at `Quality 98` and
  `Texture 92`, but ZIP/log capture failed, so v0.15.176 cannot be locally regraded.
- The active source standard is stricter than "source looks relevant": trusted proof must be real,
  accessible, license-safe, discipline-appropriate, and concept-linked.

## Goal

Keep source proof honest without throwing away all retrieval evidence. Rejected source-finder
candidates should never inflate trusted `sourceLedger` proof, but if retrieval has no trusted row to
show, the best rejected candidates should remain visible as `sourceReviewRows` so the manifest,
source report, digest, and local grader can explain the source gap.

## Lane

Product/source-ledger truth repair. This is not a grader weakening, source-standard lowering, model
upgrade, or UI copy-only release.

## Release Boundary

This release may claim that:

- metadata-only, license-ambiguous, artifact-linked, or off-topic source-finder candidates still do
  not become trusted `sourceLedger` rows;
- if source-finder retrieval produces only rejected candidates and no trusted proof exists, those
  candidates are retained as review-required rows rather than disappearing;
- when trusted source proof exists, rejected bycatch remains suppressed so export and Agent
  observation surfaces stay concise.

It may not claim a clean 100/100 package until a fresh deployed v0.15.178 ZIP/log audit proves the
UI, ZIP, manifest, quality report, source report, digest, and local regrade agree.

## V0.15.178 Scope

- Preserve the best rejected source-finder candidates as `sourceReviewRows` only when the package
  would otherwise have no source proof from retrieval.
- Mark those rows with explicit review-required status such as metadata/license/access gaps or
  off-topic/course-weak evidence.
- Keep existing behavior that suppresses false-friend bycatch when trusted source proof is already
  present.
- Update export and source-ledger regressions for OpenLibrary metadata-only rows and the observed
  CS/Python `Session (software)` false friend.

## Why This Is CourseMapper-side

A stronger model can suggest better sources, but it cannot guarantee that every candidate is
licensed, on-topic, and concept-linked. CourseMapper owns the source ledger contract. The app must
separate trusted proof from review evidence deterministically before export.
