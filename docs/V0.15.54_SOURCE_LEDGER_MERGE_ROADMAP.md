# v0.15.54 Source Ledger Merge Roadmap

_Written June 26, 2026. Target app version: `0.15.54`._

## Goal

Reduce the real 97/100 quality loss from the fresh v0.15.53 browser package
without weakening the grader. The ZIP was downloadable and honest, but
`QUALITY_REPORT.md` showed duplicated source-ledger rows: trusted DOI/URL rows
were exported beside weaker `syllabus-src-*` copies of the same source, and the
weaker copies created avoidable missing-license P2 findings.

## Lane

Source-ledger export truth. This release changes package proof assembly only:
it does not mark generic `open access` as sufficient, does not hide source
findings, and does not claim 100/100 when a provider really lacks explicit
license metadata.

## Evidence

The v0.15.53 live browser smoke passed and produced:

- `verification-output/cron-browser/2026-06-26T15-49-34-625Z/report.md`
- `verification-output/cron-browser/2026-06-26T15-49-34-625Z/01-startup-finance-and-venture-strategy/startup-finance-and-venture-strategy-package.zip`

The package regraded at 97/A with seven P2 citation findings. Six of the seven
were avoidable duplicates where syllabus-derived rows repeated sources that
already had stronger DOI/URL/provider proof elsewhere in the ledger.

## Release Boundary

In scope:

- Deduplicate source-ledger bundles by stable source identity, especially DOI
  and URL, not row id alone.
- Prefer rows with stronger access, provider, and non-ambiguous license proof
  when duplicate identities collide.
- Preserve concept links when the weaker row has useful lesson placement
  evidence.
- Pin the live failure shape with a focused exporter regression.

Out of scope:

- Treating generic `open access` as an acceptable explicit license.
- Inventing license metadata when the provider does not return it.
- Changing source-ledger quality thresholds.
- Solving the remaining research/license bridge for rows such as `kr2` where
  the provider still only supplies generic open-access proof.

license bridge and prompt-artifact leakage targets.
