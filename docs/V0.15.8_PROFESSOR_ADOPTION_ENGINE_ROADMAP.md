# V0.15.8 - Professor Adoption Engine: implement the benchmark, fix the gaps

_Written June 15, 2026. This is the 0.0.1 version bump after v0.15.7's
professor-adoption research plan. v0.15.7 defined the benchmark. v0.15.8 turns
it into an autonomous quality engine, then uses it to repair the weaknesses it
finds._

## Recommendation

Stop expanding the theory. Build the professor-adoption engine.

The current state is strategically good but operationally incomplete:

1. the professor-adoption benchmark is designed but not implemented,
2. the public professor-source courses are not source manifests yet,
3. CourseMapper has not compiled and scored outputs against those real sources,
4. the self-improvement loop still reports compiler-level weaknesses,
5. output can still sound generic, weakly discipline-specific, or templated,
6. professor approval and public-source benchmark evidence are not yet cleanly
   separated in release claims.

v0.15.8 should tackle each weakness directly.

## Definition of done

v0.15.8 is done only when all of these are true:

1. `npm run audit:professor-adoption:smoke` exists and runs three benchmark
   cases: MIT 18.06 Linear Algebra, Berkeley Data 8, and Yale ENGL 310 Modern
   Poetry.
2. `npm run audit:professor-adoption` exists and runs the full initial 15-case
   public-source benchmark pack, expanding the 12-case starter from v0.15.7.
3. Each case has a committed source manifest with source URL, public
   instructor names, source artifacts, work products, assessment architecture,
   course operations, hard blockers, and judge expectations.
4. The audit writes:
   - `verification-output/professor-adoption/latest.md`,
   - `verification-output/professor-adoption/latest.json`,
   - `verification-output/professor-adoption/latest-ledger.jsonl`.
5. The report has an autonomous decision block:
   - `status`,
   - `nextAction`,
   - `requiresHumanInterpretation`,
   - ranked required actions,
   - exact proof commands.
6. The three current compiler weaknesses are either fixed or preserved as
   explicit required actions:
   - discipline-specific examples and student work products,
   - real source/method/theorem/text/dataset/case/practice artifact names,
   - reduced templated phrasing and repetitive generated language.
7. Release claims say "public-source professor-adoption benchmarked", not
   "professors approved this."

## Build plan

### Lane 1 - Source manifest pack

Create `scripts/professor-adoption/sourceManifests.mjs`.

Each manifest must include:

```js
{
  id: 'mit-1806-linear-algebra',
  sourceUrl: 'https://ocw.mit.edu/courses/18-06-linear-algebra-spring-2010/',
  publicInstructorNames: ['Gilbert Strang'],
  disciplineFamily: 'math-quantitative',
  modality: 'lecture-problem-set',
  sourceArtifacts: ['syllabus', 'calendar', 'readings', 'assignments', 'exams', 'study materials'],
  primaryStudentWorkProducts: ['problem sets', 'worked solutions', 'exam responses'],
  assessmentArchitecture: ['problem sets', 'exams'],
  supportAndOperationsModel: ['lecture sequence', 'study materials'],
  mustPreserveSignals: ['matrices', 'systems', 'vector spaces', 'eigenvalues'],
  genericPhraseRejects: ['course evidence', 'artifact analysis'],
  hardBlockers: ['missing quantitative work product', 'generic evidence prompt']
}
```

The manifest pack is committed source, not generated output. Runtime reports
may copy it into `verification-output/professor-adoption/source-manifests/` for
receipts.

### Lane 2 - Audit CLI

Create `scripts/professorAdoptionAudit.mjs`.

Required modes:

1. `--profile smoke`
   - runs `mit-1806-linear-algebra`, `berkeley-data8-fa25`,
     `yale-engl310-poetry`.
2. `--profile full`
   - runs all 15 committed cases.
3. `--rounds <n>`
   - runs deterministic mutations across the manifest pack for autonomous loop
     testing.
4. `--case <id>`
   - runs one case for focused repair proof.

Add package scripts:

```json
{
  "audit:professor-adoption:smoke": "node scripts/professorAdoptionAudit.mjs --profile smoke",
  "audit:professor-adoption": "node scripts/professorAdoptionAudit.mjs --profile full",
  "audit:professor-adoption:100": "node scripts/professorAdoptionAudit.mjs --profile full --rounds 100"
}
```

### Lane 3 - Scorer and blockers

Create `scripts/professor-adoption/scorer.mjs`.

Score dimensions:

1. source fidelity, 20,
2. discipline fit, 20,
3. deliverable authenticity, 15,
4. instructor workload and editability, 15,
5. student learning clarity, 10,
6. course operations, 10,
7. accessibility and learner agency, 5,
8. package craft, 5.

Hard blockers:

1. fabricated source, professor, reading, dataset, policy, or assignment,
2. wrong deliverable genre for the discipline,
3. generic template language where source-specific evidence exists,
4. invented institutional policy or safety rule,
5. inaccessible or broken exported artifact,
6. untraceable assessment/objective chain,
7. missing primary student work product for the course family.

The scorer should produce findings, not just scores. Every failed dimension
must name:

1. case id,
2. artifact,
3. source expectation,
4. observed output,
5. severity,
6. suspected owner,
7. required repair action,
8. acceptance criteria,
9. proof commands.

### Lane 4 - Compiler repair targets

The first implementation should expect the benchmark to reproduce the current
self-improvement weaknesses. Fix them at the compiler level, not by tuning the
judge.

Target files:

1. `src/lib/courseBlueprintCompiler.js`
2. `src/lib/compiledLanguageFinalizer.js`
3. `scripts/internalSelfImprovementAudit.mjs`
4. `scripts/professor-adoption/scorer.mjs`

Required compiler capabilities:

1. derive `disciplineWorkProducts` from course title, topics, source
   artifacts, and manifest case family,
2. carry `sourceArtifactNames` into assignments, rubrics, lesson plans, study
   guides, quiz banks, and discussions,
3. prefer field-specific verbs and deliverables:
   - math: prove, compute, solve, justify, counterexample, problem set,
   - CS/data: implement, debug, test, notebook, dataset, model, visualization,
   - humanities: close read, interpret, cite passage, argue, revise,
   - language: speak, listen, pronounce, script, dialogue, interview,
   - biomedical/professional: case, patient perspective, design constraint,
     translation, safety, regulation,
   - large-course operations: submit, check, staff, office hours, academic
     honesty, support channel.
4. replace stock phrases such as "course evidence", "course artifact", and
   "materials" when a source-specific artifact is available,
5. preserve the specificity after the language finalizer runs.

### Lane 5 - Tests

Add focused tests before broad release gates.

Required tests:

1. `scripts/__tests__/professorAdoptionAudit.test.js`
   - manifests validate,
   - smoke profile selects exactly three cases,
   - scorer returns a machine-readable decision,
   - ledger rows include owner, action, acceptance criteria, and proof
     commands,
   - public-source evidence cannot be labeled as professor approval.
2. `tests/v0158-professor-adoption-compiler.test.js`
   - math case rejects "course evidence" and requires problem-set/proof or
     calculation language,
   - data case requires notebook/dataset/toolchain/operations language,
   - poetry case requires texts, passage evidence, close reading, and essay or
     discussion criteria,
   - repeated generic phrasing is flagged.

## Report format

`verification-output/professor-adoption/latest.md` must lead with this block:

```md
## Autonomous Decision

Status: repair-required | pass | blocked-source-access
Next action: repair-code | expand-benchmark | rerun-full | no-action
Requires human interpretation: true | false
Rationale: ...

| Priority | Type | Status | Target Area | Action ID | Acceptance Criteria |
| -------- | ---- | ------ | ----------- | --------- | ------------------- |
```

The JSON report must expose the same fields so a future loop can decide what to
do without reading prose.

## 100-round readiness

The 100-round professor-adoption loop should not browse the web every round.
It should use committed manifests as the source contract and mutate pressure
conditions:

1. sparse source fields,
2. overloaded assessment calendars,
3. missing operations,
4. copied placeholder language,
5. mixed modality,
6. large course map,
7. deliverable-specific weak spots,
8. source artifact omission,
9. discipline-family collision,
10. public-source claim-boundary wording.

`npm run audit:professor-adoption:100` is good enough only when:

1. it runs deterministically from committed manifests,
2. it writes 100 ledger rows or explicit pass receipts,
3. it produces a ranked autonomous decision,
4. it can select a repair without agent interpretation,
5. it never claims public source authors approved CourseMapper.
