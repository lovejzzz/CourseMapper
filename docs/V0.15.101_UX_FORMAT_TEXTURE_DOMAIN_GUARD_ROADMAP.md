## Problem

Three different deterministic compiler surfaces kept the run below clean export quality:

1. Enriched assignment parameters were passed through literally, so a harmless model phrase like `3-5 sections` became a strict "N sections" cover-meta finding in a student-facing assignment brief.
2. Slide Deck metadata could still carry stale notebook/model-card terms into a non-data UX package, causing the package gate to block ZIP export.
3. Lesson plans reused the same generic material trio across all lessons, creating the repeated materials shingle shown in the texture audit.

## Release Scope

- Rewrite numeric assignment `sections` parameters into student-facing `labeled parts` before Assignment Briefs and rubric criteria render them.
- Scrub stale `Jupyter`, `IPYNB`, `starter notebook`, `data-science-notebook`, and unsupported `model-card` text from non-data slide-deck IR and compiled slide-deck output.
- Preserve legitimate model-card language for data-science and AI-governance courses.
- Vary the generic lesson-plan material strings by lesson focus and artifact.
- Add compiler regressions for the v0.15.100 failure shapes.

## Non-Goals

- Do not weaken the strict quality grader or semantic validator.
- Do not claim clean 100/100 until a fresh deployed v0.15.101 ZIP/log audit proves it.
- Do not change source retrieval, source-ledger scoring, report/digest accounting, or UI layout in this release.

## Release Boundary

Ship only the compiler-output cleanup for the v0.15.100 findings: assignment parameter wording, non-data slide-deck lab-asset quarantine, and lesson-plan material texture. Keep source-ledger, report-truth, and UI-panel cleanup as evidence-led follow-up work.
