# V0.15.131 Progress Ribbon Truth Roadmap

## Goal

Stop the workspace progress spine from showing clean completion checks while
the package is still building, enriching, verifying, or blocked on review.

## Evidence

- Fresh deployed audit attempt:
  `verification-output/edutool-audit-loop/20260629T152606Z-v015130-fresh-blocker`
- Course: User Experience Design Studio
- App version: v0.15.130
- Run id observed before browser-control capture hung: `run-1782745776255`
- Visible state: `Enriching lessons 1-12`, `Deliverables 0/9`,
  `1 material ready`, disabled `Package ZIP`, and top action disabled as
  `Building...`.
- UI truth issue: the progress spine could show a checked `Map` stage while
  the visible Course Map preview still contained intermediate/unfinished cells.
- Runtime blocker: clicking generation-progress details made Chrome show a
  `Page Unresponsive` dialog before a ZIP/log audit could be completed.

## Diagnosis

The pipeline state machine used one `done` rendering state for two different
truths:

- a phase had handed control to the next phase; and
- the exported package was terminally ready.

That made earlier build phases render with emerald checks during enrichment,
compile, verify, and blocked states. The UI was technically narrating phase
handoff, but to an instructor it reads as material completion.

## Lane

1. Separate phase handoff from verified completion
   - Keep `active` for the running phase.
   - Add a neutral `settled` render state for earlier phases during an
     unfinished build.
   - Reserve emerald `done` checks for terminal ready work.

2. Keep blocked/caveated states out of clean-ready visuals
   - Blocked finish states should not inherit green checks just because the
     finish pass stopped.
   - The needs-review message and package card carry the user decision.

3. Regression proof
   - Pin enrichment, compile, verify, lull, blocked, syncing, and ready step
     states in the pipeline-machine tests.
   - Pin the rendered BuildRibbon markup so running builds contain no check
     SVG paths for settled phases.

## Fix

V0.15.131 updates the shared pipeline step selector and the BuildRibbon renderer:

- `deriveStepStatuses` now returns `settled` for earlier phases while a build is
  still running or paused between phases.
- Green checks are reserved for `ready` and post-ready `syncing` states.
- Blocked finish states render prior phases as neutral settled progress instead
  of clean-ready checks.
- `BuildRibbon` renders settled phases as neutral dots and exposes
  `data-status` for stable browser/test assertions.

## Release Boundary

- This release fixes progress UI truth; it does not claim a clean ZIP output.
- This release does not weaken source, export, report, digest, or quality
  grading standards.
- This release does not fix the separate Chrome `Page Unresponsive` blocker by
  itself; a fresh deployed v0.15.131 ZIP/log audit is still required.

## Remaining Target

Fresh deployed v0.15.131 ZIP/log evidence is still required before claiming the
strict-clean target:

- overall 100/100
- texture 100/100
- no source review caveats
- no off-topic, metadata-only, or false-friend source-ledger rows
- no prompt-artifact or generic Week/Session/Topic leakage
- no premature green/tick UI while the build or package review is unfinished
- UI, digest, ZIP, manifest, quality report, source report, and local regrade
  all agree
