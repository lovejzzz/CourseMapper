# v0.15.27 Research Source Ledger Roadmap

## Goal

Build the first source-grounded research architecture slice for teaching-material
generation. CourseMapper should research once, normalize trusted academic/OER
sources into a ledger, link CurriculumV1/CourseIR atoms to ledger rows, compile
materials from those refs, and export a package-level receipt the grader can
police.

This release is intentionally a vertical slice, not the full research brain.
It strengthens the contract and export proof without adding random browsing to
every deliverable.

## Lane

Compiler architecture, source provenance, package export proof, and grader
truthfulness. This lane changes how CourseMapper carries and audits source
support; it does not change the provider generation UI, the live EduTool.dev
automation cadence, or the broader CourseIR rollout strategy.

## Release Boundary

This release ships a local source-ledger contract slice:

- normalize source rows from existing academic/OER/CourseGraph inputs;
- extend CourseIR sourceRefs to examples and assessment prompts;
- export source-ledger proof and a source report in packages;
- grade the exported proof when present.

It does not claim a full research-session planner, semantic entailment checking
against full source text, provider API-key rollout, external instructor
approval, or a fresh live EduTool.dev 100/100 package.

## Current Audit

### What Exists

- Genome linker: real concept-kernel resolution exists. Genome-linked lessons
  carry quote/citation provenance through `conceptProvenance`, and
  `attachGenomeResources` turns those anchors into CourseGraph resources.
- OpenAlex/OpenLibrary: runtime provider adapters exist in
  `src/lib/knowledge/providers.js`. OpenAlex requests open-access, unretracted
  works; OpenLibrary supplies book metadata. Both degrade to empty results and
  cache weekly.
- Source finder: `sourceFinder.js` builds compact mini-shards and can attach
  top sources to CourseGraph resources.
- CourseGraph resources: resources already have citation, origin, URL, license,
  attribution, and section `resourceRefs`.
- CourseIR sourceRefs: outcomes, activities, and rubric criteria already had
  sourceRefs, and validation rejected missing/dangling refs.
- Package proof: PACKAGE_MANIFEST already carried assessment/readings registries
  and slim CourseIR proof. QUALITY_REPORT already checked citation hygiene,
  off-discipline citations, and registry penetration.

### What Was Weak Or Fake

- CourseIR `sourceLedger` was only `{ id, scope, status, evidence }`. It could
  satisfy validation without title, authors, URL/DOI, license, provider,
  concept links, or checkedAt.
- Worked examples and assessment prompts were not first-class sourceRef-bearing
  atoms, so important factual/instructional content could compile without a
  traceable source row.
- CourseIR projection rendered facts and constraints into supporting resources,
  but source ledger rows themselves were not visible as the approved source
  basis for compiler surfaces.
- Package export had no normalized source ledger and no human bibliography or
  source report. A downloaded ZIP could not prove atom-to-source coverage.
- The grader checked citation strings, but not the exported source ledger
  contract: fake source rows, missing refs, dangling refs, inaccessible source
  rows, unsupported factual claims, and ambiguous licenses were not directly
  audited.
- OpenStax license handling is inconsistent across historical code/comments.
  Current OpenStax pages describe the default textbook license as
  CC BY-NC-SA 4.0 except where noted, while older genome-resource rendering
  still has CC BY 4.0 assumptions in tests and fixtures. This release exposes
  license ambiguity instead of silently expanding the rewrite blast radius.

### Remaining Hallucination Risk

- Runtime retrieval still includes broad providers such as Crossref,
  Wikipedia, Library of Congress, Internet Archive, and OER Commons search
  links in the wider source-finder path. That is useful but not yet a strict
  academic/OER retrieval service.
- Source relevance is improved but still heuristic. It is not yet a
  source-ledger planner that researches once, deduplicates, licenses, checks
  access, and then compiles many artifacts from the approved ledger.
- Existing legacy course-map and source-finder resources can still be plain
  citation strings. The new ledger normalizer makes them auditable, but it does
  not retroactively prove every historical citation.
- Unsupported factual claims are currently checked through sourceRef coverage
  for CourseIR factual anchors, not semantic entailment against source text.

## v0.15.27 Slice

1. Add a trusted source-ledger normalizer for OpenAlex, OpenLibrary, OpenStax,
   CourseIR, genome, instructor, and CourseGraph resource rows.
2. Normalize source rows with title, authors, URL/DOI, license, provider,
   source type, scope, evidence, concept links, checkedAt, access status, trust
   level, citation label, and license ambiguity flag.
3. Extend CourseIR sourceRefs to worked examples and assessment prompts.
4. Build CourseIR sourceRef coverage for outcomes, activities, examples,
   assessments, rubric criteria, and factual claims.
5. Render source-ledger labels into CourseIR supporting resources so compiler
   surfaces are grounded in sourceRefs rather than free citation invention.
6. Export `sourceLedger`, `sourceLedgerSummary`, `courseIR.sourceRefCoverage`,
   and root `SOURCE_REPORT.md` in package ZIPs.
7. Add self-arming grader checks for incomplete source proof, unresolved refs,
   inaccessible rows, unsupported factual claims, and license ambiguity.

## Official Provider Design Notes

- OpenAlex should remain the main scholarly metadata adapter. Its API exposes
  works, filters, search, selected fields, DOI/open-access metadata, and
  supports key-based or polite access patterns.
- OpenLibrary should remain bibliographic metadata only, not a license proof
  for copying book text. Cache responses and respect documented rate limits.
- OpenStax should be treated as OER/source-text evidence, but license strings
  must come from official per-book/page metadata when available because the
  default/license wording has changed across OpenStax surfaces.

## Carry Forward

1. Build a real `ResearchSession` planner: course concepts in, trusted source
   ledger out, no deliverable-by-deliverable browsing.
2. Add provider API keys/config where official docs require or prefer them,
   while preserving offline deterministic compile.
3. Replace source-finder broad browsing with provider-class policies:
   academic metadata, OER/textbook, primary source/catalog, and instructor
   provided.
4. Add access/license verification jobs that refresh ledger rows without
   blocking deterministic compile.
5. Add semantic claim support checks for high-risk factual anchors using cached
   source snippets or quote anchors, not live web browsing.
6. Migrate legacy OpenStax license assumptions through a focused license audit
   rather than broad text replacement.
