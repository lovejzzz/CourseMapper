# v0.16.3 Roadmap — First Five Minutes

**Status:** implemented and locally verified  
**Target:** v0.16.3  
**Release boundary:** interaction-quality release plus a bounded compiler-texture refinement; no new independent-readiness claim

## Goal

Make the path from “I have a course” to “I have a trustworthy workspace” feel obvious on desktop and intentionally designed on mobile. The product should reveal complexity only after the user asks for it, name the next action in plain language, and keep the main action reachable without a long scroll.

This release does not change Scion's model or quality claim. It improves how users enter, configure, and understand the existing system, and it removes several deterministic compiler patterns exposed by the retained Scion package. The compiler work remains contract-tested evidence, not proof that instructors can use every package with minimal edits.

## Audit evidence at the start

The deployed v0.16.2 site was inspected at 1440×1000 and 390×844, then used to generate a real three-session Scion course-map workspace.

### Landing

- Desktop is visually clean, but the full AI configuration panel appears before the user has described a course. System choices compete with the actual first task.
- The headline “Everything you need to teach/learn a course” is broad and uses an awkward slash construction; it does not explain the product's concrete transformation.
- The disabled Continue button gives no reason it is disabled.
- After entering a prompt, the visually primary action says “Adjust setup” while the direct action says “Generate with defaults.” The hierarchy and labels conflict.
- The mobile landing page is 1,344px tall. Scion configuration occupies most of the first screen, the model label truncates, and both useful actions sit below the fold.
- The sample shuffle and configuration-collapse controls are below a 44px touch target.

### Materials and generation setup

- Material cards clamp their descriptions to one line, so several choices become indistinguishable at scan speed.
- The binary “Select all / Clear selection” control offers no sensible starter package between Course Map only and every material.
- The Course Map settings accordion opens by default even though the page instructs users to “Tune only what needs to be different.”
- On a 390px viewport, generation setup reaches 2,648px. The generate action is not sticky, and optional column controls account for most of the scroll.
- Back, Help, scope, accordion, and column actions include controls below the intended mobile target size.
- Initial entry into the lazy-loaded flow visibly replaces the page with a generic full-screen Loading state.

### Generated workspace

- A real public Scion run completed in 11 seconds with 3 lessons and 100/A, proving the core first-use path works.
- On desktop, the three-panel workspace is coherent, but the course-map table remains information-dense.
- On mobile, the title truncates, the Content/Agent/Export switcher is 36px high, and icon-only lesson actions can be as narrow as 16–22px.
- The table technically avoids page overflow, but compresses many columns into an unreadable first view. A true mobile course-map representation remains a later design lane.

## Lane A — Brief first, system second

- Replace the generic headline with a concrete product promise and a short explanatory line.
- Collapse connected Scion configuration by default. Keep provider, model, trust boundary, and review requirement one explicit Edit action away.
- When the course brief is empty, explain what is required instead of showing only a disabled button.
- Once a brief exists, make “Generate full course” the primary action and “Customize package” the secondary action.
- Bring sample and configuration controls up to the mobile target floor.
- Prefetch the main flow while the user is on the landing page so the first transition keeps continuity instead of showing a blank loading interstitial.

## Lane B — A guided setup path

- Add a compact three-step progress indicator: Brief, Materials, Generate.
- Add a “Recommended set” action that selects a balanced instructor package rather than forcing an all-or-nothing choice.
- Let material descriptions wrap to two lines and keep selection state visible without relying only on border color.
- Make the material count part of the continuation action.
- Keep the continuation surface sticky on narrow screens.

## Lane C — Optional means collapsed

- Start generation setup with every material accordion collapsed.
- Keep lesson scope and the final package summary visible; put per-material tuning behind explicit disclosure.
- Add an honest Scion review boundary beside the final action.
- Keep the generate action sticky on narrow screens.
- Increase the mobile target floor for setup controls and column actions.

## Lane D — Mobile workspace handoff

- Allow a two-line course title on mobile instead of silently truncating identity.
- Raise the Content/Agent/Export switcher and labeled/icon actions to a 44px minimum target.
- Preserve current no-horizontal-page-overflow behavior.
- Record a later roadmap item for a card-based mobile Course Map; do not disguise the current compressed table as solved.

## Compiler follow-through — Teach the artifact, not the template

The retained 12-lesson Scion package exposed two issues that a 99/A structural score did not communicate clearly:

- Course FAQ, lesson-plan, slide, and short-answer surfaces still shared long sentence families across nearly every lesson.
- When a lesson listed a quiz before a richer studio task, one-point rounding in compiler-distributed weights could make the quiz the central teaching artifact even though the source did not explicitly weight it more heavily.

The bounded compiler refinement now:

- chooses exams and oral performances first, then production/performance artifacts, then retrieval checks when grading weights are compiler-distributed;
- preserves fully explicit source percentages as the ranking authority;
- rotates fallback FAQ answers and their student-action, assessment-connection, and concrete-example metadata;
- varies flat lesson-plan workshop, collaboration, and closure language plus slide activity debriefs; and
- uses the existing lesson-specific seed to vary evidence-bounded short-answer questions, model answers, and scoring guidance while preserving the cue-free concept-selection and claim-evidence-boundary contract.

On the retained-course export regrade sequence, Course FAQ overlap moved from 7.7% to 4.9% and shared tails from 12 to 1; lesson-plan overlap moved from 6.9% to 3.4% and shared tails from 55 to 14; slide overlap moved from 3.9% to 2.0% and shared tails from 42 to 8. Reprojecting the retained lesson kernels through the new short-answer compiler reduced quiz-bank shared tails from 74 to 29. These are deterministic texture measurements, not a human teachability verdict.

## Verification bars

### Deterministic

- Landing tests pin the new promise, collapsed connected Scion summary, empty-state guidance, and primary/secondary action labels.
- Feature-selection tests pin the recommended set and selected-count continuation label.
- Config tests pin collapsed-by-default optional tuning and the Scion review boundary.
- Source and browser tests pin flow prefetch and mobile sticky action hooks.
- Full formatting, lint, relevant unit tests, production build, and bundle budgets pass.

### Browser

- Desktop and 390×844 landing renders show the brief before AI configuration and keep the next action understandable.
- Mobile landing and generation setup have no horizontal page overflow.
- The mobile generation action remains visible while optional material panels are collapsed.
- The generated workspace's mobile switcher and icon actions meet the 44px target floor.
- A real or retained deterministic generated workspace still reaches Content, Agent, and Export without regressions.
- No new browser console errors.

## Deferred, not hidden

The next workspace-focused roadmap should replace the many-column Course Map table with a mobile card/field view, then simplify the desktop Agent/Content/Export density. v0.16.3 improves the first five minutes and touch ergonomics; it does not claim that every generated-workspace surface has completed its mobile redesign.
