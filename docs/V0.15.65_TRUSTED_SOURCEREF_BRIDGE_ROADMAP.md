# v0.15.65 Trusted SourceRef Bridge Roadmap

_Written June 26, 2026. Target app version: `0.15.65`._

## Evidence

v0.15.64 made source-ledger trust accounting stricter, but package export still
had one mismatched bridge rule: `bridgeCourseIRSourceProofToTrustedLedger`
treated every exported `sourceLedger` row as bridgeable. That meant two
metadata-only rows could replace a CourseIR review row in atom-level
`sourceRefCoverage`, even though the source summary and quality checker now
correctly report those rows as untrusted.

This is CourseMapper-side export truth, not an AI-model issue.

## Goal

CourseIR sourceRef coverage should bridge to exported source rows only when
those rows satisfy the same trusted-row definition used by source summaries and
the deep quality grader:

- accessible URL or DOI,
- non-ambiguous license,
- trust-eligible provider,
- concept-linked row evidence.

Metadata-only rows should still be exported for review, but they must not
replace review-only source proof or make sourceRef coverage look stronger than
it is.

## Lane

Package export source-proof truth. This release aligns sourceRef bridge
eligibility with v0.15.64's trusted-row accounting. It does not change source
retrieval, source ranking, or the deep-quality scoring threshold.

## Changes

1. Package export now filters bridge candidates through
   `isTrustedSourceLedgerRow`.
2. The bridge only replaces CourseIR review rows when more than one strict
   trusted row exists and sourceRef coverage is otherwise complete.
3. Metadata-only Open Library/Crossref rows remain visible in `SOURCE_REPORT.md`
   and `sourceLedger`, with `sourceReviewRows` preserved.
4. A package-export regression proves metadata-only rows do not set
   `courseIR.sourceRefBridge`, do not change `sourceRefCoverage.sourceLedgerRows`,
   and keep Source Review Notes visible.

## Release Boundary

In scope:

- Tighten sourceRef bridge eligibility.
- Preserve review visibility for metadata-only rows.
- Keep the strict grader and source-ledger summary aligned with export behavior.

Out of scope:

- Claiming a fresh v0.15.65 package is 100/100 without a deployed ZIP/log audit.
- Changing source retrieval providers or weakening license ambiguity checks.
- Fixing slide-deck depth or whole-package texture.
