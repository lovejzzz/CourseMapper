# EDUTOOL V0.17.18 — Verified Coherent Draft Checkpoint

## Goal

V0.17.18 asks one narrow question: can Scion consistently turn different kinds of course input into a coherent, inspectable first draft that a teacher can responsibly revise?

The checkpoint is not a claim that a generated course is classroom-validated, factually certified, accessible by expert review, or ready to teach without instructor judgment. It is a publication gate for a strong, honest draft.

## Lane

Scion must plan before it drafts. A course-level blueprint and lesson-specific instructional intent graph establish the governing source facts, objectives, evidence tasks, assessments, visual-analysis needs, and artifact relationships. The compiler then projects that shared plan into the nine exported artifact families.

This release also separates kinds of evidence that older scoring could blur:

- semantic source claims versus structural compiler records;
- prospective generation lineage versus replay repair lineage;
- document integrity versus rendered-page inspection;
- structural accessibility checks versus accessibility certification;
- deterministic conformance versus independent quality judgment.

## Publish standard

V0.17.18 is publish-ready when its bounded release checklist passes:

1. the full unit suite, lint, format, production build, bundle budget, and release-history checks pass;
2. one fresh representative course produces every requested export family;
3. every generated Office artifact opens and renders without a release-blocking defect;
4. the package reports no P0 or P1 finding and no export failure;
5. the release metadata states only what this evidence supports.

The retained representative course is a fresh five-lesson Visual Evidence and Image Analysis export. It produced ten requested export families (the course map plus nine teaching-material families), passed 38 of 38 export checks, rendered 42 Office artifacts across 141 pages, slides, and sheets, and recorded 99/100 deterministic conformance with zero encoded findings, blockers, or warnings. A manual spot-check covered the syllabus, course map, lesson plan, assignment, rubric, and slide deck.

## Why the finish line changed

The earlier research plan required three complete courses, full-frame render receipts, two-order model scoring, claim-by-claim review, and six Roundtable rounds. That protocol is useful for benchmark research, but it made routine publishing depend on a very large proof exercise. It is no longer the release-critical path.

Future quality research can still run broader multi-course campaigns. It must not silently redefine a finished release or block an otherwise verified maintenance release unless a concrete release-blocking defect is found.

## Release Boundary

This is engineering evidence for a strong, coherent first draft. It does not certify factual accuracy, accessibility, instructor approval, classroom effectiveness, or readiness to teach without instructor review. Remote CI and the live deployment remain downstream facts verified after the exact commit is pushed.
