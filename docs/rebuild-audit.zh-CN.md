# EduTool 重建审计：代码、模型与真实教学输出

审计日期：2026-09-05。状态：v0.19.0 候选版，尚未完成发布验收。

本次结论来自实际实现、运行记录和重新生成的课程，不把历史评估文档、模型自评分或测试数量当作教学质量证明。旧实现固定于 `27513a835c5fc9a6bd4a2d98813a04a8afbc55d4`，新实现位于 `src/studio` 和 `server/scion`。这里区分已经实现的行为、实测失败和仍需证明的假设。

## 1. 核心判断

EduTool 最值得保留的产品承诺是：一个可编辑的课程，持续生成相互一致的教学材料。仅给基础模型加名字、套提示词或安装一个 adapter，不足以证明技术壁垒。此次也没有证据支持“前无古人”或已经拥有更强的基础模型。

当前建议是把技术投入集中到三件可检验的事情：

1. **可追踪的课程内容与修改。** 课程、课次、活动、来源拥有稳定身份；各材料从同一份实体投影，避免分别生成后逐渐矛盾。
2. **有明确边界的验证。** 数值由程序复算，引用由原文位置绑定，来源变化使依赖内容失效。文字匹配不是事实推理验证；这条边界必须公开。
3. **以学习任务为单位的生成和改进。** 先设计学生实际要做的工作，再生成示范、练习、答案和反馈。通过具体失败建立回归样例，避免无限增加“质量分”和特殊规则。

这是一套有用的工程基础，还不是已证明的教育效果或不可复制的护城河。后续更有价值的独有数据应来自教师修订及真实学习困难，并且需要同意、去标识化、适当的数据权利和独立验证；本版本没有收集学生行为数据。

## 2. 代码与产品改动

旧 `src` 中有 868 个文件，包含多轮编译器、适配器管理、评估接口、导出和产品逻辑。此次没有继续把它们全部留在默认应用：退休 3,989 个已跟踪文件，把 346 个旧研究、模型运行和 public 文件移出 Git 跟踪但保留在开发机器上。完整旧实现可从固定 Git 版本恢复，见 [恢复说明](legacy-recovery.md)。没有重写历史，也没有删除本地模型权重。

默认产品依赖减少到 12 个，npm 脚本为 20 个；依赖安装减少 725 个包。当前首屏约 311.75 KiB 原始大小、100.89 KiB gzip，包括 HTML、CSS 与标题字体。数字来自实际构建预算脚本，不包含按需加载的提取、导出库、中文 PDF 字体或可选模型。

新的首页只保留主题输入、文件拖放和必要入口。课程创建后提供 13 种材料视图，包括学生手册、教师指南、作业、评分标准、课件和来源集。模型及重型导出库不会因打开首页而下载。

关键代码：

| 实现                         | 已有行为                                   | 边界                                       |
| ---------------------------- | ------------------------------------------ | ------------------------------------------ |
| `domain.ts`、`references.ts` | 稳定身份、版本、修改历史、关联字段同步     | 修改题目不会自动证明原答案仍正确           |
| `storage.ts`                 | IndexedDB 保存、版本冲突保护、课程文件备份 | 无账户、无跨设备自动云备份                 |
| `engine.ts`                  | 串行阶段、检查点、有限修复、实际回复记录   | 部分供应商传输失败没有可保存的回复正文     |
| `evidence.ts`、`context.ts`  | 原文片段、版本和字符位置，有限检索         | 相关性检索可能遗漏信息；引用不等于蕴含     |
| `verify.ts`                  | 数值复算、结构、缺材料、部分重复任务检查   | 不能穷尽学科概念错误或教学可行性           |
| `pedagogy.ts`                | 第二次模型审查，问题定位到具体原句         | 审查者与作者同源，可能漏错或提出错误修正   |
| `materials.ts`               | 从同一课程投影出材料，学生版隐藏练习答案   | 题库复用练习和离堂题，不是未见过的独立考试 |
| 各导出模块                   | 可编辑 Office、PDF、HTML、CSV、Google 转换 | 导出的副本是快照，不会反向或持续自动同步   |

“同步”具体指共享内容在 EduTool 内的所有出现位置一致。修改题目、数据或来源后，相关教学判断仍须重新审核。界面和 README 明确说明这一点，不能把字符串联动宣传为已经解决所有语义依赖。

## 3. Scion、Gemma 与 adapter

当前在线路线是 Google 免费 Gemma 4 31B，由 Cloudflare Worker 持有密钥并进行请求准入。它没有加载我们的 LoRA。浏览器实验路线使用约 3.35 GB 的 Gemma 4 E2B 基座，也没有加载本次新训练的 adapter。

Adapter 方法仍然成立，但 adapter 不是独立模型：推理时仍需要兼容的基础权重、运行时、内存及计算资源。Google 的这个托管端点不接受本地 LoRA；不能通过上传一个小文件让公共托管基座自动应用它。浏览器端 adapter 的可行性与训练质量、设备兼容性是三个不同的问题。

源代码审计发现训练目标掩码问题：右侧 padding 可能进入 loss，assistant 头部匹配可能取到较早或不完整的标记。保留的研究训练器现在使用移位的 attention mask 与最后一个完整 assistant 标记；四个 NumPy 测试覆盖这一表达式。**修复训练代码不等于重新训练，更不等于质量提升。** 本次未推广一个新 adapter。

新真实调用还表明，配置方式本身会影响能力：Gemma 26B 的强制 JSON 实验出现重复与数值错误；将 JSON 契约放入提示并在输出后验证，数值探针能够返回正确的 3.75 均值与 3 中位数。31B 能完成较长教学任务，但证言归因、缺失信息和独立练习设计仍会出错。小模型本地探针没有给出足以优先替代托管作者的证据。

下一轮 adapter 研究应保留：固定基础版本、训练/验证课程隔离、相同输入的基座/adapter 对照、原始回复、教师盲审以及跨主题的失败统计。不能用训练 loss、模型自己给的分数或单次输出变化作为推广依据。研究代码见 [Scion research](../research/scion/README.md)。

## 4. 不租服务器的可用方案及容量

网站静态部署到 GitHub Pages，Worker 只代理与记账，推理使用 Google 免费层。没有租用 GPU 服务器，没有配置付费模型回退。

2026-09-05 在已登录 AI Studio 的 CourseMapper 免费项目中，Gemma 4 31B 显示 30 RPM、16K 输入 TPM、14.4K RPD。实际曾观察到输入 token 峰值超过 TPM，因此只限制请求次数不够。新网关调用 `countTokens` 计算完整输入（包括系统提示和 JSON schema），用 Durable Object 事务预留滚动 65 秒内最多 14,000 输入 token，并为每次请求增加余量。

另设每日 500 次、每分钟 6 次、每访客每日 200 次准入。请求和课程串行；短期忙碌进行有限重试，长期配额不足则保存并暂停。CORS 不是身份认证，这些限制只能约束滥用影响，不能保证免费额度不被耗尽。上线后的实际并发容量仍需观察，不能承诺所有人无限使用。

免费 API 有地区、年龄和数据使用条件。网站告知用户：在线生成面向符合条件地区的成年人，不提交敏感学生记录；Google 免费服务可能用于产品改进并经人工处理。编辑和导出不依赖持续在线生成。参考 [Gemma API](https://ai.google.dev/gemma/docs/core/gemma_on_gemini_api)、[定价](https://ai.google.dev/gemini-api/docs/pricing#gemma-4)、[API 条款](https://ai.google.dev/gemini-api/terms)、[地区](https://ai.google.dev/gemini-api/docs/available-regions)、[输入计数 API](https://ai.google.dev/api/tokens)、[Workers 费用](https://developers.cloudflare.com/workers/platform/pricing/) 和 [Durable Objects 费用](https://developers.cloudflare.com/durable-objects/platform/pricing/)。额度会变化，本报告记录的是本次观察。

## 5. 真实课程审查：未把失败当成完成

测试材料是虚构、非敏感的统计学、英文论证写作和中文博物馆史料课，各四课时、每课 50 分钟。真实运行与机械测试分开保存。一个“完整 JSON”只表示字段齐全，不表示教学合格。

| 样本                      | 实际状态                                         | 发现的主要问题                                                                           |
| ------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| 英文论证写作，iteration-7 | 四课完整；教师文本已逐段读完；教育审查未通过     | 把“没有提供预算”当成“没有预算”；用需求回应人员可行性；最后两次完整作文重复；示范漏检字数 |
| 中文博物馆，iteration-10  | 四课完整；设计、评审问题和原始档案已审查；未通过 | 重构原档案时增加材料事实；示范/引导/独立阶段混在一起；限定词评分可能代替证据判断         |
| 英文写作，iteration-9     | 两课保存，第三课暂停；未通过                     | 学生句框被误判为缺材料；部分归因和论证范围仍不准确                                       |
| 新统计学，iteration-11    | 已保存前两课，第三课审查遇空响应；未通过         | 数值正确仍可能重复示范；课程设计把总体适用性混成实施可行性；审查有漏项                   |
| 新中文及英文课程          | 串行重新生成中                                   | 尚无最终质量结论                                                                         |

已落实的改进包括：按显式记录 ID 切分原文；程序插入来源而非让作者重新写档案；活动生成只接收当前阶段的任务范围；单独设计并检查课程；限制修复轮数；按具体原句提出批评；将离堂题数据一并交给审查者；允许学生作答句框同时继续禁止缺失题干和答案；让来源修改使旧草稿失效。

仍需改进的是示范与练习之间的实质差异、对学科概念边界的判断、合理的课堂工作量以及评分是否奖励目标推理。当前不能签署“所有课程 classroom ready”。进一步修正后必须重跑并重新阅读，不能手工修一份 JSON 后声称管线普遍改善。

## 6. 导出与浏览器实测

已通过 53 个当前代码单元测试、类型检查、lint、生产构建及体积预算。四个单 Chromium 浏览器测试覆盖导入、编辑、刷新持久化、稳定课次身份、配额暂停、移动布局、学生/教师答案隔离、格式化 Word 和中文 PDF。测试响应中的人工样例明确标为机械夹具。

中文 PDF 夹具的两页已实际渲染并查看，中文与加粗字形正常，答案区和表格分页已修复。完整中文旧生成课程还用于导出布局压力测试；它的教育内容未通过，不能作为合格课程示例。

布局压力测试发现：转换器未配置中文字体时呈现空白；配置实际 Noto Sans SC 后，暴露出 PowerPoint 长材料和连续换行溢出。现在统一字体名称，按字符宽度和显式行数分页，并让 PowerPoint 保留富文本强调与链接。新课件为 82 页，正在逐页检查，尚未签署整份视觉通过。PDF 改用可捕获布局/流错误的导出路径，避免错误后按钮无限等待。

Google 导出已实现真实 Drive 转换。已登录的本地 OAuth 测试返回 `origin_mismatch`，原因是现有客户端没有注册本地开发地址。没有将这个失败算作通过，也没有绕过 OAuth。必须在已授权的 `edutool.dev` 部署后验证实际 Docs、Sheets 和 Slides 文件。

## 7. 剩余安全与发布工作

本次依赖更新后，npm 仍报告两项 high 公告，路径是 PPTX 的 Node 图像尺寸解析依赖。当前浏览器构建明确排除该解析器，导出代码仅添加文字和形状，不接收图片，因此当前产品路线不调用受影响解析。仍保留这个公开限制；将来加入图片或服务器渲染时必须重新处理。没有执行会退回旧版 PPTX 库的强制自动修复。

在发布 v0.19.0 之前还要完成：真实课程重新审查、完整导出视觉验收、候选版推送和 CI、公共域名 SHA 核对、真实 Google 导出、完整浏览器功能及 UI/UX 回归，再更新本报告、README 与 changelog。版本标记必须反映这些实际结果，不能用“没有发现任何问题”替代有范围的验收记录。
