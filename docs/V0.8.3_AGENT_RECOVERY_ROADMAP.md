# CourseMapper v0.8.3 Roadmap: Workspace Recovery and Agent Trust

Version target: `0.8.3`

North Star: an instructor can open an old or half-finished project, even with a broken API key, reconfigure the model inside the workspace, ask naturally for changes, and trust the agent because it plans, executes, verifies, and shows exactly what changed.

## Release Principles

- Keep the workspace open. A broken key, retired model, no-credit state, or missing local model should not force the user back to the landing page.
- Prefer conversation over modes. The user says what they want; the agent decides whether it is safe to apply, needs clarification, or must be refused.
- Trust requires receipts. Every serious run should report what changed, what was skipped, what failed, and what was verified by reading the final state back.
- Missing deliverables are hard blockers. The agent must not create ghost assignments, rubrics, slides, study guides, FAQs, quizzes, or custom artifacts.
- Finish package should be one path. The user should not choose among repair, verify, export, retry, and audit primitives when they mean “make this ready.”

## Release Scope

### 1. Workspace Model/Key Recovery

- Click the workspace model label to open provider, key, and model settings.
- Show in-place recovery banners for invalid keys, expired keys, no-credit keys, missing model selection, and validating provider state.
- Preserve no-key local commands for safe reads, package audits, planning, undo, and configuration.
- Route Configure from the command strip and typed commands into the same workspace model settings panel.

### 2. Conversation-First Agent Behavior

- Remove visible “review/edit mode” decisions from the main path.
- Apply safe targeted edits directly, then verify them.
- Ask before broad rewrites, deletes, regenerations, overwrites, unclear targets, and missing scope.
- Refuse missing or not-ready deliverables with a clear explanation and no mutation.
- Keep legacy internal plan values readable, but emit new plan vocabulary: `inspect-first` and `safe-edit`.

### 3. Receipts Instructors Understand

- Use compact labels: `Change details`, `Work done`, `Plan`, and `Verified by reading back`.
- Include before/after evidence for changed state.
- Include affected deliverables.
- Include skipped actions and reasons.
- Include failed actions and recovery paths.
- Include verification from reading the edited state back.
- Keep the receipt card compact enough to scan during real course work.

### 4. Closed-Loop Scenario Expansion

First target: add 50-75 high-value v0.8.3 cases.

Priority scenario groups:

- Restored-project broken-key recovery.
- No-credit and retired-model recovery.
- Multi-turn edits and user changes their mind.
- Stale deliverables and downstream sync pressure.
- Missing deliverable refusal.
- Provider failure and bad model tool calls.
- Large 14-lesson package finishing.
- Ambiguous requests where the agent must ask first.
- Finish-package loops with repair, retry, export verification, and remaining human-review items.

Longer target: grow toward 150 closed-loop scenarios that assert intent, safety, state change, verification, recovery, and final user value instead of only exact tool-call paths.

### 5. Finish My Package

- One command and natural-language route for “finish my package,” “do the final pass,” “make this ready for class,” and “prepare export.”
- Inspect/plan when package state is unclear.
- Run finalization.
- Apply deterministic safe repairs.
- Retry only localized weak sections when finalization identifies them.
- Verify exports and readiness after mutations.
- Report changed, skipped, failed, verified, and remaining instructor-decision items.

### 6. Release Operability

- Keep pull-request CI fast: format, lint, unit/offline tests, build, and bundle budget.
- Keep deep proof gates for push/manual release validation: deterministic audits, gold audit, internal expert harness, proof packet, E2E, and Firebase rules.
- Preserve rigor without making ordinary iteration wait on every deep audit.

## v0.8.3 Gate

- Focused unit coverage for agent availability, workspace model recovery, receipts, commands, plan vocabulary, and quality scorecard versioning.
- Closed-loop scenario suite includes the v0.8.3 recovery and receipt bank.
- Full offline test suite passes.
- Build and bundle budget pass.
- Deep proof gates remain available on push/manual CI.
