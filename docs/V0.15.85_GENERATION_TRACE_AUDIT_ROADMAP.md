# v0.15.85 Generation Trace Audit Roadmap

## Goal

Make real EduTool.dev ZIP/log audits easier to explain by documenting what the
generation runtime did in the background, especially provider API calls,
retry/fallback behavior, and blueprint compiler work.

## Evidence

The June 27, 2026 User Experience Design Studio audit produced a package at:

`verification-output/edutool-audit-loop/20260627T143736Z-v01584-ux-design`

The package exported at `99/100 (A)` with texture `93`. After the current
source-ledger checks, local regrade is `93/100 (A)` with six P1 citation
findings: unrelated feedback, layout, pattern, metaverse, climate feedback, and
facility-layout rows were promoted as trusted UX Design source proof.

The visible app showed a simple top-line score, but the saved log still required
too much archaeology to answer basic process questions:

- Which provider request started for which feature/chunk?
- Which attempt number and retry budget was in play?
- Did the call use structured schema output?
- How large was the approximate request and response?
- Which deliverables were compiled locally instead of model-generated?
- What did the compiler plan, validate, and finish?

The same audit surface also exposed three adjacent cleanup targets already in
this slice:

- The export card repeated the Agent panel note state.
- Current-run logs can hit local-storage quota pressure while saving
  conversations.
- UX Design source-finder retrieval can return false-friend rows such as
  systems feedback or unrelated layout pages and still look trusted unless
  quarantined or graded.

## Lane

Observability, runtime resilience, and report truth. This release adds process
evidence; it does not weaken quality standards or claim a clean 100/100 package.

## Scope

In scope:

1. Default `[CM][API]` logs include run id, stage, type, feature, provider,
   model, counters, call plan, token/cost summary, failure metadata, and
   compiler savings.
2. Provider calls emit request-start and response-complete events with attempt
   number, schema presence, max output budget, approximate input tokens, output
   character count, and stream chunk count.
3. The blueprint compiler emits a real plan/start/compiled sequence before and
   after local compilation, including config feature ids and item counts.
4. Export panel notes stay simple and delegate details to the Agent panel.
5. Conversation persistence clears orphaned conversation payloads before giving
   up on quota pressure.
6. UX false-friend source-finder rows are quarantined as review notes, and the
   source-ledger grader flags exported trusted false-friend rows.

Out of scope:

- Logging raw prompts, API keys, request bodies, full provider responses, or
  instructor-private text.
- Replacing the run digest.
- Claiming provider quality reached 100/100.
- Broad redesign of the Agent panel.

## Release Boundary

The release is useful if the next saved console log can reconstruct:

- API call plan and running provider-call counters.
- Which feature/chunk called the provider and which attempt finished.
- Whether output used schema guidance.
- Provider response size and stream chunk count.
- Local compiler plan, compile duration, item counts, and avoided calls.
