# V0.9.11 Roadmap — The Super-Power Compiler: cost shift without quality loss

**Source analysis:** `docs/COMPILER_COST_SHIFT_AUDIT.md` (June 2026).
**Target:** ≈55–60% reduction in billed output tokens per course
(24–29k → 11–13.5k on a 14-lesson course) plus elimination of the hidden
OpenAI reasoning default — per-course cost ~$0.50–2 → ~$0.20–0.80 —
while CCR-relevant quality holds or improves.
**Principle:** the model is paid only for irreplaceable disciplinary
authorship (stems, options, definitions, facts, scenarios, tensions, tasks).
Everything reconstructable — stems-of-form, numbering, framing, notes,
alignment prose, boilerplate columns, duplicate knowledge — is compiler code.

Phases are ordered by risk: two zero-contract-risk wins first, then the
flag-gated lean flip, then the kernel restructure as the centerpiece.

---

## P0 — Token telemetry baseline (prove every phase's savings)

The generation pipeline already records call events
(`recordGenerationApiCallEvent` in `useDeliverables.js`, `recordApiCallEvent`
in `useGeneration.js`) but not token usage, so savings are currently
unprovable. OpenAI chat already requests `stream_options: {include_usage: true}`
(`modelRequestBuilders.js:217`) and nobody reads it.

**Changes**
1. `src/lib/streamUsage.js` (NEW): per-provider usage extraction from stream
   frames — OpenAI chat (`usage` on final chunk), OpenAI Responses
   (`response.completed` → `response.usage`, including
   `output_tokens_details.reasoning_tokens`), Anthropic (`message_start` /
   `message_delta` → `usage`), Google (`usageMetadata`, including
   `thoughtsTokenCount`).
2. `useStreamReader` / `streamProvider`: thread parsed usage into the
   resolved result; both hooks attach `usage: {inputTokens, outputTokens,
   reasoningTokens, cachedInputTokens}` to their call events.
3. `src/lib/generationCostReport.js` (NEW): aggregates a run's call events
   into a per-call + total table; logged at generation end and stored on the
   project (`generationCostReport`) so the agent's digest and the export
   manifest can cite it.
4. `scripts/` repro harness: print the cost table after each harness run.

**Acceptance:** one full generation prints a table of every call with input /
output / reasoning / cached tokens and a course total. Unit tests with
fixture frames for all four providers.

**Savings:** none directly — this is the measuring stick for P1–P5.

## P1 — Explicit reasoning effort per task (kill the hidden medium default)

`modelCapabilities.js` sets `applyByDefault: false` on every profile and no
plan ever sets `reasoning.enabled`, so `buildOpenAIResponsesBody`
(`openaiProvider.js:41–43`) omits `reasoning` entirely → gpt-5.x servers
default to **medium** effort and bill the thinking as output. The computed
`controls.reasoning` is also dropped on the OpenAI chat-completions path
(no `reasoning_effort` in the body, `modelRequestBuilders.js:204–221`).

**Changes**
1. `src/lib/modelCapabilities.js` (`inferReasoningControls`, ~line 195):
   replace `applyByDefault`/`highValueTasks` with a `taskEffortMap`:
   - OpenAI gpt-5.x / o-series (`reasoning_effort`):
     `{'course-map': 'medium', examine: 'medium', blueprintEnrichment: 'low',
     repair: 'low', 'gap-fill': 'low', default: 'low'}`.
   - Google thinking models (`thinking_level`): same tiers
     (`LOW` for enrichment/repair, `MEDIUM` for course-map/examine) — Gemini
     also thinks by default when unconfigured.
   - Anthropic (`thinking_budget`): unchanged — omitting = no thinking, so
     leave disabled by default (no regression to fix).
   - Keep `plan.reasoning` as an explicit override for power users.
2. `src/lib/modelRequestBuilders.js` (`createReasoningRequestControl`):
   resolve effort from `taskEffortMap[task] ?? taskEffortMap.default`;
   return `enabled: true` whenever the map provides a level.
3. Same file, OpenAI chat-completions branch: send
   `reasoning_effort: controls.reasoning.effort` when
   `controls.reasoning.enabled && control === 'reasoning_effort'` (parity with
   the DeepSeek branch at line 287).
4. Settings escape hatch: `generationOptions.reasoningEffortOverride`
   passthrough (no UI yet; honored by the planner).

**Tests:** request-builder unit tests asserting the exact body field per
provider × task; capability-profile mapping tests.
**Quality gate:** repro harness before/after on the 4 audit syllabi — diff
deterministic gate results (gold, boilerplate, substance); P0 telemetry must
show `reasoningTokens` collapse on enrichment calls.

**Savings:** the entire silent reasoning bill on enrichment/repair/gap-fill —
typically 30–60% of real OpenAI spend. No visible-output change expected.

## P2 — Compact keys for lesson-content enrichment

The repo's own measured idiom (`keyMaps.js`: ~15–20% output reduction via
short keys + `expandKeys()`) is unused by the v0.9.1 enrichment contract,
which spells out `distractorRationales`, `taskDescription`, `scoringGuidance`
in every item of every lesson of every chunk.

**Changes**
1. `src/lib/keyMaps.js`: add `enrichment` map —
   `q→question, op→options, ai→answerIndex, dr→distractorRationales,
   an→answer, ex→explanation, sg→scoringGuidance, t→term, df→definition,
   eg→example, mc→misconception, ti→title, bu→bullets, no→notes,
   pr→prompt, tn→tension, po→positions, td→taskDescription, pa→parameters`
   (wrapper keys `lessons`, `quizItems`, `keyTerms`, `slideContent`,
   `discussionPrompt`, `assignmentCore`, `lessonId`, `index`, `type` stay
   full per keyMaps rules).
2. `blueprintEnrichmentPass.js`: `buildLessonContentEnrichmentPrompt` emits
   the schema with short keys (one shared `SHORT_SCHEMA` constant);
   `parseLessonContentEnrichmentResponse` runs `expandKeys('enrichment', …)`
   before linting — lints and overlay code untouched.

**Tests:** round-trip (short-key fixture → parse → full-key payload identical
to today's), all 11 existing enrichment tests stay green unchanged.
**Savings:** ~15–20% of the largest output call (~2.5–3k tokens/course).
Risk ≈ zero.

## P3 — Lean course map default-on + compiler-owned columns

Lean atoms are fully built and wired (`leanCourseMap.js`,
`useGeneration.js:853/985/1043`) but `generationPlan.leanCourseMapAtoms` has
**zero writers** — the v0.8.6 investment was never collected. Measured cost
of the verbose contract: 30,139 chars (~7.5k tokens) of cell prose in the
Social Policy production map.

**P3a — flip the flag**
1. `modelCapabilities.js` (plan builder, near `courseMapOutputTokens`,
   ~line 890): set `leanCourseMapAtoms: true` for models with
   `structuredOutput` support; respect
   `generationOptions.leanCourseMap === false` as the off switch.
2. Reduce `courseMapOutputTokens` scale for lean plans (atoms need ~55% of
   verbose budget; keep ≥4096 floor).
3. Proof sweep before default-on: repro harness lean profile across the 4
   audit syllabi → `audit:gold` 40/40, blueprint matrix 132/132, copy-variety
   budget, boilerplate gate, `audit:deliverables`.

**P3b — remove compiler-owned columns from the model contract (lean mode only)**
1. `prompts.js`: in lean mode, drop `evaluateDesign`, `presentationFormat`,
   `technologyNeeded` from the requested keys (they remain in the app's
   column model); add optional `specialTools` atom array — emitted only when
   the syllabus names concrete tools (SPSS, Logic Pro, ArcGIS…).
2. `src/lib/leanCourseMap.js` — `deriveCompilerOwnedColumns(courseMap)` (new,
   called from `expandLeanCourseMap`):
   - `evaluateDesign` ← rendered from the actual objective↔assessment↔activity
     mapping (reuse the compiler's alignment derivation; varied templates per
     lesson to satisfy the copy-variety budget) — *computed* alignment replaces
     *asserted* alignment.
   - `presentationFormat` ← modality decode + activity verbs (existing
     "never blank" fallback logic, promoted).
   - `technologyNeeded` ← modality stack + `specialTools` atoms.
   - Each derived cell carries provenance (`compilerDerived: ['evaluateDesign',…]`
     on the lesson) surfaced in trust records and the pre-export checklist.
3. Examine-pass guard: derived columns are exempt from "incomplete cell"
   triggers in `getCourseMapExamineScan` (they are never model omissions).

**Tests:** derivation unit tests (variety across 14 lessons, provenance,
specialTools passthrough); lean E2E fixture through blueprint → compile →
gates.
**Acceptance:** P0 telemetry shows course-map output ≈ −55–65% vs v0.9.1
baseline on the same syllabus; all deterministic gates green; no examine-rate
increase (scan triggers compared before/after on harness runs).
**Savings:** ~4.5–6k output tokens/course (P3a ~40–55% + P3b ~20–25% of the
course-map call).

## P4 — Knowledge kernel: pay for knowledge once, compile it everywhere

The flagship. The v0.9.1 per-lesson contract buys five finished surfaces and
pays for the same knowledge 2–3×: `keyTerms[].misconception` vs
`distractorRationales`, slide bullets vs quiz explanations, slide notes
restating bullets the compiler's `slideNotes()`
(`courseBlueprintCompiler.js:14353`) can already frame.

**P4a — kernel contract**
1. `blueprintEnrichmentPass.js`: `buildLessonKernelPrompt(courseMap,
   lessonIndices, options)` — per lesson the model returns (short keys per P2):
   ```
   { facts: [5–8 one-line content-bearing claims],
     terms: [4 × {term, definition, example, misconception}],
     scenario: {setup, materials},          // one concrete case/dataset/text
     tension: {question, positions[2–3]},
     task: {description, parameters[2–4]},
     mc: [3–4 × {stem, options[4], answerIndex}] }
   ```
   System prompt keeps the Haladyna + no-meta + grounding rules verbatim.
2. Kernel lints (reuse the v0.9.1 lint bodies): `lintKernelFact`
   (length/meta/grounding), existing `lintEnrichedKeyTerm`, MC lint =
   `lintEnrichedQuizItem` minus rationale checks, scenario/tension/task =
   existing prompt/assignment lints. Per-item drop + fallback as today.

**P4b — deterministic projection (the compiler superpower)**
3. `src/lib/kernelProjection.js` (NEW): `projectKernelToSurfaces(kernel,
   lesson)` produces the **existing** `lesson.enrichment` payload shape, so
   every v0.9.1 overlay (`overlayEnrichedQuizItems`,
   `enrichedKeyTermsForLesson`, `overlayEnrichedSlideContent`, discussion and
   assignment overlays) runs unchanged:
   - quiz MC ← `mc`; `distractorRationales` ← matched `terms[].misconception`
     (lexical match option↔term, generic-misconception fallback);
     `explanation` ← the supporting `facts` entry (keyword match).
   - short_answer / essay ← compiled stems framed around `scenario` +
     `facts` + `task` (compiled frame, model substance — the v0.9.1 pattern
     inverted); scoring guidance from compiled criteria frames + `task.parameters`.
   - slides ← assertion titles + evidence bullets selected from `facts`;
     notes via `slideNotes()` (model notes no longer purchased).
   - discussion ← `tension`; assignment ← `task`; study-guide misconceptions
     ← `terms` (reused, not re-bought).
   - provenance: `enrichmentSource: 'kernel-projection'` on projected fields,
     `'lesson-content-enrichment'` retained for direct model text.
4. Storage: `lesson.enrichment.kernel` persisted (LESSON_STORAGE_KEYS already
   includes `enrichment`); projection runs at attach time in
   `buildCourseBlueprint` so compiled output is reproducible from storage.
5. Back-compat: `parseLessonContentEnrichmentResponse` (surface contract)
   kept as fallback parser; old stored projects compile unchanged.

**P4c — absorb the course-level call**
6. Chunk #1's kernel schema adds `courseLevel: {lens, signatureTerms,
   styleNotes}` (~150 output tokens). `lessonPhrases` for kernel-enriched
   lessons are derived deterministically (topic first-phrase extraction —
   the finalizer's `topicShort` machinery, exported for reuse);
   the standalone `buildBlueprintEnrichmentPrompt` call remains only for the
   enrichment-on/lesson-content-off configuration.

**P4d — chunking + cache alignment**
7. `useDeliverables.js` (`runBlueprintEnrichment`): `chunkSize` 2 → 4;
   per-chunk `maxOutputTokens = max(cap, 1200 × lessonsInChunk)`;
   keep truncation canary + per-item fallback (bounds the blast radius).
8. Prompt layout for caching: system prompt + schema + item plan move into
   `systemPrompt` (static across chunks → Anthropic `cache_control` already
   applies, `modelRequestBuilders.js:229`; OpenAI automatic prefix caching
   needs ≥1,024 identical leading tokens — now reachable); the user prompt
   carries only `Course:` line + the lesson array.

**Tests:** kernel parse/lint/projection units; projection determinism
(same kernel → byte-identical surfaces); end-to-end enriched-compile fixture
(extend `lessonContentEnrichment.test.js` with a kernel fixture: CO2/greenhouse
facts → verify slides/quiz/discussion/study-guide all trace to kernel atoms);
substance assertion (`auditSubstance` metaShare on projected output);
storage round-trip.
**Acceptance:** per-lesson enrichment output ≈ −40–50% (P0 telemetry);
4 calls instead of 7 for 14 lessons; `auditSubstance` ≤5% meta on the harness
fixture; gold 40/40; CCR judge re-scores D1/D2/D3 mechanism on the kernel
fixture before release.
**Savings:** ~6–8k output + ~5k input tokens/course (kernel + absorbed call +
fewer chunks), multiplicative with P2's key compaction.

## Risk register & rollback

| Risk | Phase | Mitigation / rollback |
|------|-------|----------------------|
| Lean atoms degrade cell specificity on sparse syllabi | P3a | Proof sweep gates before default-on; `generationOptions.leanCourseMap=false` escape hatch; expansion is idempotent so mixed output is safe |
| Derived evaluateDesign trips copy-variety budget | P3b | Varied per-lesson templates; gate runs in the sweep; column can be re-added to contract per-course |
| Kernel projection produces flat distractor rationales | P4b | Lexical match + fallback ranks below v0.9.1 quality bar → keep rationales in the MC contract for that item (lint-triggered, per item) |
| Chunk=4 truncation loses 4 lessons of enrichment | P4d | Truncation canary + per-item fallback; output cap scaled; auto-retry path splits the chunk in half |
| Low reasoning effort hurts messy-syllabus extraction | P1 | course-map/examine stay `medium`; before/after harness diff is the gate |
| OpenAI cache assumptions wrong | P4d | Caching is a discount, not a dependency — layout change is harmless if uncached |

## Non-goals (the quality line, restated)

No deterministic distractor generation. No template essay prompts without a
model scenario. No compiler-fabricated facts, definitions, or citations.
Lean mode compresses *form*, never *sourcing*. Phase 4 of the classroom-ready
program (instructor pilot) is unaffected and still pending.
