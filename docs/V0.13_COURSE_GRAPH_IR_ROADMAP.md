# V0.13 Roadmap — The Course Graph: Blueprint as Model-Authored IR

**Source analysis:** the v0.12 four-course output audit + the v0.12.1 release
retrospective. Every audited defect class (slot grammar, truncation,
mail-merge sameness, the stem strip/re-add contradiction, placeholder
citations) traced to one architectural fact: the model writes a
**spreadsheet of prose** (the course map), and `buildCourseBlueprint` — the
largest and most defect-dense layer in the codebase (16k lines, of which an
estimated 25–40% is prose→structure recovery) — re-infers the structure the
model already had: concepts from cell text, artifacts from assessment
sentences, evidence plans from resource strings, modality from keyword
heuristics.

**Thesis:** the course map is a lossy serialization format sitting between
two structured representations. Every major improvement since v0.9 was a
step away from it — lean atoms (model emits arrays, app renders cells),
compiler-owned columns (computed alignment instead of asserted prose),
knowledge kernels (the concept as the unit of meaning), the genome (verified
concepts as data). V0.13 completes the move: **the model authors a typed
course graph; the course map becomes one deterministic render of it.**

**Target:**

- The generation call(s) emit graph entities, never spreadsheet prose.
- `courseMap = renderCourseMap(graph)` — byte-stable, deterministic, free.
- Compiled deliverables are byte-identical (or strictly better) versus the
  map-driven path on the full quality matrix before cutover.
- Cold-genome cost per 15-lesson course drops ~25–35%; genome-covered
  courses drop 60–85%. Wall clock from ~2.5 min toward ~60–90 s.
- The prose→structure inference layer of the compiler begins retiring.

**Principle:** the model is paid only for irreplaceable disciplinary
authorship (concepts, outcomes, assessment substance, misconceptions,
worked examples) and for _parsing_ the instructor's own syllabus. Structure,
alignment, rendering, numbering, and framing are code. The course map is a
view instructors love — it stays — but it stops being the database.

## The CourseGraph schema (v1)

One typed object, stored as the project's source of truth
(`project.courseGraph`, version-tagged). Entities carry stable ids so edits,
diffs, undo, and agent operations are entity-level.

```
CourseGraph {
  version: 1,
  course:      { name, description, audience, deliveryMode, term, policies: PolicyRef[] }
  concepts:    Concept[]      // THE unit of meaning
  outcomes:    Outcome[]      // course- and lesson-level
  assessments: Assessment[]   // graded work, weights, genre
  sessions:    Session[]      // ordered teaching units (today's "lessons")
  resources:   Resource[]     // extracted citations from the syllabus
  edges: {
    teaches:        [sessionId, conceptId][]      // placement
    assesses:       [assessmentId, outcomeId][]   // alignment (QM 3.1 by construction)
    requires:       [conceptId, conceptId][]      // prerequisites
    practicedIn:    [outcomeId, sessionId][]
    instanceOf:     [conceptId, archetypeId, mapping][]   // genome layer-2
    genomeLink:     [conceptId, genomeConceptId][]        // resolved kernels
  }
}

Concept    { id, term, definition, facts[], examples[], misconceptions[],
             workedExample?, source? }            // == today's kernel shape
Outcome    { id, bloomVerb, text, conceptRefs[], level: course|session }
Assessment { id, title, genre, weightPct, dueSession, conceptRefs[], successCriteria[] }
Session    { id, number, title, minutes, conceptRefs[], activities[],
             asyncActivities[], notes? }
Resource   { id, citation, kind, sessionRefs[], origin: syllabus|instructor|genome }
```

Two non-negotiable properties:

1. **Concept ≡ kernel.** The Concept entity is the existing knowledge-kernel
   shape. Genome-linked concepts come from shards (free, cited); unlinked
   concepts are model-authored in the same pass that authors the rest of the
   graph. The separate kernel-call stage disappears — absorbed, not added.
2. **Alignment is edges, not prose.** `evaluateDesign` (asserted alignment),
   "Aligns to:" strings, and the outcome-alignment matrix all become renders
   of the `assesses`/`practicedIn` edges. Misalignment becomes a lint error
   the finalizer can see — a dosage-calculation session whose assessment
   tests no dosage concept is detectable _structurally_.

## The call structure

Replace the single course-map call (+ kernel calls) with two purpose-built
passes:

**Pass A — Extraction (cheap, low reasoning).** Parse the syllabus into the
structural entities: sessions, schedule, assessment plan with weights,
resources/citations, policies. Mostly transcription of the instructor's own
document; typed JSON out (~3–4k tokens); deterministic pre-extraction
(dates, weights, citation patterns) seeds the prompt so the model confirms
rather than authors. Runs even on messy imports — this is where `medium`
reasoning is bought _adaptively_ when source-grounding signals are weak.

**Pass B — Authorship (the only irreplaceable spend).** For each session's
topics: resolve concepts against the genome first (free); author Concept
entities + Outcomes + assessment substance only for unresolved topics.
Chunked 4–5 sessions per call, **parallel** (today's kernel chunks are
sequential), low reasoning, compact keys. Chunk #1 carries the course-level
lens, as today.

The blueprint builder then becomes a thin adapter: `graph → blueprint` is
mostly identity + derived conveniences, replacing the prose-inference layer.

## Phases

Ordered so that every phase ships behind the old path until proven, using
the harness built for v0.12.1.

### P0 — Schema + renderers + golden equivalence harness

1. `src/lib/courseGraph/schema.js`: the v1 schema, validators, entity-id
   helpers, JSON round-trip.
2. `src/lib/courseGraph/deriveFromCourseMap.js`: build a graph FROM a legacy
   course map — this is largely a re-packaging of what
   `buildCourseBlueprint` already infers. It is both the migration path for
   saved projects and the bootstrap for testing.
3. `src/lib/courseGraph/renderCourseMap.js`: deterministic graph → course
   map (cells, columns, stems, numbering — all the rendering rules the
   repair pass enforces today, applied at render time so repair finds
   nothing to fix).
4. **Golden harness:** for the full blueprint-quality-matrix fixture set:
   `compile(buildCourseBlueprint(map))` vs
   `compile(blueprintFromGraph(deriveFromCourseMap(map)))` must produce
   equivalent deliverables (allowlisted diffs only). This gate guards every
   later phase.

**Acceptance:** golden harness green on all matrix fixtures; round-trip
`renderCourseMap(deriveFromCourseMap(map))` preserves every cell the
readiness checks care about.

### P1 — Graph authoring contract (flag-gated)

1. New generation contract (`prompts` + schema): Pass A/Pass B emit graph
   entities with compact keys. Extends the lean-atoms machinery rather than
   replacing it.
2. `generationPlan.courseGraphAuthoring: 'on'|'off'` — default off; the
   degraded-plan guard from v0.12.1 applies (prompt-only profiles never get
   the graph contract).
3. Genome linking moves to parse time: Pass B receives only unresolved
   topics. Kernel-call stage retired when the flag is on (Concept ≡ kernel).
4. Side-by-side proof: same fixture syllabi through both paths; compare
   cost report, quality matrix, output artifact gate, and CCR scores.

**Acceptance:** graph path ≥ map path on every quality gate; cold-genome
cost ≤ 75% of the v0.12.1 path on the 15-lesson fixture; digest shows
`pipeline: course graph (passes A+B)`.

### P2 — Write-back editing

1. `useCourseMapEditor` cell edits become entity operations: each rendered
   cell carries provenance (`entityRefs`) so an edit maps to the entity
   (objective text → Outcome.text; assessment cell → Assessment fields).
   Free-text edits that defeat parsing fall back to a per-cell override
   layer (rendered verbatim, flagged "manual override" in readiness) — no
   silent re-inference, ever.
2. `useSmartSync` cascades become graph-dirty propagation: entity change →
   affected views re-render free; AI regeneration only when authored
   substance is stale (concept changed → that session's kernel-derived
   surfaces).
3. Version history / undo move to graph diffs (entity-level, smaller and
   more legible than cell-text diffs).

**Acceptance:** the v0.8.59 real-browser agent harness editing scenarios
pass against the graph workspace; an objective edit re-renders map + all
views with zero provider calls.

### P3 — Agent graph tools

1. `agentTools`: `edit_course_map`/`edit_deliverables` gain graph-native
   operations (update_outcome, move_concept, reweight_assessment,
   link_resource); `FIELD_ALIASES` cell-munging retires for graph projects.
2. `agentPrompts` system context describes entities and edges instead of
   column names — smaller context, cheaper agent calls.

**Acceptance:** agent red-team editing scenarios (50-scenario suite) pass on
graph projects with equal-or-better response quality scores.

### P4 — Product/UI changes

1. **FeatureSelect:** the locked "Course Map (always required)" card is
   retired. The graph is not a deliverable — it is what generation
   produces. The card is replaced by a non-selectable "Course structure —
   always included" note; the deliverable list contains only real outputs.
   Course Map remains available as an **export format** (XLSX render).
2. **Config:** `ColumnEditor` becomes view settings for the map render and
   XLSX export (order, visibility, labels) — no longer part of the
   generation contract. Custom columns map to either a graph field or a
   custom authored atom (Pass B addendum).
3. **Workspace:** `CourseMapPreview` stays the home view, now rendering the
   graph with per-cell structured editors (P2). Generation progress copy:
   "Reading your syllabus" (Pass A) → "Writing the subject matter" (Pass B)
   → "Compiling materials".
4. **Digest/manifest:** pipeline block reports passes A/B, genome
   resolution ratio, and authored-concept count.

**Acceptance:** e2e flow (upload → select → configure → generate → edit →
export) green in the Playwright suite with the graph flag on.

### P5 — Persistence v2 + migration

1. Project format v2: `courseGraph` is the stored source; `courseMap` is
   not persisted (rendered on load). Legacy projects migrate on open via
   `deriveFromCourseMap` with a one-time "structure imported" receipt.
2. localStorage/Firestore size check: compact graph encoding (the keyMaps
   pattern) — target ≤ today's compacted blueprint size.

**Acceptance:** every fixture in the restored-workspace recovery suite (30
scenarios) opens, edits, regenerates, and exports correctly from both v1
and v2 project files.

### P6 — Flip the default, retire inference

1. `courseGraphAuthoring` defaults on for structured-output models (same
   gating as lean atoms; webllm/prompt-only keep the legacy path).
2. Begin deleting the prose-inference layer: each `buildCourseBlueprint`
   heuristic that the graph supplies directly (concept extraction, artifact
   labeling, evidence-plan derivation) is removed once the golden harness
   shows no consumer needs it. Track with a "retired heuristics" ledger in
   this doc.
3. Constraint-based validation replaces the equivalent pedagogicalValidator
   regex checks: every outcome assessed; every assessed concept taught
   first; weights sum to 100; every session within stated minutes.

**Acceptance:** four-course live regeneration (the v0.12.1 protocol) on the
graph path: enrichment/genome ratio reported, cost ceilings met (below),
output artifact gate zero hits, CCR ≥ map-path baseline.

## Cost model (15-lesson course, gpt-5.4-mini class pricing)

| Path                                           | Output tokens (≈)  | Cost (≈)       | Notes                                                                               |
| ---------------------------------------------- | ------------------ | -------------- | ----------------------------------------------------------------------------------- |
| v0.12 audited (degraded: verbose, no kernels)  | 20k (8k reasoning) | $0.09          | mail-merge quality — the baseline to never repeat                                   |
| v0.12.1 healthy (lean map + 4 kernel calls)    | 30–38k             | $0.12–0.17     | map prose and kernels duplicate objectives/assessments/facts                        |
| **v0.13 graph, cold genome**                   | 18–25k             | **$0.08–0.11** | Pass A ~3–4k + Pass B ~1.4–1.6k/session; duplication eliminated; reasoning adaptive |
| **v0.13 graph, genome-covered (10/15 linked)** | ~10k               | **$0.04–0.05** | Pass B authors 5 sessions only                                                      |
| **v0.13 graph, fully linked or kernel-cached** | ~4–5k              | **$0.02–0.03** | extraction only — the regeneration/iteration price                                  |

Secondary savings not in the table: smart-sync cascades that today can
trigger AI regeneration become free re-renders; agent edit calls shrink
(entity context instead of full map prose); finalizer retry spend drops as
structural lint prevents the defects retries fix; and the recurring
engineering cost of the inference layer (where both audits' bugs lived)
goes away. Latency: parallel Pass B chunks + a shorter primary stream takes
~2.5 min toward 60–90 s.

## Verification protocol (release gate)

1. Golden equivalence harness green across the quality-matrix fixtures at
   every phase.
2. Output artifact gate (tests/output-artifact-gate.test.js) extended to run
   both paths.
3. Side-by-side cost report: graph path ≤ 75% of map path cold; ≤ 35%
   genome-covered.
4. Live four-course regeneration on the graph path with content spot-gates
   (the v0.12.1 protocol).
5. Browser harness: agent editing + restored-workspace suites on v2
   projects.

## Explicitly deferred (v0.14+ directions, recorded not planned)

- **Interview-first onboarding** — agent interview fills graph fields no
  syllabus contains; becomes natural once the graph exists.
- **Backward-design generation order** (outcomes → assessments → sessions
  with verification between stages) — the graph makes it possible; flip the
  authoring order only after P6 stabilizes.
- **The living course** — semester feedback (quiz results, pacing) absorbed
  into the graph and re-projected.
- **Graph/outline visualization view** in the workspace.
- Genome foundry expansion (nutrition/nursing/ed-psych shards) and kernel
  cache persistence — independent of this roadmap and multiply its savings;
  tracked in the CurriculumOS ops queue.
