# V0.17.06 Output Quality Checkpoint

**Release date:** July 31, 2026

**Scope:** EDUTOOL/CourseMapper deterministic package content, formatting, evidence resolution, and quality-proof integrity

## Goal

Make the package that instructors and learners open match the quality seal EDUTOOL displays, down to lesson-level evidence, reader-visible language, and rendered Office-file structure.

## Lane

This is the deterministic compiler, repair, grader, package-evidence, DOCX, and PPTX quality lane. It changes no model weights and promotes no adapter.

## Release Boundary

The release proves encoded package conformance and reproducible render checks. Factual accuracy, WCAG certification, pedagogical efficacy, instructor approval, and classroom outcomes remain outside the boundary.

## Decision

V0.17.06 is a defensible deterministic output-quality checkpoint. It closes every verified code-level defect from the V0.17.05 production-output audit and replaces the stale-proof failure mode with a current-grader contract.

The checkpoint does **not** certify factual accuracy, instructional efficacy, WCAG conformance, instructor approval, or classroom outcomes. Its 99/A result means the fresh retained package satisfies the encoded checks in grader V1.12.0.

## What changed

### The quality seal is release-current

The grader version now has one small static owner. ZIP finalization compares any precomputed result with that current version before reuse. A mismatch discards the old result and performs a fresh grade, so a clean seal cannot survive a grader-policy change merely because it was saved in the workspace.

### Evidence completeness is lesson-specific

The package manifest now includes a dependency record for every lesson. Each record names its source references, external assets, assessment artifact, and unresolved dependencies. Any unresolved lesson dependency creates a score-bearing P0 finding and blocks package readiness.

### Reader-visible content is repaired at its source

- Missing-configuration assignment deferrals receive concrete submission defaults.
- Duplicated subjects, malformed concept explanations, empty instructional objects, and doubled punctuation are detected and repaired.
- Unknown glossary terms no longer receive procedural pseudo-definitions; domain-aware definitions remain compiler-owned.
- Fourteen-lesson quiz generation varies its final evidence/revision slot by lesson focus.
- Slides use complete, bounded, concept-specific prompts instead of truncated or generic fragments.

### Office files are intentionally laid out

- DOCX semantic table rows cannot split across pages, real header rows are marked, list markers use hanging indents, and unconditional syllabus page breaks are removed.
- The retained syllabus, study guide, and assignment render to 9, 3, and 3 pages with no blank content page or orphaned semantic row.
- Accessibility inspection of all three retained DOCX files reports zero high-, medium-, or low-severity findings.
- PPTX decorative shapes stay on-canvas and carry semantic names; visible content stays within the slide boundary.

### Source reporting says exactly what is proven

The source report distinguishes structural references, trusted ledger rows, and per-reference trust resolution. Classroom-readiness language no longer implies that aggregate source presence proves lesson-level evidence completeness.
