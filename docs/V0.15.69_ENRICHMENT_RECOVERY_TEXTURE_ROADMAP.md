# v0.15.69 Enrichment Recovery + Texture Roadmap

_Written June 26, 2026. Target app version: `0.15.69`._

## Evidence

The latest full EduTool.dev ZIP/log audit available in
`verification-output/edutool-audit-loop/20260626T235926Z/` regraded the
Project Management package at `97/100` with texture `90/100`. The remaining
quality losses were not a single model outage:

- partial enrichment: `11/12` lessons enriched, with lesson 3 falling back to
  template;
- retry evidence: `retryCallCount: 0`, so the package had no proof that the
  missing lesson kernel was retried;
- texture evidence: repeated package-wide shingles in lesson plans, slide decks,
  discussion prompts, and study guides;
- source evidence: Open Library metadata rows remained concept-linked but
  license-review-only.

v0.15.68 made the partial state visible in the ribbon. v0.15.69 starts reducing
the actual quality loss by making missing enrichment repairable earlier and by
removing deterministic repeated phrasing found in the audit.

## Lane

Quality reliability for the provider pipeline. This release spends its scope on
making partial lesson-kernel enrichment repairable within the original
generation plan, making those repair attempts visible to the run digest, and
reducing the deterministic texture repeats found in the latest Project
Management package.

## Changes

1. Reserve enrichment recovery budget.
   - The initial generation cost plan now includes a
     `blueprintEnrichmentRecoveryReserve` of two calls whenever lesson-content
     enrichment is active.
   - This means a `9/12`, `11/12`, or similar partial kernel pass has bounded
     budget to repair missing lesson kernels before later polish stages spend
     the remaining provider-call headroom.

2. Count enrichment recovery as retry evidence.
   - Native Pass B recovery and lesson-kernel recovery calls now emit
     `repairRetryCall` events.
   - The run digest can now show that recovery was actually attempted instead
     of hiding those calls inside ordinary enrichment activity.

3. Make cost control honest for native/enrichment/voice calls.
   - Cost-control totals now include native skeleton, blueprint enrichment, and
     voice pass calls.
   - Retry stopping decisions now account for the same provider-call classes
     shown in the generation digest.

4. Vary the latest Project Management texture stamps.
   - Study-guide transfer prompts, slide closing criteria, discussion peer
     response instructions, warm-up misconception polls, and exit-ticket
     misconception corrections now use deterministic lesson variants.
   - The focused Project Management texture regression now includes Study
     Guides and checks the exact repeated phrases from the latest audit.

## Non-Goals

- This release does not claim that current deployed packages regrade `100/100`.
- It does not weaken the texture metric, source-ledger grader, finalizer, or
  partial-enrichment blocker.
- It does not promote Open Library metadata-only rows as trusted source proof.
- It does not replace the required fresh v0.15.69 EduTool.dev ZIP/log audit.

## Release Boundary

In scope:

- Reserve bounded enrichment repair calls before later polish can spend the
  provider-call headroom.
- Count enrichment repair as retry evidence instead of ordinary enrichment
  activity.
- Remove deterministic Project Management repeated stems proven by the latest
  ZIP/log audit.

Out of scope:

- Claiming v0.15.69 reaches `100/100` before a fresh deployed ZIP/log audit.
- Weakening the partial-enrichment blocker, source-ledger trust rules, texture
  metric, or export verifier.
- Spending unbounded provider calls or promoting metadata-only sources as
  trusted proof.
