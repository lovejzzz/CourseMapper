# V0.15.7 - Finished Package Surface: ready means handoff, not audit work

_Written June 17, 2026, after the Human Anatomy and Physiology I ready-state
UI audit. v0.15.6 fixed the output truth problems, but the workspace still
opened a successful package into a dense table plus assistant-side queue. This
release makes the ready state feel like a finished package._

## Goal

When CourseMapper says a package is ready, the first screen should help a
non-expert user download, inspect, or lightly revise the package without asking
them to interpret every internal table, chip, and agent note. The dense course
map must remain available, but it should no longer be the default handoff.

## Lane 1 - Finished Package Overview

1. Add a finished-package overview that appears on the Course Map tab once the
   package machine reaches the ready state.
2. Show the minimum useful handoff facts: lesson count, material readiness,
   quality score, texture score, safe repairs, export checks, and selected
   materials.
3. Put the ZIP download action in this surface, matching the header CTA rather
   than forcing the user to scan the editable map.

**Bar:** a ready package renders `finished-package-overview` with the download
and edit actions, and it does not render the dense Course Map Preview by
default.

## Lane 2 - Dense Map Stays Available

1. Add an explicit `Edit course map` path from the overview.
2. Reset the overview when the user comes back to Course Map after visiting
   other deliverable tabs.
3. Make the Course Map material card open the editable table; make other
   material cards open their artifact tabs.

**Bar:** users can still reach every editable artifact in one click, but only
after choosing to inspect or revise.

## Lane 3 - Compact Ready Agent Panel

1. Add `compactReadyMode` to the workspace agent panel.
2. Hide the project-brief strip, working-set panel, opener buttons, and old
   chat/digest queue when the package is already ready.
3. Keep the package receipt and chat input available so the user can still ask
   for a revision without treating optional polish as a blocker.

**Bar:** ready mode passes only package receipt messages to the message list and
uses `quietReadyMode` so the greeting/starter stack does not return.

## Lane 4 - Release Truth

1. Ship v0.15.7 as a separate release from v0.15.6 so the changelog does not
   imply the overwhelmed UI was fully fixed by the backend/grader work.
2. Add focused tests that pin the finished overview, the editable-map escape
   hatch, and compact ready mode.
3. Keep browser smoke in the proof path because download handoff quality is a
   real-browser concern.

**Bar:** release-history audit validates the new contract, roadmap, anchors,
and proof commands.

## Release Boundary

v0.15.7 changes the ready-state workspace presentation. It does not claim new
course-generation quality, new professor-adoption evidence, live-provider
model improvement, or remote deep-proof success before the pushed run exists.
