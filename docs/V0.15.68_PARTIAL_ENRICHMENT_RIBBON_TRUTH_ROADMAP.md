# v0.15.68 Partial Enrichment Ribbon Truth Roadmap

_Written June 26, 2026. Target app version: `0.15.68`._

## Evidence

The fresh deployed v0.15.66 Project Management ZIP/log audit saved under
`verification-output/edutool-audit-loop/20260626T235926Z/` showed a package
that regraded `97/100 (A)` with texture `90`. The source bridge improved to
seven concept-linked source rows and three trusted concept-linked source rows,
but enrichment still covered only 11 of 12 lessons. Lesson 3 fell back to
template.

v0.15.67 fixed the durable ZIP evidence so `PACKAGE_MANIFEST.json` and
`READINESS_REPORT.txt` cannot hide that blocker. This slice fixes the earlier
visible pipeline surface: partial enrichment should not look like a neutral
`Materials 9/12` progress badge while the app compiles toward a later blocked
finish state.

## Goal

As soon as CourseMapper knows enrichment is partial, the build ribbon should
make the repair state visible:

- the materials chip names the incomplete enrichment fraction,
- the existing readiness/report path keeps the missing-lesson repair details,
- the materials chip turns amber and says repair is needed,
- full enrichment coverage keeps the existing calm neutral chip.

## Lane

Pipeline UI truth for strict enrichment coverage. This release does not add
more provider calls; the enrichment stage already spends its bounded recovery
budget. It makes the remaining partial-coverage state visible before the final
package gate.

## Changes

1. The ribbon model derives partial-enrichment chip tone from
   `budget.enrichmentOutcome`.
2. Partial material coverage now emits a warning-tone chip:
   `Materials 9/12 · repair needed`.
3. The BuildRibbon component renders warning chips before the ready state while
   keeping normal diagnostic chips hidden until finish.
4. Focused regressions pin the live 9/12 shape at both selector and rendered
   HTML levels.

## Release Boundary

In scope:

- Make partial enrichment visibly amber before export.
- Preserve the v0.15.67 manifest/readiness-report blocker.
- Keep full-coverage packages visually calm.

Out of scope:

- Spending additional model calls beyond the existing recovery budget.
- Claiming source, texture, or overall package quality is fixed.
- Changing the source trust rules or texture grader.
