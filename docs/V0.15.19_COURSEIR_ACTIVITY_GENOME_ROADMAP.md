# V0.15.19 - CourseIR Activity Genome

## Goal

v0.15.18 made deterministic repair honest: a repaired CourseIR object no
longer counted as accepted direct provider authoring. The next gap was the one
the live audits kept pointing at: the generated package could be good enough
while the curriculum brain still hid learner work inside prose fields.

v0.15.19 makes outcomes and activities part of the CourseIR contract:

1. Every lesson needs first-class `outcomes[]` atoms.
2. Every lesson needs first-class `activities[]` atoms.
3. Those atoms must link to concept ids and assessment ids before compile.
4. Deterministic repair can synthesize missing atoms for explicit compiler
   input, but that repair is visible and does not count as accepted direct
   provider authoring.

## Lane

This is a CourseIR contract and compiler-projection slice. It does not add a
new genome shard, does not claim live provider quality improvement, and does
not make direct CourseIR the unconditional default. It tightens the definition
of an accepted direct CourseIR brain and keeps repaired/prose-derived learner
work visible as fallback evidence.

## Why Genome-Linked Still Matters

Genome-linked is important, but it is not sufficient by itself.

The genome provides reusable, source-grounded concept knowledge. CourseIR is the
course-specific curriculum brain that decides how those concepts become
outcomes, learner work, assessment evidence, constraints, examples, and
handoff notes. A package is not "better brain" quality merely because some
lesson concepts link to a genome shard. It is better only when the compiler can
trace this chain:

`concept -> outcome -> activity -> evidence -> assessment -> deliverable`

That is the reason this slice validates outcome and activity edges instead of
only counting generated prose.

## Fix

CourseIR now normalizes, validates, repairs, and projects these lesson fields:

- `outcomes[]`: stable outcome atoms with statements, performance verbs,
  concept links, and assessment links.
- `activities[]`: learner-action atoms with mode, title, evidence output,
  concept links, and assessment links.

The course-map and enrichment adapters use authored activity atoms first. The
older deterministic derivation remains only as a supplement or repair path, not
as proof that the provider authored a dense CourseIR brain.

## Boundary

This is still not a claim that every live EduTool.dev run is better than the
legacy path. It is a stricter acceptance boundary:

1. **Accepted direct CourseIR:** provider output already includes dense
   outcome and activity atoms with links.
2. **Repaired CourseIR compile:** explicit CourseIR input can be repaired and
   rendered deterministically, but proof metadata records the repair.
3. **Fallback path:** provider output that only has prose/objective/activity
   strings is rejected as direct authoring and may fall back to the older path.

## Release Boundary

v0.15.19 ships only after focused CourseIR and native-authoring regressions,
formatting, lint, build, bundle check, full unit suite, browser verification,
constitution audit, gold smoke audit, and release-history audit. Remote Fast
verification and Pages deploy are claimed only after push.

## Acceptance

This slice is acceptable when:

1. Missing lesson outcomes and activities are validation blockers.
2. Compiler repair adds outcome/activity atoms before deterministic rendering
   and records `added-lesson-outcomes` / `added-lesson-activities`.
3. Direct provider acceptance rejects prose-derived repaired atoms.
4. CourseIR projection feeds authored activity atoms into course-map and
   enrichment surfaces.
5. Native authoring regression stays green under the stricter CourseIR
   contract.

## Carry Forward

The remaining work is live proof: run side-by-side EduTool.dev ZIP/log audits
where one course uses accepted direct CourseIR and another uses the legacy
native/prose path, then compare cost, caveats, package structure, classroom
texture, and teacher-ready quality.

Longer term, CourseIR should also make rubric dimensions, source citations, and
feedback loops first-class enough that the compiler can prove the entire
curriculum chain without depending on final deliverable prose.
