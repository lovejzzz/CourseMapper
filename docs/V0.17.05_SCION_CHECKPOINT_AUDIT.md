# V0.17.05 Scion Checkpoint Audit

## Goal

Make “ready” mean that deterministic package grading actually completed, and
make the same result auditable in the workspace, ZIP, tests, and release gates.

## Lane

This is the Scion deterministic finalization, evidence, and reader-visible
texture lane. It changes no model weights and promotes no adapter.

## Release Boundary

The release stops at encoded compiler, grader, export, and evidence behavior.
Factual, accessibility, pedagogical, instructor, and classroom validation stay
outside the boundary.

## Decision boundary

V0.17.05 is a candidate named **Scion deterministic quality-gate checkpoint**.
That name means the checked-out compiler, finalizer, deep grader, ZIP evidence,
and release gates behave reproducibly at their encoded boundaries. It does not
mean every generated statement is factually correct, every artifact is
accessible or teachable, an instructor approved the course, or classroom
outcomes were observed.

This boundary matters because a deterministic quality score is a defect signal,
not an independent human or empirical evaluation. The release must never use a
green automated result as evidence for a claim outside that construct.

## What the code-backed review found

A six-turn Roundtable review of the V0.17.04 tree found four reproducible
release blockers and one infrastructure gap:

1. Finalize-time grading failed open. Timeout or error became `not-graded`, but
   the package could still be labeled ready and downloaded.
2. An ungraded ZIP recorded the status only in its manifest and omitted
   `QUALITY_REPORT.md`, leaving recipients with weaker evidence than the app.
3. The whole-pass and inner-grader timers shared the same deadline, so the
   outer race could discard the inner grader's terminal result.
4. Score-bearing reader-visible repetition covered only lesson plans and only
   at a 40-unit floor; assignments and rubrics stayed score-neutral.
5. Roundtable intentionally withheld host Git metadata but thereby prevented
   ordinary repository-aware checks such as `git ls-files` from running.

The review also separated two lower-level concerns from the checkpoint claim:
source wiring is not external factual authentication, and a GitHub-authored
canary answer vector is not a fresh model run. V0.17.05 retains those boundaries
rather than converting them into unsupported certifications.

## Repairs accepted into V0.17.05

### Quality proof fails closed

`buildQualityGateIssues` now creates one `qualityGate` blocker for any explicit
non-graded result. Canonical finish evidence owns that blocker in the quality
domain rather than counting it as both a warning and a readiness blocker.
`getPackageTrustStatus` therefore receives `status: blocked`, a blocker total of
one, and `canDownload: false`. The assembled work remains available for a retry;
only the unsupported ready claim and download permission are withheld. Restored
pre-ledger records with an explicit `not-graded` result infer the same blocker,
and the workspace crown renders a red report-opening "Quality proof unavailable"
control instead of the old calm gray chip.

### The ZIP tells the same truth

Every grading attempt now produces `QUALITY_REPORT.md`. When grading is
unavailable, the report states `NOT GRADED`, preserves the normalized reason and
attempt timestamp, repeats the automated-quality claim boundary, and tells the
owner to run finalization again. The manifest receives the same quality blocker.
ZIP assembly remains recoverable work, but the physical save boundary fails
closed: an attempted ZIP-time grade that returns `not-graded` returns the blob
to the app without calling `saveAs`, and the workspace presents a blocked retry
state. A same-click finish supplies its exact current grade to ZIP assembly;
if that finish returns no grade after repairs, older proof is never reused.
The explicit low-level `quality: false` assembly API performs no grading attempt
and therefore makes no graded or ungraded claim.

### Deadline ownership is explicit

The inner grader retains its 60-second budget. The enclosing assembly/import/
grade pass has a separately named 15-second margin. A boundary regression holds
the mocked inner result until after its nominal deadline and proves the outer
pass does not pre-empt it.

### Repetition policy covers three long-form families

`visible-units.v2` evaluates `skeleton.extraDuplicateRate` for:

| Family       | Minimum eligible units |  P2 |  P1 | Penalty |
| ------------ | ---------------------: | --: | --: | ------: |
| Lesson plans |                     12 | 15% | 30% |   3 / 8 |
| Assignments  |                      8 | 15% | 30% |   3 / 8 |
| Rubrics      |                     12 | 15% | 30% |   3 / 8 |

The thresholds retain the prior known-bad repetition boundary, while the
family floors make a normal four-lesson course evaluable. Short-form artifact
families remain measured and reportable but are not represented as calibrated.
Family findings remain separate, but the strongest family penalty is charged
once; one shared boilerplate frame cannot consume 24 of 25 texture points.
The compiled geology package assertion is unconditional: all three calibrated
families evaluate (70 lesson-plan, 134 assignment, and 84 rubric units), the
base and final texture scores are both exactly 97, and there are no texture
findings.

Expanding the policy correctly exposed a separate Trellis compatibility defect:
its renderer stamped identical length, submission, and rubric-interpretation
sentences across an eight-lesson golden package, dropping conformance to the P1
cap at 89. The renderer now composes four concrete lesson-bound variants while
preserving explicit extent, citation, deadline, and observable-band rules. The
same golden compile is 98/A with no P0 and only one P2 texture note. Grader
V1.11.6 and held-out benchmark boundary V37 bind the changed implementation;
no earlier adapter result or promotion claim is inherited.

### Bundle variance is not product-growth permission

The AppFlow gzip content ceiling is again 85 KiB and the compiler ceiling is
238.25 KiB. Each declares a separate 64-byte compressor tolerance covering the
measured Node/zlib byte spread. Failure output names that tolerance; future
content growth cannot silently redefine it as the content budget.

### Roundtable can execute repository gates without host Git authority

Roundtable V0.0.0.35 creates a synthetic repository inside each disposable
workspace using two path-inventory commits: an origin/main baseline followed by
the session-start snapshot. It uses placeholder blobs and assume-unchanged index
entries, so repository-aware path gates work without hashing or importing large
model weights. It copies no host Git configuration, refs, hooks, credentials,
remotes, object history, or file-content authority. `.roundtable-context`
remains authoritative for original branch and content-diff claims.

## Executable evidence

The release candidate requires all of the following from the exact checkout:

- focused fail-closed, artifact, timeout, trust-state, and texture regressions;
- the full unit suite, lint, formatting, production build, and bundle ratchets;
- the layered PR evaluation contract across its held-out course panel;
- the frozen 25-case source-anchored factual-canary audit, treated only as its
  stated canary construct;
- release-history validation; and
- a fresh code-backed Roundtable re-audit of the candidate diff.

CI and deployment statuses remain `pending-push` until the exact release commit
passes their remote jobs. A local green run is not written as remote evidence.

## Freeze rule

Freeze this candidate only if the fresh re-audit finds no reproducible code-level
blocker inside the stated deterministic boundary and the exact release checkout
passes every local and remote gate. Any later claim about factual correctness,
accessibility, teaching quality, instructor approval, or classroom effect needs
new evidence and is outside this checkpoint.
