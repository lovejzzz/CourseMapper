# V0.15.152 Provider Failure Status Truth Roadmap

## Goal

Make failed provider-credit starts truthful on the workspace surface: once the
course-map request has failed, the header CTA and build ribbon must stop
showing active `Building...` status.

## Lane

UI truth and pipeline-state repair. This is not a quality-generation release;
it is the smallest fix justified by the failed fresh v0.15.151 GPT-5.5-pro
audit attempt.

## Release Boundary

Ship only the terminal generation-error state fix, focused pipeline/ribbon
regressions, and release-truth documentation. Do not broaden this release into
blocked-step semantics, source scoring, texture scoring, or provider-cost
changes.

## Evidence

A fresh deployed v0.15.151 GPT-5.5-pro Python audit attempt loaded the live
app, authenticated as Tian Xing, selected OpenAI `gpt-5.5-pro`, and accepted
the Introduction to Computer Science with Python prompt. The start screen
already showed `Insufficient Funds`; after the bounded start attempt, the
workspace showed:

- `Model credits unavailable`
- `AI generation failed: Failed to generate a course map. Please check your API key and try again.`
- no course map and no generated materials
- stale header/ribbon state still saying `Building...` / `Generating the course map`

No fresh v0.15.151 ZIP/log score can be claimed from this attempt because the
provider stopped before course-map output. The useful CourseMapper-side defect
is the stale UI truth: a terminal provider-credit failure must not continue to
look like an active build.

## Scope

V0.15.152 keeps the release narrow:

1. Terminal course-map generation failures set `progressStep` to `error`.
2. The pipeline machine no longer sees the failed attempt as active Map work.
3. The build ribbon and primary CTA stop rendering a stale Building state when
   the package is blocked by a provider failure.
4. The release preserves the existing source, texture, report, export, and
   grader standards.

## Non-goals

- Do not claim a fresh v0.15.151 or v0.15.152 GPT-5.5-pro package score.
- Do not weaken model-comparison criteria or infer quality from the failed
  provider attempt.
- Do not hide provider-credit failures; show the actionable blocked state.

## Exit criteria

The release may claim the failed-provider UI state is truthful after focused
pipeline/ribbon tests and normal release gates pass. The next quality evidence
step remains a fresh deployed v0.15.152 GPT-5.5-pro Python ZIP/log audit after
the OpenAI key has enough credits.
