# v0.15.86 UX Source Relevance Gate Roadmap

## Goal

Keep User Experience source proof honest in real provider output by moving weak
false-friend rows into review notes instead of trusted source-ledger proof.

## Evidence

The June 27, 2026 fresh v0.15.85 User Experience Design Studio audit produced
a package at:

`verification-output/edutool-audit-loop/20260627T160000Z-v01585-ux-fresh`

The saved logs met the v0.15.85 observability goal. The current-run log includes
readable `providerRequestStart`, `providerResponseDone`, `repairRetryCall`,
`compilerPlan`, `compiledDeliverable`, and `[CM][DIGEST]` rows. Those rows show
that native enrichment retried twice, compiled 9 deliverables locally, avoided
about 17 provider calls, and still finished with one lesson on template fallback.

The package exported at `97/100 (A)` with texture `94`, but the stricter local
regrade is `88/100 (B)`. The loss is mostly citation truth, not general prose
quality:

- trusted UX source-ledger rows included weak or off-discipline false friends
  such as metaverse hype, process-control workshop proceedings, film/book pages,
  aircraft design process, Persona series, and generic interface/prototype rows;
- Lesson 1 stayed partial after two repair/retry calls;
- readiness correctly blocked the package rather than presenting it as clean.

## Lane

Source trust and grader truth. This release does not lower source standards or
claim a clean package. It makes the production source ledger and local grader
agree on what counts as trusted User Experience proof.

## Scope

In scope:

1. Require User Experience or design-domain anchors before source rows become
   trusted concept-linked proof.
2. Accept concept-specific anchors such as user research, persona, usability,
   accessibility, wireframe, prototype, journey map, and interface design when
   they genuinely match the attached concept.
3. Quarantine weak UX false friends into source review notes instead of trusted
   sourceLedger rows.
4. Mirror the same UX false-friend gate in the deep quality grader so exported
   trusted rows are scored as citation defects.
5. Preserve v0.15.85 trace logging because it made the repair/compiler process
   explainable from ordinary saved logs.

Out of scope:

- Weakening citation scoring to make this package pass.
- Treating metadata-only or off-discipline rows as trusted proof.
- Broad source-finder architecture changes.
- Fixing partial enrichment recovery in the same release.

## Release Boundary

The release is useful if a weak User Experience source row can no longer become
trusted proof just because it shares generic terms with the lesson concept, and
if the grader catches any exported package that still trusts those rows.

## Carry Forward

- Run a fresh deployed v0.15.86 ZIP/log audit and verify UX false-friend rows
  appear only as source review notes or are absent from trusted sourceLedger
  proof.
- Continue partial enrichment recovery for the remaining lesson-coverage loss.
- Keep using the v0.15.85 trace rows to explain retry, fallback, compiler, and
  export behavior in every fresh audit.
- If the Agent note card still feels too dense after quality fixes, simplify the
  note presentation without adding warning prose back to the export panel.
