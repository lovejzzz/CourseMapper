## 2. 第一段 schema 决策

保留外层 `COURSE_GRAPH_VERSION = 1`，新增可选的 `teachingProgram.version = 1`。没有教学程序的旧图仍可读取。后续增加操作和评分协议时单独版本化，不能把本轮版本号误解为整个 v0.20.0 schema 已冻结。

当前程序包含：

- `objectives`：任务需要学生展示的具体表现，稳定 ID 和文本。
- `sources`：带稳定 ID 的输入陈述；旧来源标为 `legacy-task-input`，不追认其事实真实性。
- `tasks`：通过 `objectiveRef`、`inputs[].sourceRef` 引用目标与来源，保留任务 ID、原输入 ID、课次绑定、时间、作用域和未知的教师字段。
- `revision`：对规范化 JSON 计算摘要，用于检测变动和不完整保存；不是事实认证或教师审批。

任务层表现与旧课程总体 outcomes 的正式对齐关系仍待 M2 实现。首轮存储迁移仍通过旧 solver 派生推理和评分；后续首个操作的绑定与评分权重已写入任务，见第 8 节。所有教学实体的统一尚未完成。

没有根据文本相同自动合并来源。两个独立案例即使陈述相同，也保留各自身份。显式共享引用可表达共同来源；不同任务对同一引用提出相互矛盾的更新时拒绝静默选择其中一个。

`teachingTaskSources` 继续存在于材料快照和 map 的兼容视图中；只要程序存在，读取时以程序为准。新的图不在 `course.meta` 另存这份 ledger。旧文件中用户自定义的来源、输入和任务字段需往返保留。

### 8.1 题目、答案、评分与对照作答一起改

原评分的 Developing 档只举了错误结论，没有合理覆盖“结论正确但缺少解释”。新描述区分有效范围的解释、只有结论的回答和“新记录证明旧记录从来错误”的误解。

题目、参考解答和最高档都明确要求提出一份能够补足日期缺口的具体佐证，避免只在评分中偷偷增加要求。参考解答把拟寻找的记录与已经取得的事实分开，也接受其他相关佐证。

每个该类核心任务现在产生四种检查用回答：完整推理、正确结论但推理不足、典型误解、合理的替代表达。记录按评分要求关联的判断、理由和精确作答摘录。Rubrics 与 Assignment Briefs 的现有教师参考折叠区展示这些内容；Word 的 rubric 教师参考也包含四类示例。它们是作者构造的检查材料，不是学生数据，也未取得独立评分信度证据。

新要求不能把旧生成文字误判成教师覆盖。为此从真实 v0.19.2 发布工程提取 Study Guides 回归夹具，并保留仅用于三方合并的历史呈现基线；接受修改后写入新的明确操作。这一兼容基线不参与新的内容生产。
