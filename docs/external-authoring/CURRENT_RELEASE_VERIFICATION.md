## Resilience follow-up

A deterministic interleaving reproduced an additional quota-fallback race: an older pending IndexedDB save removed a newer project's local Resume marker. Marker retirement now checks that the stored value still equals the marker the pending operation replaced. Failed fallback transactions preserve the previous marker.

Website exchange calls now have a 30-second deadline covering token refresh, network response and response parsing. Timeout aborts the request and releases the UI; a late token refresh cannot send a mutation. The message explicitly says a server change may already have committed and directs users to refresh/recover before retrying. Null response bodies fail with an actionable error. Existing durable intent/reservation/receipt recovery remains the mechanism for uncertain writes.

All 175 authoring tests passed locally (six Firestore cases require the separate emulator workflow). New real HTTP tests use cryptographically signed JWTs and the production verifier to check same-token binding revocation, revoked-before cutoffs, newly issued tokens, expiry, cross-account denial and request revocation/list filtering. These automated issuer fixtures do not substitute for real provider or second-Google-account acceptance. ChatGPT's fresh page still stalled loading its connector selector during the follow-up, before a tool call could be submitted.

The follow-up also runs two isolated real Chrome profiles against an HTTP exchange fixture. Lost reservation and receipt response bodies trigger the production client deadline; reloading the first profile recovers its durable intent and latest teacher edits. The second profile remains locked out after a simulated day and after receipt commit, while retrying the first receipt is idempotent. This six-case script is now part of browser CI. Identity and server storage remain fixtures; it does not establish live Google/Auth0 or physical-device cloud-sync behavior.
