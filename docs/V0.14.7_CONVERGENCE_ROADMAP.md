# V0.14.7 — Convergence: one graph, one machine, one voice

_The execution plan for everything in [BEFORE_V0.14.6.md](BEFORE_V0.14.6.md). Theme: stop maintaining two of everything — two authoring worlds, six overlapping status flags, two notions of quality (grader 100/A vs judge 5–6/10). Every workstream below collapses a duplication into one owned thing, with the bar defined before the work starts._

**North star:** the judge's question — _"would a professor teach from this as-is?"_ — becomes a measured, gated dimension, and the answer moves. Without giving up the $0.15 course.

## WS-A — Parallel prose enrichment (the quick win)

**Problem (audit §2.4):** `useDeliverables.js` ~1165–1200 runs enrichment as `for (chunk) { await call(chunk) }` — four serial model calls for 15 lessons. This is most of the 152s-vs-65s gap, and the prose path remains the fallback even after the native flip.

- **A1.** Replace the serial loop with bounded concurrency (`Promise.all` over chunk thunks; cap 4). Kernel results are keyed by lessonIndex, so the merge is already order-independent — verify, don't assume.
- **A2.** Budget integrity under concurrency: `blueprintEnrichmentCall` / `apiUsage` events will interleave. The apiCallBudget reducer is event-applied and should tolerate this — pin it with a test (concurrent event sequences produce the same totals as serial). The trailing-event test must stay green.
- **A3.** Ribbon behavior: the enrich sub-label shows the latest event; with interleaving it will flicker between chunks. Acceptable; if it reads badly live, show "Enriching lessons (2 of 4 batches)" from counts instead.
- **A4.** Stop/abort: cancelling generation must abort all in-flight chunk calls, not just the current one. Recovery passes stay serial (they're small and sequential by design).

**Bar:** byte-identical kernels vs serial on the fixture matrix; 15-lesson live wall-clock −40% or better; budget totals identical; abort leaves no orphan spend events.

## WS-C — The pipeline state machine (kill the bug class)

**Problem (audit §2.2):** phase truth is re-derived from six overlapping flags (`gen.isStreaming`, `gen.progressStep`, `deliv.isGenerating`, `packageGenerationBusy`, `finishPackageBusy`, `packageQualityPass.status+phase`). Three releases in a row shipped a symptom of this.

Two-step strategy — **derive first, invert later** — so this is never a big-bang rewrite:

- **C1.** `src/lib/pipelineMachine.js`: a pure selector `derivePipelineState({ generation, deliverables, packageQualityPass, busyFlags })` returning ONE value: `{ state: 'idle'|'mapping'|'enriching'|'compiling'|'verifying'|'grading'|'ready'|'blocked', detail }`. It encodes, in one tested place, every precedence rule we currently re-implement per surface (including v0.14.6's phase split and the `!mapRunning && !delivRunning` belts).
- **C2.** Consumers swap to the selector: `buildRibbonModel` (its stage logic becomes a render of C1), `WorkspaceQualityChip`, the Finish button, `AgentWorkingSetPanel`, `ProgressHeader`, ExportSidePanel's gating. **No UI string changes** — this step is pure plumbing, pinned by the existing surface tests passing unmodified (the v0.14.6 regression tests are the acceptance suite).
- **C3.** Invert ownership (second commit): AppFlow dispatches transitions (`MAP_STARTED`, `ENRICH_STARTED`, `FINISH_STARTED`, `GRADED`, …) to a reducer; the legacy booleans become derived/back-compat reads. Illegal transitions log loudly in dev. `packageQualityPass` keeps its shape (receipt, quality) but its `status/phase` become projections of the machine.
- **C4.** AppFlow diet: move the finalizer orchestration block (~1200–1800) into `src/lib/packageFinishRunner.js` with an injected dispatch. Target: AppFlow under 4,000 lines this release (it's structure, not heroics — bundle budget updated with a dated comment).

**Bar:** all existing tests pass at C2 with zero string changes; after C3, a new test enumerates every machine state and asserts each surface's render for it (the matrix that was impossible to write against six booleans); the v0.14.6 screenshot states are machine states, not boolean coincidences.

## WS-D — Voice pass + texture gate (the point of the release)

**Problem (audit §2.1, §2.5):** templates can't manufacture teaching, and nothing in the pipeline is paid to improve the judge's 5–6/10.

**Why the judge says 5–6/10 — the four root causes, named:**

1. **One skeleton, fifteen stamps.** Every lesson plan shares one section arc, every brief one structure, every discussion one shape — fifteen instances of one template family. A professor flipping pages senses the stamp in seconds; sameness across documents is the loudest machine-tell.
2. **Slot-filling can't commit.** A template sentence must be true for ANY concept, so it is generic by construction — "use [concept] to guide the evidence you select in [artifact]." A real instructor writes "watch what happens to the difference quotient for f(x) = x² as h → 0." Only content that _knows the subject_ can commit to specifics; templates structurally cannot.
3. **Enrichment fills holes, not connective tissue.** Kernels inject real subject matter (misconceptions, worked examples, citations) — but only into designated slots. The prose _between_ the slots stays boilerplate, so documents read as real-content beads on a templated string.
4. **Uniformity has no rhetorical arc.** Human teaching documents have voice, emphasis, asymmetry — a long warning where students actually struggle, a terse line where nothing needs saying. Templates weight every week identically, and uniform emphasis reads as no emphasis.

And the meta-cause: **texture was never a scored dimension**, so the refine loop — which crushed every defect it could measure, 51/F → 100/A — never applied a single round of pressure here. The one controlled lever we have measured: grounding in the instructor's real material moved the judge +1 (world-lit 6/10 vs its readings-free twin's 5/10). Specificity is the lever; D2 pulls it deliberately, D1 makes it measurable, WS-E widens it (more genome coverage = more lessons with real kernels = fewer generic slots), and WS-G7 keeps it from washing out on sync.

- **D1. Texture becomes a measured dimension.** New grader dimension `texture` (advisory weight 0 at first): slot-masked cross-document skeleton similarity (mask concept/lesson/registry tokens, then shingle-overlap across same-feature docs), distinct sentence-opener ratio per document, template-tail frequency. Calibrate against the judge ledger (`scripts/crucible/verdicts.json`): the metric must rank world-lit-readings above its readings-free twin and rank v0.14.0 fixtures below v0.14.6 output, or it doesn't ship. **Trap from v0.14.3:** calibrate before gating — a texture metric that fails honest variation is worse than none.
- **D2. The voice pass** (flag `coursemapper-voice-pass`, default off): after compile, batched low-reasoning calls rewrite ONLY the high-read surfaces:
  - assignment brief context/overview paragraphs,
  - discussion prompt framings (the "Anchor your post in X" requirement line is **frozen text** — voice wraps it, never rewrites it),
  - study-guide narrative intros.
    Prompts are grounded in the graph: kernel, registry ids, readings, evidence cues. **Hard contracts per item:** registry ids and verbatim titles preserved exactly; zero new factual claims or citations (citation text is frozen); 60–140 words; per-item lint with fallback to the compiled text on any violation (never block the package on voice). Budget: $0.03–0.05/course as a planned line in the cost plan, with the standard loud degradation if the budget is exhausted mid-pass.
- **D3. Crucible proof, native-funded:** `--voice on|off` side-by-side on 3 courses (one readings-rich, one genome-linked, one stranger). **Bar to flip default:** judge +1 or better on at least 2 of 3 courses, deterministic grade stays 100/A with drift Δ0, zero new P0/P1 classes, texture dimension improves, total cost ≤ $0.15 (native savings fund it — that's the whole deal). Met twice on different days, same as the native bar. Until then: flag-gated, honestly reported.
- **D4.** QUALITY_REPORT and the digest disclose the voice pass ran (which surfaces, how many fallbacks) — provenance discipline applies to our own rewrites too.

**Bar:** D1 calibration passes; D3's bar met twice before any default flip; a voice-pass failure can never produce a worse package than no voice pass (fallback proof in tests).

## WS-E — Genome as cache, math as the proving case

**Problem (audit §2.6):** hand-curated shards don't scale; calculus linked 5/15.

- **E1.** Seed the math shard the proven way: foundry run over OpenStax Calculus (the scripts exist; this is the same motion as the original 3-shard run). Target ≥15 concepts with verified citations.
- **E2.** On-miss extraction (flag `coursemapper-genome-extract`, default off this release): when the linker misses, one low-reasoning call proposes kernel-shaped concepts (definition shape, misconceptions, prerequisite edges, citation _candidates_). **Citations are never model-trusted:** candidates resolve through the knowledge providers (OpenAlex/OpenLibrary) and only verified ones persist — the v0.14.1 citation-relevance gate applies unchanged.
- **E3.** Persistence through the commons layer, kernels only: concept abstractions, never course or instructor content (the privacy boundary already drawn for commons applies verbatim). Local cache first; commons contribution stays behind the existing opt-in.
- **E4.** Proof: re-run the Calculus I course. Before/after metric is the log line itself: `5/15 lessons genome-linked` → **12+/15**, with citation gate green and zero grader regressions.

**Bar:** E4's numbers; no extraction call ever runs without the flag; nothing model-invented persists unverified.

## WS-G — Sync as a star feature (the IP made visible)

**Problem (audit §2.9):** sync is the one capability only a compiled product can offer honestly — "change one thing" without regenerating everything at full cost and fresh hallucination risk. The engine exists and its bones are good (approval-first, zero-cost compiler path, blueprint projection, budget guards), but it still runs on its pre-graph V1.8 architecture, and the audit found four holes: synced lessons silently lose enrichment, the syllabus is excluded from every per-lesson blast radius, the quality grade goes stale after sync with no disclosure, and patch identity is regex-on-titles instead of registry ids.

- **G1. Enrichment-preserving sync (the correctness P0).** Persist the per-lesson enrichment kernels in the project (they're small; today they die with the generation run). `compileBlueprintLessonPatch` merges them via `mergeBlueprintEnrichment` before compiling, so a synced lesson keeps its subject-matter grounding. When the edited fields invalidate the kernel (objectives/topic/title edits), refresh that one lesson's kernel with a single low-reasoning call (~$0.005, disclosed in the sync receipt); cosmetic edits (resources, technology, format) reuse the stored kernel at $0. **Gate:** a new finalizer check — a sync may never reduce a lesson's enrichment coverage; if the kernel is missing and can't be refreshed, the sync card says so before approval, not the package after.
- **G2. Recompile-and-diff replaces the lookup table.** The compiler is a pure function and runs all 9 features in ~500ms — so compute the TRUE blast radius: apply the edit to the blueprint, recompile affected-candidate features, and **diff against current state using registry identity** (assessment ids, reading ids, lessonNumber on every compiled item). What actually changed _is_ the sync plan; `FIELD_DEPENDENCY_MAP` survives only as a fast pre-filter and for labels. The syllabus rejoins the blast radius automatically (its grading table diffs when `weeklyAssessments` changes), and readings edits propagate to every surface that inherits them — both current silent-divergence holes close by construction, not by remembering to update a map.
- **G3. Post-sync truth.** After any executed sync: re-run the deterministic finalize check and the quality grade (both free, both <2s), update the chip and manifest, and stamp the sync receipt with the new grade. The pipeline machine (WS-C) gets a real `syncing` state so the ribbon narrates it honestly. A stale "Quality 100 · A" over an edited package becomes unrepresentable.
- **G4. Queue-native approval with a real diff preview.** The sync suggestion becomes a review-queue class (the v0.14.6 pattern: one-line entry, queue carries the detail). Because G2 produces actual diffs, the approval card can finally show the educator **exactly what will change, per deliverable, before they click Sync** — "Rubric L5: 2 criteria reworded · Syllabus: grading table row updated" instead of "3 deliverables need syncing." Batch approve, per-target opt-out, nothing auto-applies (the existing covenant stands).
- **G5. Identity-based patch merging.** `buildCompiledLessonPatchData` and the regen merge match items by registry ids first (assessmentId, readingIds, the compiler's own lessonNumber fields); the title-regex matcher demotes to last-resort for legacy data, with a loud trace when it fires. This retires the text-matching defect class from the one code path that rewrites graded content.
- **G6. The Crucible learns to edit.** A scripted scenario joins the round set: generate → edit lesson 5's objectives + an assessment weight → approve sync → assert enrichment coverage unchanged, syllabus grading table updated, grade re-run with drift Δ0, compiler-only cost $0 (plus the one disclosed kernel refresh). The star feature finally gets the same live discipline as generation.
- **G7 (after WS-D flips).** Voice-on-sync: if the voice pass is default-on, a synced surface re-runs its voice rewrite within the same budget contract — synced lessons read like the rest of the package, not like a template patch in a voiced document.

**Bar:** G6's scenario green twice; a sync can never reduce enrichment coverage (gated, not advised); `weeklyAssessments` edit updates the syllabus in the same approval (test); post-sync chip always reflects a fresh grade (test); compiler-only syncs complete in <5s wall-clock at $0; every model-assisted step in a sync is itemized in the receipt.

## The horizon (explicitly not in scope — but what this release builds toward)

**CurriculumOS is the product; the website is its first client.** The end-state surface is two things: a **door** (describe your course — one box, your materials) and a **desk** (the living course you work at with your TA — the package, the grade, sync). Everything else we've ever drawn — config screens, feature pickers, export panels — is incidental UI that progressively dissolves into the brain behind an API:

- `POST /course` → brief + materials in; graph + package + grade + provenance receipts out.
- `PATCH /course/{id}` → an edit in; a **diff + a fresh grade** out. (This is WS-G's recompile-and-diff, verbatim — sync IS the API's update semantics.)

Every response carries its own QUALITY*REPORT and provenance — the only course API whose answers prove themselves. Clients beyond our website: LMS plugins that compile courses \_into* Canvas/Moodle, other ed-tech products that embed the brain. And the genome-as-cache (WS-E) is the network effect: every course generated anywhere makes the brain smarter for everyone, privacy-safely, through the commons.

Why write this here: V0.14.7 is, item by item, the API's prerequisites — WS-C defines the lifecycle states an API would expose, WS-G defines its update semantics, WS-D raises the quality bar to "teachable," WS-B/E make the unit economics and knowledge coverage scale. Convergence isn't cleanup; it's productization groundwork.
