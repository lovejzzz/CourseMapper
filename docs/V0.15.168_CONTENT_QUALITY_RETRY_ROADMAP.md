# V0.15.168 Content-quality Retry Roadmap

## Evidence

- Fresh deployed v0.15.166 GPT-5.4-mini Python browser evidence:
  `verification-output/edutool-audit-loop/20260630T221931Z-v015166-fresh-blocked/`.
- The run blocked before ZIP export, so no exported-package score should be
  claimed from it.
- The digest showed:
  - final status `blocked`;
  - 16 deterministic repairs applied;
  - 1 repair-stage retry call from generation recovery;
  - 0 finish-stage retry actions;
  - 9 export/content warnings, all `dangling-clause`, across generated
    deliverables.

## Goal

Move export finishing from "warn after we know the defect" to
"validate, repair, retry targeted content-quality defects, then export or
block honestly."

Content-quality warnings that survive deterministic repair are not subjective
style preferences. They are concrete, visible defects such as dangling clauses
or student-facing instruction seams. If the user clicked export and the app has
retry budget, these warnings should produce retry targets before the app asks
the instructor to review a caveated package.

## Lane

Export finish policy, content-quality retry routing, and report-truth
agreement. This is not a model upgrade, grader weakening, source-ledger
relaxation, or broad UI redesign.

## Release Boundary

This release may claim a deterministic CourseMapper-side retry-routing fix. It
may not claim a clean v0.15.168 package until a fresh deployed GPT-5.4-mini
ZIP/log audit proves the retry path in real provider output.

## V0.15.168 Scope

- Add a finalizer option for retrying content-quality warnings separately from
  broad warning retries.
- Enable that option only for export-triggered package finishing.
- Keep normal classroom/readability warnings review-only when `retryWarnings`
  is disabled.
- Add a regression proving a surviving student-facing content-quality warning
  creates a concrete retry target.

## Why This Is CourseMapper-side

A better model may emit fewer dangling clauses, but the observed failure was in
CourseMapper's finish policy: the app had named warnings and reserved retry
budget, yet produced zero finish retry actions. The product should not wait for
the user to review defects it can target itself.
