**Thesis:** CurriculumOS already has the only thing that cannot be retrofitted
— a mechanical trust gate (quote-verified anchors, the T0–T4 ladder, the
foundry admission pipeline) and a typed Course Graph to hang knowledge on.
What it lacks is **scale and reach of real knowledge**. V0.13.5 connects the
six great open-knowledge systems — **OpenStax, OpenAlex, CORE, ERIC, OER
Commons, Open Library** — so that every course CourseMapper produces is
backed by sources a librarian would accept: cited facts, real readings,
licensed activities, and teaching moves that themselves cite the learning
science. No course generator on the market has receipts; this release makes
receipts the default.

**The architectural insight that makes it feasible without a backend:** split
the knowledge layer by WHERE it runs.

- **Build time (the foundry, Node, no CORS limits, keys allowed):** OpenStax
  full-text ingestion, CORE full-text retrieval, bulk OpenAlex topic
  harvesting → genome shards. Heavy, slow, careful — runs in CI/locally,
  ships as static JSON.
- **Run time (the browser, keyless, CORS-friendly only):** OpenAlex
  (CORS ✓, polite-pool mailto already in use), ERIC (api.ies.ed.gov),
  Open Library, Wikipedia — for per-course reading lists, citation
  freshness, and retraction checks. Cached aggressively; every call
  optional; the compiled course never blocks on a network call.

The existing `academicSearch.js` adapters (agent chat cards) get promoted
into a real provider layer that BOTH consumers share.

**What each system contributes:**

| System       | Role in CurriculumOS                                                                                                               | Where                            |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| OpenStax     | The fact feedstock: ~60 CC-BY textbooks covering most intro curricula → quote-anchored genome kernels                              | Build time                       |
| OpenAlex     | Scholarly readings per concept; topic taxonomy for concept discovery and prerequisite hints; retraction + currency checks          | Both                             |
| CORE         | Open-access full text for upper-level readings; PDF links students can actually open                                               | Build time (API key)             |
| ERIC         | The pedagogy evidence base: citations for the teaching moves themselves (misconception polls, worked examples, retrieval practice) | Both                             |
| OER Commons  | Licensed activities, labs, and lesson materials matched to lessons                                                                 | Build time index + runtime links |
| Open Library | Textbook metadata, ISBNs, editions, covers for syllabus Required Texts                                                             | Run time                         |

## P0 — The knowledge provider layer

Promote `academicSearch.js` from agent-tool helper into
`src/lib/knowledge/`: one adapter per provider with a shared contract
(`search`, `byId`, `cache`, rate-limit etiquette, license metadata on every
result), consumed by the agent cards (no behavior change), the reading-list
engine (P2), and the foundry clients (P1). Hard rules: every result carries
`{ license, attribution, url }`; every adapter degrades to empty results on
failure (offline compile always works); OpenAlex keeps the polite-pool
`mailto`; runtime calls are cached in localStorage keyed by query + week.

**Acceptance:** agent research cards work unchanged through the new layer;
adapters have unit tests with recorded fixtures; zero network calls in the
deterministic compile path.

## P1 — The foundry goes industrial: OpenStax ingestion at scale

Today a shard is hand-authored (the astronomy shard: one session, 12
concepts). P1 builds the pipeline that makes shards cheap:

1. `scripts/foundry/ingestOpenStax.mjs` — fetch a book's section pages
   (the `pages/<n-n-slug>` pattern proven in v0.13.3), strip to clean text,
   store per-section snapshots with checksums.
2. `scripts/foundry/proposeKernels.mjs` — model-assisted candidate
   extraction (build-time API key): for each section, propose concept
   kernels — definition, facts, misconceptions WITH correctives, worked
   examples for quantitative concepts, MC items — where **every anchored
   field must quote the snapshot verbatim**. The model proposes; the
   mechanical gate disposes. Rejected anchors strip to tier 0 and surface
   in the build report for human review.
3. Aliases and `instanceOf` candidates seeded from OpenAlex's topic
   taxonomy (concept names, related terms) — proposed at low confidence,
   never auto-verified (Layer 2's forced-analogy guard stays sovereign).
4. **Flagship shards shipped with this release:** Psychology (OpenStax
   Psychology 2e → ed-psych courses), Anatomy & Physiology + Microbiology
   selections (→ nursing courses), and Human Nutrition (University of
   Hawai‘i OER, CC-BY — OpenStax has no nutrition title). Target: **+100
   to +150 concepts**, taking the four audit flagship subjects
   (astronomy ✓, nutrition, nursing, ed-psych) fully onto the cited path.

**Acceptance:** the three audit courses that linked 0/14–15 lessons in
v0.12 each resolve ≥60% of lessons from the genome in the proof harness;
every admitted kernel passes the quote gate; the build report shows
proposal→admission yield per book.

## P2 — The reading-list engine: real readings in every lesson

The v0.12 audit's longest-lived defect was "Instructor-provided course
materials" — the placeholder citation. P2 retires the _class_ of problem:

1. For each lesson, build resource queries from its Course Graph concepts
   (terms + aliases — not cell prose).
2. Assemble a per-lesson **Readings & Resources block**: the genome
   concept's own anchor section (OpenStax §, always first), one
   peer-reviewed reading (OpenAlex, prefer OA + recent + cited), one
   open-access full text (CORE, when available from build-time cache), one
   activity/lab (OER Commons), and book metadata for syllabus Required
   Texts (Open Library). Every entry: title, source, license, URL, and a
   one-line "why this reading" tied to the lesson objective.
3. Results land as **Resource entities in the Course Graph** (`origin:
'openalex' | 'oer-commons' | …`) and render in supportingResources, the
   syllabus, lesson-plan materials, and the study guide — replacing every
   placeholder fallback.
4. Instructor control: the reading list is a proposal surface — swap,
   pin, or reject per lesson; rejections persist in the graph.

**Acceptance:** zero placeholder citations in the four flagship courses;
each lesson ships ≥2 real, linked, licensed resources; reading lists render
offline from cached graph entities.

## P3 — Evidence-based pedagogy: the teaching moves cite their science

Nobody else can do this honestly, because nobody else has deterministic
teaching moves. CourseMapper's compiler owns its pedagogy — misconception
polls, worked examples, retrieval-practice warm-ups, peer instruction,
spaced review — so the pedagogy itself can carry citations:

1. `src/lib/pedagogyEvidence.js` — a curated evidence file mapping each
   compiler teaching move to its research base (the worked-example effect,
   misconception-based instruction, retrieval practice, peer instruction),
   each entry carrying 2–3 real citations with ERIC/OpenAlex identifiers,
   curated by hand and link-checked at build time.
2. Lesson plans gain instructor-facing "why this works" notes ("Worked
   examples reduce cognitive load for novices [Sweller; ERIC EJ...]");
   the syllabus gains an optional Methods Statement section summarizing
   the course's evidence-based design — the artifact instructors show
   accreditors.
3. The CCR rubric gains a pedagogy-evidence dimension.

**Acceptance:** every deterministic teaching move in the compiler maps to a
cited evidence entry; links verified by the build-time link checker; the
methods statement renders in the syllabus when enabled.

## P4 — The trust surface: coverage you can see

Receipts only matter if they're visible:

1. **Coverage meter:** per-course "X% of facts source-anchored · Y lessons
   genome-linked · Z readings attached" in the workspace trust strip, the
   run digest, and PACKAGE_MANIFEST.json.
2. **Per-lesson source panel:** what's cited (with quote-on-hover), what's
   model-authored pending verification (T1), what an instructor verified
   (T3) — the trust ladder made visible where editing happens.
3. **Export surfaces:** a Sources & Licenses appendix in the syllabus DOCX
   and the package (every OpenStax section, paper, and OER item with its
   license and attribution — CC-BY compliance made automatic).
4. The compiled-without-enrichment warning generalizes into a coverage
   gate: below-threshold courses say so, honestly, in the digest and the
   trust strip.

**Acceptance:** the four flagship courses show ≥80% anchored-fact coverage;
the appendix renders with correct attribution for every source system.

## P5 — Living knowledge: the backbone stays alive

1. **Link health + retractions:** a build-time (and on-demand runtime)
   checker walks every genome anchor and reading-list entry; OpenAlex
   `is_retracted` flags retracted papers; dead links and retractions
   surface as shard freshness findings.
2. **Freshness review:** shards carry `reviewBy` dates by volatility;
   fast-moving disciplines get earlier review windows.
3. **The commons flywheel formalized:** instructor verifications (T3)
   recorded against anchor checksums, so a verified fact whose source text
   later changes is re-flagged — verification is of a quote, not a vibe.

**Acceptance:** `npm run knowledge:audit` reports link health, retraction
status, and freshness across all shards and curated evidence; CI runs it
weekly.

## Cost & constraints

- Generation cost is unchanged (~$0.05–0.15/course): the backbone is
  build-time data plus cached keyless runtime lookups. Foundry proposal
  passes cost build-time tokens (~$1–3 per textbook, one-time, amortized
  over every course ever compiled from it).
- No backend appears: runtime providers are CORS-friendly and optional;
  CORE (API key) is build-time only; the static-BYOK privacy posture is
  untouched.
- API etiquette: polite-pool mailto (OpenAlex), conservative rate limits,
  cached responses, attribution everywhere — we are a good citizen of the
  commons we draw from.
- Licensing is structural: only CC-BY/CC-BY-SA/public-domain sources enter
  the genome; the attribution appendix is generated, not hoped for.

## Explicitly deferred

- Non-English sources and translations.
- Publisher-licensed (non-open) textbook ingestion — by-design exclusion,
  not a gap.
- Embedding-based semantic linking (the lexical+alias linker stays until
  its miss rate, measured by the P1 harness, justifies vectors).
- Student-facing live citations UI (instructor surfaces first).

## Why this is the release that makes the impact

1. **Trust is the product.** Every AI tool can generate a quiz; none can
   show an instructor the verbatim textbook sentence behind every answer
   key. The quote gate plus the backbone turns "AI-generated" from a
   liability into a credential.
2. **It compounds.** A textbook ingested once backs every course compiled
   from it forever, at zero marginal cost. Instructor verifications make
   the shared genome better for the next instructor. No per-course API
   spend competes with that economics.
3. **It serves the people the market ignores.** Adjuncts teaching four
   courses, community colleges without instructional designers, teachers
   in low-resource systems — they get what elite universities pay teams
   for: a cited, evidence-based, accreditor-ready course package, free to
   open, built on the open commons, giving back to it.
