# V0.15.6 - Classroom Truth: coverage, texture, and ready states get stricter

_Written June 17, 2026, from the Human Anatomy and Physiology I export audit and
the overwhelmed ready-state UI screenshot. Theme: the app cannot call a package
perfect when it only linked one useful concept, reused obvious templates, or
showed the user duplicate download confidence._

## Goal

Make CourseMapper more honest at the classroom boundary. A ready package should
mean the subject received real source coverage, the generated resources match
the discipline, visible prose repetition affects the grade, and the workspace
does not ask a non-expert user to reconcile contradictory quality signals.

## Lane 1 - Anatomy Coverage Becomes Real

1. Add an Anatomy and Physiology genome shard from OpenStax A&P 2e.
2. Teach the shard loader to route anatomy, physiology, histology, homeostasis,
   lab practical, and body-system prompts into the anatomy shard.
3. Keep physics reproducible by restoring its foundry source instead of relying
   on an orphaned built shard.

**Bar:** anatomy and physics foundry sources validate cleanly, the genome build
emits both shards, and the A&P fixture links most lessons instead of passing on
one linked concept.

## Lane 2 - Native Authoring Recovers Missing Resources

1. When Pass A names resources but the graph skeleton has no reading/resource
   nodes, synthesize explicit instructor-confirmation resource placeholders.
2. Preserve the native graph path instead of falling back to prose solely
   because resource slots were omitted.
3. Surface the recovery in pipeline decision text so audit logs explain the
   repair.

**Bar:** native authoring tests prove missing resources recover with
`missing-resources-recovered`, while degenerate assessment blockers still block.

## Lane 3 - A&P Assets Stop Looking Like Field Geology

1. Add an A&P required-assets genre before generic wet-lab handling.
2. Use anatomy models, histology slides, anatomy lab manuals, and specimen/model
   policy instead of rock, mineral, streak plate, field notebook, or hand-lens
   supplies.
3. Make the deep package grader flag geology/chemistry field kits in A&P
   packages as a structural finding.

**Bar:** unit tests reject field-geology supplies for A&P, and the grader
detects the exact wrong-asset class found in the user export.

## Lane 4 - Texture Counts

1. Give texture a light score weight instead of treating it as advisory only.
2. Add package-wide repeated-template checks for common generated stems.
3. Turn low texture into a finding so an A can still exist, but a perfect
   100/A cannot hide same-pattern prose.

**Bar:** quality tests prove texture contributes to the weighted score and
repeated stems create P2 findings.

## Lane 5 - The Ready UI Calms Down

1. Rename weak genome judgment from "Judgment clean" to "Limited knowledge
   check" when concept coverage is too thin.
2. Rename the top-line coverage chip to "Materials" when it is counting
   generated artifact coverage, not teaching knowledge coverage.
3. Hide the side-panel duplicate ZIP button when the header owns the ready
   all-package CTA.
4. Replace technical dependency tooltip phrasing with a shorter "also updates"
   message.

**Bar:** UI tests prove the new labels and single primary ZIP CTA are present.

## Lane 6 - Proof and Release Boundary

This is a compiler/grader/UI-truth release. It does not claim human professor
approval, live-provider model improvement, or remote deep-proof success before
the pushed CI run exists.

1. Add a v0.15.6 release contract with anchors for every current changelog
   claim.
2. Keep v0.15.5 as historical truth-ledger evidence.
3. Generalize the release-history audit so it validates the current roadmap
   instead of only one hard-coded release.

**Bar:** `npm run audit:release-history` passes for v0.15.6 and still validates
the v0.15.5 truth-ledger roadmap.

## Release Boundary

v0.15.6 fixes the concrete output and UI truth failures surfaced by the A&P
test. It does not finish the larger autonomous self-improvement loop, expand the
professor-adoption benchmark, or prove external classroom adoption. Those remain
future quality-system work.
