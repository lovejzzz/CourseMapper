## Deletions executed this release: NONE — and why that is the honest call

The D3 protocol asked for any deletion certified by phase-1 + live data.
None is:

- **legacy-anchor-rebuild** is zero across all 11 live runs, but the live
  corpus is 100% graph-path generations — the zeros only re-confirm the
  registry short-circuit the fixture matrix already proved. The legacy arm
  itself is what detects criteria-stripped anchors after compact-storage
  restore on no-registry projects (12 matrix-core + 1 legacy-fixture hits;
  `tests/v0143-compiler-diet.test.js` asserts them as "the legacy path
  stays alive"). Deleting it would ship criteria-less anchors to every
  restored legacy project. The live rounds cannot certify a branch dead for
  a population they never sample.
- **concept-comma-split** went the other way: the fixture zero on the graph
  classes was a corpus artifact (fixture titles carry no commas). Live
  graph-path runs hit it in 10/11 courses. Not deletable, not narrowable to
  legacy-only entry.

## Migration risk list (P5 prerequisites)

1. **Firestore restore**: derive-on-open must never block open — a
   malformed legacy map's derivation failure needs a degraded-open guard
   (the v0.12.1 degraded-plan lesson: silent fallbacks re-shipped
   mail-merge).
2. **Empty-registry maps**: a map with no parseable weeklyAssessments
   derives a graph with zero assessments → `normalizeAssessmentRegistry`
   returns null → the compile still lands on the legacy arm. P5 must either
   synthesize a minimal registry at derivation time or the deletion keeps a
   ~20-line guarded fallback. This is the single edge that blocks naive
   deletion.
3. **`.coursemapper` imports**: same derive-on-open requirement; verify the
   import path (not just the four open paths) adopts the graph.
4. **Agent edits on legacy projects**: legacy anchors are keyed
   `assessment-N`; registry anchors are keyed `A<lesson>.<n>`. Version
   history, agent proposals, and stored references to legacy ids must
   survive the re-key (or the re-key must be applied once, at migration,
   not on every open).
5. **Telemetry stays armed** one full release after deletion — the C4 net.

## Recommendation for v0.15: GO, with the two-step shape

GO on executing the P5 migration + the ~212-line deletion in v0.15,
provided: (a) derive-on-open lands in all open paths AND import AND restore
with a degraded-open guard; (b) the empty-registry edge is closed by
synthesizing a minimal registry (preferred) or retaining a guarded
fallback; (c) the golden harness and blueprint-quality-matrix gate the
deletion commit (restore on any byte change); (d) the diet-test legacy
assertions flip from "legacy path stays alive" to "legacy entry points are
gone" in the same commit. Do NOT bundle the finalizer regex deletion — it
narrows with P5 but only dies with lesson-level identity (a v0.15.x
follow-up). The full ~3–5k prose-path retirement remains a separate, later
decision after P5 ships and one release of live telemetry confirms zero
legacy-arm entries from production opens (not just Crucible rounds).
