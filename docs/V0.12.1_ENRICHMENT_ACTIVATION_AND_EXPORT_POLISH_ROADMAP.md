# V0.12.1 Roadmap — Activate the Content Stack, Polish the Exports

**Source analysis:** June 10, 2026 four-course output audit (Nutrition, Nursing,
Microeconomics, Educational Psychology — 410 exported files + production console
log `edutool.dev-1781109038012.log`). All four packages were generated with
exactly **one provider call each** ($0.09, course map only): a stale capability
profile silently degraded the generation plan to `prompt_only`, which turned
**off** blueprint enrichment (v0.10.1 adaptive default) and **off** lean
course-map atoms (v0.9.11 default) in the same stroke. Result: the v0.8.6
mail-merge disease shipped again inside v0.12's polished export chrome.

**Audit headlines (what V0.12.1 must fix):**

| Finding | Evidence |
| --- | --- |
| Enrichment never ran | `blueprintEnrichmentRequested: false` + "verbose contract" in all 4 runs; Micro's 13/15 genome-linked lessons are the only real key-concept slides in 58 decks |
| Content is template skeleton | Cross-course sameness modulo nouns: Rubrics 83%, Assignments 76%, Quiz 68%, FAQ 60%, Discussions 59%, Lesson Plans 56%, Study Guides 42% |
| Assessments not classroom-usable | Nursing "Dosage Calculation I" quiz: 0/6 items test dosage; Micro "Elasticity" quiz: 1/6 real; study-guide key terms define themselves circularly |
| Deterministic text bugs | "A. A." doubled option letters (232×), "its the" (58×), "name one the Week N quiz" (56/58 decks), ALL-CAPS short-answer keys (57 files), 62+15 mid-phrase truncations, FAQ double-periods |
| DOCX render defects | All 136 tables overflow A4 margins; `Normal` style + theme part missing; 9 pt ALL-CAPS H3 smaller than body; quiz answers inline (no key section) |
| PPTX render defects | 0 visuals in 708 slides while 464 notes spell out the wanted visual; 0 placeholders/layouts; no autofit (~187 overflow suspects) |
| XLSX render defects | No stored data-row heights (opens as 15 pt slivers); col K unwrapped; band fill defined but applied to zero cells; font is Inter (violates universal-font rule) |

**Target:** every capable-model run gets lean course map + adaptive enrichment
(the stack we already shipped); zero deterministic grammar artifacts in a
four-course re-run; exports open clean in Word/PowerPoint/Excel with no manual
fixing. Cost: ~$0.10–0.25 per 15-lesson course (lean map + ≤4 kernel calls)
instead of $0.09 of pure mail merge.

**Principle:** v0.12 didn't have a cost problem — it had a "paid for chrome,
skipped the content" problem. Spend the 1–4 enrichment calls; claw the tokens
back from the verbose contract and the medium reasoning tier.

Phases ordered by leverage: the one-bug-two-symptoms root cause first, then
free deterministic fixes, then per-format polish.

## P0 — Fix the degraded-plan fallback (the root cause) + make enrichment visible

When the persisted `modelCapabilities` don't match the current provider/model,
`AIConfigContext.jsx:103-110` rebuilds the plan from a **bare** profile
(`createGenerationPlan({ provider, modelId, maxOutputTokens })`). With no
`structuredOutput` metadata and no `supportsJsonMode`,
`modelCapabilities.js:859-860` resolves `structuredOutputMode: 'prompt_only'`,
so line 898-900 sets `blueprintEnrichment: false` and line 907 sets
`leanCourseMapAtoms: false`. One stale profile = no enrichment AND the
expensive verbose contract. No UI exposes any of this; the only surface is a
read-only counter in `DeveloperModeSidebar.jsx:89`.

**Changes**

1. `src/contexts/AIConfigContext.jsx:103-110`: on profile mismatch, resolve a
   **known-model baseline profile** instead of a bare one — look up the
   provider/model in the capability registry (same data `createGenerationPlan`
   consumes) so OpenAI/Anthropic/Google models keep
   `structuredOutput.defaultMode: 'json_object'`-class metadata. Only true
   unknowns (webllm, custom endpoints) may fall back to `prompt_only`.
2. `src/lib/modelCapabilities.js` (`createGenerationPlan`): add
   `planDegraded: true` to the returned plan whenever a bare profile forced
   `prompt_only` for a provider in (openai, anthropic, google). Never let a
   *missing* profile zero out enrichment for first-party providers — distrust
   of the contract should change `chunkStrategy`, not switch off the content
   stack.
3. `src/hooks/useGeneration.js:939` + `src/hooks/useDeliverables.js:633-637`:
   when `plan.planDegraded`, emit a `[CM][API]` warning event
   (`"Generation plan degraded — enrichment and lean contract disabled; check
   model capability profile"`) so this state can never be silent again.
4. **Run digest gate** (`useDeliverables.js` digest assembly): when
   `blueprintCompiledFeatureIds.length > 0` and enrichment did not run, the
   digest `gates:` line gets `[warning] content: compiled without enrichment
   (mail-merge risk)` — same severity treatment as export warnings.
5. **UI control** (`src/screens/Config.jsx`): add a three-state "Subject-matter
   enrichment" control (Auto / On / Off, default Auto = plan's adaptive),
   persisted in localStorage (`coursemapper-enrichment-mode`), threaded as
   `generationOptions.useBlueprintEnrichment`. Show the resolved state
   ("Enrichment: adaptive — ~4 calls for 15 lessons") next to the model picker.
6. Surface enrichment state in `PACKAGE_MANIFEST.json` (`packageZipExporter`):
   add `pipeline: { enrichment: 'ran'|'skipped:<reason>', genomeLinked: N }` so
   downloaded packages are auditable without console logs.

**Acceptance:** clear `coursemapper-modelname`/capabilities localStorage, pick
gpt-5.4-mini, generate a 15-lesson course → digest shows lean contract, genome
linker, and ≥1 kernel call; `blueprintEnrichmentRequested: true` in run_start;
manifest carries `pipeline.enrichment: 'ran'`. Regenerating with the toggle
Off shows the new digest warning.

**Impact:** restores the entire v0.9.1→v0.11 content stack in production; cuts
course-map output via lean atoms at the same time.

## P1 — Deterministic text fixes (compiler + exporters; zero API cost)

Every item below is a string-level bug shipped in all four courses. None
require model calls; all are provable with the existing repro harness.

**Changes**

1. **Quiz "A. A." doubling** — `src/lib/exporters/docxExporter.js:518` prepends
   `String.fromCharCode(65 + oi)` to option text that already begins with
   `"A. "`. Strip a leading `/^[A-Z][.)]\s+/` from the option string before
   prepending (and normalize at the compiler's option builder so the data is
   clean for PPTX/preview too). 232 occurrences across the corpus.
2. **ALL-CAPS short-answer keys** (57 files) — the quiz answer text is routed
   through a `toUpperCase()` kicker helper in `docxExporter.js` (the
   `makeLabel`/`makeMeta` family, lines 73-285). Only the literal "ANSWER"
   label may be caps; answer prose renders as body text.
3. **Raw enums in print** — map `multiple_choice`/`short_answer` → "Multiple
   choice"/"Short answer" at the quiz section builder; never print snake_case.
4. **FAQ double-period** — wrap `lesson.studentArtifact` (and
   `assessmentAnchorExamples.strongSample`) with `stripTerminalPunctuation()`
   in the FAQ builders at `courseBlueprintCompiler.js:15339, 15346, 15353,
   15390` — ~15 sibling call sites already do this; the FAQ builders just
   don't.
5. **"name one the Week N quiz"** — `courseBlueprintCompiler.js:15129`:
   `Can you name one ${artifact} feedback action…` → `Can you name one
   feedback action for ${artifact} before the next submission?` (56/58 decks).
6. **"its the" double article** (58×) — audit the slot templates that emit
   `its the` (`grep -rn "its \${" src/lib/courseBlueprintCompiler.js` plus the
   Micro Q3 stem builder); rewrite so the possessive and the article can't
   stack.
7. **"X: X" self-colon chains** — in the agenda/practice line builders
   ("Practice with X: For X"), suppress the suffix clause whenever it would
   begin with the same string as the prefix slot.
8. **Mid-phrase truncation** (62 slide lines, 15 DOCX) — replace hard
   `slice(0, N)` truncation with sentence/clause-boundary truncation
   (cut at the last `. `/`, `/` and ` before the cap, append nothing); never
   end with "in Instructor-provided".
9. **Objective-stem contradiction** — pick ONE owner for "Students will be
   able to:". Decision: the **cell never stores the stem** (matches what the
   repair enforces). Remove the stem demand from `prompts.js:16` and the
   `learningObjectives` column def at `prompts.js:26`; keep
   `stripObjectiveStemText` (`deliverableReadiness.js:375,454`) as a true
   repair (it should now fire ~never — assert that in the harness); fix the
   lean expander double-add at `leanCourseMap.js:80-84`; exporters/preview add
   the stem at render time. Kills the guaranteed 14-42 fake "repairs" per run
   and the wasted output tokens.
10. **"Learning  Objectives" double space** —
    `deliverableReadiness.js:656-663` `columnLabel()`: only apply the
    camelCase-splitting regex when the label has no spaces, and collapse
    `\s{2,}` → single space before returning.
11. **"Instructor-provided course materials" placeholder** (112 slides /
    48 decks) — resolve to the lesson's actual Supporting Resources entry from
    the course map; when none exists, drop the citation clause entirely rather
    than printing the placeholder.
12. **Lesson-title mail-merge cap** — compiler-side: full lesson title at most
    2× per slide's text and 2× per DOCX paragraph block; elsewhere use a short
    topic alias (first key concept or title before the first comma/colon).
    Today the title appears ~34×/deck and 4-6× in single study-guide
    paragraphs.
13. **PPTX audit log spam** — `pptxExporter.js:1534-1543` logs unconditionally
    per `createPptxWithDecks` call; the per-lesson ZIP split
    (`packageZipExporter.js:241-261`) routes single decks through it (15
    meaningless "1 decks" lines per package). Gate the log + thin-deck warning
    on `deckAudit.length > 1`, and have the ZIP loop aggregate one summary line.

**Acceptance:** harness regen of all four courses → `grep` over extracted text
finds 0 of: `[A-Z]\. [A-Z]\. `, `its the `, `name one the `, `\.\.`(non-ellipsis),
`Learning  Objectives`, `Instructor-provided course materials`; short-answer
keys are sentence case; console shows exactly one PPTX audit line per package.

**Impact:** removes every "this is obviously machine-generated" artifact for
$0; cuts course-map output tokens (stem removal) and repair noise.

## P2 — Wire content-quality findings into the repair pipeline

The export verifier's `auditDeliverableContentQuality`
(`packageExportVerifier.js:291-301`) found the FAQ double-period in 2 of 4
runs, but it runs **after** the finalizer's retry loop
(`AppFlow.jsx:1365-1391`) and feeds nothing into `buildPackageRepairQueue`
(`classroomReadiness.js:913-1001`) — so 8-14 reserved retry calls sat unused
while a known defect shipped.

**Changes**

1. Run the content-quality audit **inside** the finalizer's initial check
   (alongside `workspaceReadiness`/`classroomReadiness` in
   `packageFinalizer.js:299-307`), not only at export-verify time.
2. Add a **deterministic repair pass** before any AI retry: findings with
   mechanical fixes (double-period, double-space, doubled option letters,
   raw enums) map to pure-code normalizers applied to the deliverable data —
   0 provider calls.
3. Findings that genuinely need authorship (e.g., truncated sentences that
   can't be re-flowed) map to retry actions with feature/lesson scope so the
   existing retry budget can be spent on them.
4. Keep the export-verify audit as the final gate; it should now pass clean
   and only report regressions.

**Acceptance:** seed a `studentArtifact` ending in "." in a fixture → finalizer
fixes the FAQ double-period deterministically, digest reports
`1 content repair (deterministic)`, export verify shows 0 warnings.

**Impact:** the gate system stops being display-only; warnings self-heal.

## P3 — DOCX export overhaul

All defects below are systematic (same builder, 410 files). The chrome
(kickers, navy/blue palette, banded tables, footers) is good — keep it.

**Changes**

1. **Table width vs page size** — every one of 136 tables is fixed
   `tblW = 9360 dxa` (6.5 in, US-Letter content width) on **A4** sections
   (9026 dxa text column) → all tables overflow the right margin by ~6 mm.
   Fix in the shared table builder: `tblW` → `type: 'pct', w: 5000`. Decide
   page size deliberately (US Letter for the NYU audience, or keep A4) —
   pct-width is correct under both.
2. **styles.xml integrity** — add the missing `Normal` style and a minimal
   `theme1.xml`; move the actually-rendered formatting **into** the style
   definitions (Title: Georgia 18 pt navy; Heading2: Georgia 15 pt `1F3864`
   bold) instead of run-level overrides, so Word's navigation pane, ToC, and
   instructor restyling work. Set `dc:creator` = "CourseMapper" and `dc:title`
   per file (currently "Un-named"/empty).
3. **Heading hierarchy** — stop rendering H3 as a 9 pt ALL-CAPS kicker
   (`docxExporter.js:217-237` family) that is *smaller than body text*; H3
   becomes ≥11 pt bold small-caps. Use Heading 1 for top sections (currently
   used 0 times in 410 files; outline jumps Title→H2→H3).
4. **Kill "Label␣␣value" glued paragraphs** (the most repeated defect —
   hundreds of paragraphs) — add a shared 2-column borderless layout-table
   builder (shaded `F3F7FB` label column) and use it for: lesson-plan
   Formative Assessment/Homework blocks, study-guide Key Terms, rubric
   front-matter, discussion-prompt labels (`If Stalls`, `If Dominates`),
   FAQ "See also", assignment Format Requirements.
5. **Quiz & Exam Bank restructure** (worst-formatted type):
   per-question Heading 3; options as a real lettered Word list; **answers,
   rationale, Aligns-to and Tags move to an "Answer Key" section after a page
   break** so the question pages are student-distributable; Tags line printed
   once per document.
6. **Rubrics** — landscape section (or ≤5 columns), `cantSplit` on rows,
   `%` unit in the Weight column, 4-6 pt cell margins, top-aligned cells; cap
   level-cell text at ~150 chars at generation time (current max 284).
7. **Syllabus** — add a ToC field + page breaks before Schedule/Grading/
   Policies; merge the duplicated `Week 1 || Week 1` schedule columns; render
   instructor/course info as a 2-column table; fill or merge the empty
   grade-scale F-row cells; outcome-alignment table must cover all lessons
   (currently lessons 1-2 of 15 only).
8. **Assignment Briefs** — drop the duplicate title (cover page then identical
   kicker+Title again at P006-P007); cover subtitle shows the artifact name +
   weight + due week, not "14 sections"; tabularize Grading Criteria
   (Criterion | Weight | Strong work shows) and Scaffolding Milestones.
9. **Real Word numbering** everywhere manual numbers appear (assignment
   instructions 1-9, review questions, syllabus SLOs — fixing the `● 1.`
   double-marker bug where bullet `numId` text carries manual numbers).

**Acceptance:** open each deliverable type in Word: no table touches the
margin; navigation pane shows a full outline; restyling Heading 2 in the
gallery visibly changes the doc; quiz prints as student copy + answer key;
python-docx round-trip test asserts `Normal` exists, zero `tblW` > section
text width, zero manually-numbered bullet paragraphs.

## P4 — PPTX export overhaul

The 12-slide frame, palette, and notes scaffolding are genuinely good; the
decks fail on content density (see P0) and four mechanical issues.

**Changes**

1. **Render the suggested visuals** — 464/708 notes already begin with
   `SUGGESTED VISUAL (<kind>): …` built at `pptxExporter.js:1460`. For the
   three kinds with structured data behind them, render native objects instead
   of prose: *evidence table* (slide 6) and *decision matrix* (slide 10) as
   PPTX tables from the deliverable JSON; *concept map* (slide 5) as a simple
   hub-and-spoke shape group (title + key concepts already in the lesson
   data). Keep the note text as alt-text. Takes the corpus from 0 visuals to
   ~3/deck with zero API calls.
2. **Fit-aware text** — every frame has `auto_size=None` (~187 overflow
   suspects). Set `normAutofit` (shrink-on-overflow) on: slide 6/9 headline
   boxes (28 pt in 0.9 in), slide 4 "LAST TIME" headline (0.7 in box),
   title-slide subtitle (107-char strings in a 0.6 in box). Unify per-list
   font sizes — agenda rows currently mix 13-16 pt within one list.
3. **Variable activity timing** — `pptxExporter.js:1003` renders
   `Duration: ${s.timer}`; the compiler feeds a constant → "Duration: 10 min"
   on slide 8 of all 58 decks. Compiler emits real per-archetype timings
   (setup/work/debrief from the lesson-plan outline, which already varies).
4. **Per-course accent palette** — all four courses ship identical navy/gold.
   Add a subject→accent map (keep navy; vary gold → sage/teal/terracotta…)
   selected from `inferCourseDisciplines`; one constant table in the exporter.
5. **Placeholders/layouts** (stretch, flag-gated) — map title/body shapes to
   master placeholders so outline view, theming, autofit, and screen readers
   work; currently 0 placeholders in 708 slides. Large change to the deck
   builder — gate behind `exportOptions.nativeLayouts`, default off until
   verified in PowerPoint + Keynote + Google Slides.
6. **Kernel/bridge keying on slide 13 (Micro bug)** — "How Experts Think:
   Price elasticity of demand" carries a *marginal analysis* body and repeats
   verbatim in L03/L06/L08/L14. Key the expert-routine block by the lesson's
   own linked concept; suppress the slide when it would repeat a previous
   lesson's body verbatim.

**Acceptance:** four-course regen → ≥2 native visuals per deck; zero
text overflowing shape bounds at 100% zoom on the audited slides; activity
durations vary across lessons; each course visibly distinct in thumbnail
strip; Micro slide 13 unique per lesson and correctly titled.

## P5 — XLSX course-map render fixes

Content scored well (specific, aligned, zero placeholders); the workbook just
renders broken on open.

**Changes**

1. **Stored row heights** — data rows have none, so Excel opens every
   3-4-line wrapped cell as a 15 pt sliver. Estimate per row from
   `max(ceil(len/charWidth(col)))` across cells × line height, set explicit
   `row.height`. This is the single biggest perceived defect.
2. **Column K (Evaluate Design)** — currently the only `wrap_text=None`,
   `vertical=center` column, holding 350-char single lines. Set wrap + top to
   match B-J.
3. **Apply the orphaned band fill** — `FFF2F6FC` is defined in styles.xml and
   applied to zero cells; alternate it across each lesson's two section rows
   (B-K) to group lessons visually.
4. **Header row 120 pt → ~32 pt**, vertically centered.
5. **Width + furniture** — shrink col I (`Presentation Format`, max 39 chars)
   to ~22; widen A to ~34, D/K to ~45-50; add `AutoFilter` on A1:K1; rename
   header `Week or Module` → `Lesson` (every value is "Lesson N: …"); tab
   color.
6. **Print setup** — landscape, `fitToWidth=1`, repeat row 1 as print title.
7. **Font** — replace Inter with the universal design-system pair (Calibri
   body / Georgia accents); Inter violates the v0.12 rule that export fonts
   must be universally installed.
8. **Repair-path normalization** — enforce terminal periods on objective
   lines (Micro shipped 120/120 without them; other courses with them) and
   normalize Learning Goals numbering (Nutrition unnumbered vs others
   numbered) in the course-map repair pass; hoist the per-row accessibility/
   VPAT boilerplate (28/28 rows in Nutrition) into a single note row.

**Acceptance:** open each XLSX fresh in Excel: all text visible without
autofit; alternating lesson bands; prints on one page width in landscape;
fonts render identically on a machine without Inter.

## P6 — Genome/data follow-ups (post-P0, feeds the refine loop)

1. **In-course bridges are structurally impossible today** — bridges require
   ≥2 same-archetype concepts within one course
   (`archetypeBridges.js:77: if (distinct.length < 2) continue`), and the
   genome has at most one instance per archetype per discipline; every
   single-discipline course logs `0 bridges`. Either (a) add second instances
   per archetype to the econ shard (the pure-data recipe in the refine-loop
   memory), or (b) hydrate sibling-discipline shards and allow cross-discipline
   bridge surfacing with an "analogy from another field" framing. Pick one in
   the refine loop before investing.
2. **Non-econ shard coverage** — Nutrition/Nursing/EdPsych all linked
   0/14-15 lessons. These are flagship demo subjects; schedule foundry runs
   (OpenStax A&P, nutrition, ed-psych sources) so the linker contributes
   outside econ.
3. **Kernel mislabeling guard** — add a foundry/linker validation that a
   kernel's `instanceOf` archetype matches its body text concept (catches the
   elasticity-titled/marginal-analysis-bodied kernel from P4.6 at data level).

## Verification protocol (release gate for v0.12.1)

Re-run the same four-course test end-to-end (same syllabi, gpt-5.4-mini) and
assert, per course:

1. Digest: `provider calls` = 1 (map) + ceil(unlinkedLessons/4) kernel calls;
   lean contract; `enrichment (model): ran`; cost ≤ $0.30.
2. Artifact grep gate (P1 acceptance list) = 0 hits across all extracted text.
3. Content spot-gates: Nursing L07 quiz contains ≥3 items with actual dosage
   math/medication content; Micro L03 quiz ≥4 elasticity items; every
   course's slide 5 states a real domain proposition (no "X: a decision tool
   for the Week N quiz"); study-guide key terms are non-circular definitions.
4. Cross-course sameness re-measure (audit scripts preserved in `/tmp/audit/`,
   port into `scripts/`): Rubrics ≤ 50%, Assignments ≤ 50%, Quiz ≤ 40%
   (from 83/76/68).
5. Format opens clean: Word navigation pane populated, no margin-overflowing
   tables; Excel opens with visible rows; PowerPoint shows ≥2 native visuals
   per deck.
