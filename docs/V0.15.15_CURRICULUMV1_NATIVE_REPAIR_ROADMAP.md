# V0.15.15 - CurriculumV1 Native Repair

## Goal

The generated package can be structurally clean while still feeling less like a
better curriculum brain than it should. Two weak signals made that visible:

1. A native skeleton with one assessment for many lessons still had to fall back
   to prose.
2. Genome-linked coverage grounded lesson facts, but did not by itself prove the
   whole course plan, assessment lattice, constraints, or prerequisite sequence.

v0.15.15 moves one real runtime path toward the intended architecture:
recoverable sparse native plans repair through CurriculumV1 before any prose
fallback, and the resulting package carries proof metadata.

## Lane

This is a narrow compiler/runtime patch, not the full one-call CurriculumV1
default flip.

In scope:

1. Strengthen CourseIR v1 with constraints, prerequisite concept links, source
   ledger repair, lesson concept repair, and under-assessed course repair.
2. Repair degenerate native assembly through CurriculumV1 at the
   `resolveNativeAssembly` seam.
3. Keep unrecoverable native failures loud and honest.
4. Export slim CourseIR/native-repair proof into package manifests.
5. Add a research-methods genome shard so more courses have grounded concept
   kernels.

Out of scope:

1. No provider-routing flip to a single giant CourseIR call.
2. No claim that genome-linked coverage alone proves package quality.
3. No claim that all native repairs preserve every optional reading/resource
   nuance yet.
4. No live EduTool.dev generation claim for this release.

## Release Boundary

v0.15.15 ships only if local proof covers both the narrow seam and broad
regression surface: focused native/CourseIR/package/genome tests, full unit
suite, constitution audit, build, bundle budget, release-history audit, and the
40-sample gold audit.

Remote Fast verification and GitHub Pages deploy are claimed only after the
commit is pushed and those runs complete.

## Acceptance

The release is acceptable when:

1. CourseIR validates and repairs the new curriculum atoms before compile.
2. A one-assessment native skeleton resolves to an ok CurriculumV1-repaired graph
   instead of a native prose fallback.
3. The run budget/log trail says CurriculumV1 repaired the native graph.
4. Package manifests include CourseIR/native-repair proof metadata.
5. Research-methods genome coverage is listed in the manifest and pinned by
   tests.
6. All local verification gates named in the release contract pass.

## Why Genome-Linked Still Matters

Genome-linked is important because it is the grounding layer: cited concepts,
verified facts, misconception patterns, examples, routines, and open resources.
It reduces hallucinated subject matter and gives the compiler stable knowledge
kernels.

It is not sufficient by itself. A course also needs a coherent plan: lesson
order, prerequisite links, constraints, assessment coverage, rubrics, source
ledger, and artifact handoff. CurriculumV1 owns that course-level structure.
The right architecture is genome for grounded knowledge atoms plus CurriculumV1
for the whole-course brain.

## Carry Forward

The bigger CurriculumV1 default flip still needs:

1. Provider routing that asks for a dense CourseIR object in one call when model
   context/output limits make that safe, and shards only when required.
2. A stronger compiler that expands dense atoms into every artifact without
   reintroducing prose fallback as the normal path.
3. Preservation tests for optional readings/resources through repair.
4. Live EduTool.dev ZIP/log audits proving the repair path appears in real
   packages and improves teachability, not only structural grades.
