# V0.15.187 — Live-Proven Compiler

_Release version: 0.15.187 · July 1, 2026 · contract: `release-contracts/v0.15.187.json`_

## Goal

Execute the first seven batches of the July 1 compiler deep-audit roadmap —
route authored kernel atoms into the deliverable surfaces that measured 0%
lesson-specific content, make grounding a measured number instead of a guess,
isolate per-feature compile faults, and get the compile off the main thread's
critical path — then prove the result against live provider generations. The
live rounds became the release's own test: three consecutive blocked packages
exposed a class of assessment-identity bugs (classification split-brain,
transcription-echo identity, repair-minted exams) that only live model output
can produce, and all three were fixed at the root before the loop went green.

## Lanes

### Lane 1 — Content: atoms into 0% surfaces

- Course FAQ builders 1/2/5/7/8 quote kernel facts, task descriptions,
  misconception-versus-correction, `scenario.materials`, and term definitions,
  all `enrichmentSource`-tagged.
- Discussion follow-ups and response stems quote authored positions and the
  authored tension; rubric parameter rows are tagged; syllabus week rows gain
  key vocabulary; study-guide practice activities work scenario materials and
  anchor facts; registry exam short answers compare authored definitions when
  covered lessons carry kernels.
- Quiz correct-answer explanations quote the authored definition ONLY on an
  exact concept match (the unrelated-atom attachment was the v0.14 field-audit
  mismatch defect).

### Lane 2 — Measurement: grounded fraction + fallback counters

- `measureGroundedFraction` (enrichmentSource-ancestor byte counting, a
  documented undercount) and `contentFallbackTelemetry` (lens / modality /
  artifact-genre / discussion-protocol default counters) surface as the
  `groundingMetrics` pipeline event and `grounding_metrics` trace.
- Live measurement (final smoke round): overall ~43% — discussions 98%,
  assignments 99%, quiz bank 42%, slide decks 28%, course FAQ 23%, syllabus
  and lesson plans 0% (the next targets).

### Lane 3 — Kernel extension: the model authors, dictionaries fall back

- Kernel studyGuide block: summary (`sm`, 60–600 chars) and review strategy
  (`rs`, 30–400), meta-language linted; compileStudyGuides prefers them.
- Course-level `discussionProtocol` (format / participationPattern /
  artifactUse / reviewFocus), complete-or-dropped validation;
  `buildDiscussionProtocol` prefers the authored protocol over the 34-genre
  dictionary, which now fires a counted fallback.

### Lane 4 — Engineering: fault isolation, yield, budget

- Per-feature try/catch in `compileBlueprintDeliverables`; failures ride the
  `Symbol.for('coursemapper.blueprintCompileErrors')` channel; only the failed
  feature errors, with its real message; the gold audit emits per-feature
  compilerException blockers.
- `compileBlueprintDeliverablesYielding` yields between features on the
  browser path (the compile was a 0.8–1s synchronous main-thread block).
- The compiler entry chunk is budgeted in `checkBundleBudgets`; the dead
  `mergeBlueprintEnrichment` is deleted; twelve stateless text helpers moved
  to `compilerText.js` with identical clones unified.

### Lane 5 — The live loop: three catches, then green

Five crucible smoke rounds (cs-python, gpt-5.4-mini) during this release:

1. **Catch 1 — classification split-brain** (74/C, P0 "registered exam
   artifact contains no exam content"): courseIR defaulted exam-titled
   assessments to `graded-artifact` while the export manifest re-derived
   `exam` from the title. Fix: one classifier everywhere —
   `classifyAssessmentKind` is the fallback in courseIR normalization and
   compileQuizBank's exam filter (plus the "exam review guide" false-positive
   fix the 132-case matrix caught).
2. **Catch 2 — transcription echoes as identity** (same P0, new cause,
   diagnosed via the new failure forensics): Pass A transcribes numbered
   prose cells into titles, minting "Title: 1. Title" echoes the compiler
   deduped but the graph/manifest kept. Fix: `dedupeNumberedAssessmentEcho`
   runs where registry rows are born (map derivation, skeleton parse, courseIR
   normalize) plus a manifest belt for legacy saved graphs.
3. **Catch 3 — repairs minting exams** (same P0 family): the finish-pass
   readiness repair replaced a midterm week's assessment cell with pool text
   ("Midterm exam edge-case probe: …") AFTER compile, registering a new exam
   no compile built. Fix: `getCourseMapFallbackValue` never rewrites an
   exam-bearing cell and can never mint an exam-classified title.

- Final round: **PASSED 99/A, 0 P0, in-app/offline delta 0, $0.12, 165s,
  125-file ZIP** (round-2026-07-02T02-49-56-242Z). Earlier rounds observed
  `cachedInputTokens: 1280` on courseIR calls — the v0.15.186 cache work
  produces live hits.
- The crucible driver now dumps the autosaved project to
  `project-at-failure-<phase>.json` on any failure — catches 2 and 3 were
  undiagnosable from screenshots alone.

## Release Boundary

This release may NOT claim:

- Consistent prompt-cache hits: three rounds showed 1280 cached tokens on
  courseIR, the final green round showed 0 — cache-hit consistency across
  rounds and providers is unproven.
- Kernel-authored modality modeDetails or lesson-plan flat-mode step
  descriptions — the remaining Lane 3 items are open roadmap.
- `compactBlueprintForStorage` on the hot compile path — deferred to its own
  round (persistence-shape risk).
- Compiler decomposition beyond the `compilerText.js` pure move — the
  leaf-first per-deliverable extraction has not started.
- A fix for the raw-map facade path's title shortening (headless-only legacy;
  in-app maps derive-on-open).
