# v0.15.43 Trusted SourceRef Bridge Roadmap

_Written June 20, 2026. App version: `0.15.43`._

## Goal

Make the exported CourseIR sourceRef proof follow the trusted source ledger rows
that the research layer already recovered, instead of leaving complete-looking
atom coverage attached to a single review-only CourseIR fallback row.

## Lane

Package export source-proof bridge. This lane changes export assembly and
manifest/report proof. It does not change source retrieval, source scoring,
license normalization, provider prompts, or the grader threshold.

## Release Boundary

In scope: bridge already-complete CourseIR sourceRef coverage to trusted
concept-linked source ledger rows during ZIP assembly, disclose the bridge in
the manifest, preserve source-ledger grader behavior, and document the release
contract.

Out of scope: claiming ambiguous OpenAlex/OpenLibrary rows are license-clean,
inventing source licenses, changing retrieval adapters, changing source-finder
ranking, or proving full semantic atom-level source relevance before
compilation.

## Evidence

The `20260621T010414Z` EduTool.dev audit ran against deployed v0.15.42
(`6fdb641`). Fast verification and Pages deploy were green before the run. The
fresh Genetics and Society package exported successfully and downloaded as:

- `verification-output/edutool-audit-loop/20260621T010414Z/Genetics and Society - Course Materials (8).zip`

Local regrade reproduced the package report:

- quality: `97/100` (`A`)
- texture: `94/100`
- findings: `0 P0`, `1 P1`, `5 P2`
- export verification: passed

The P1 was source-proof wiring, not missing files:

- `sourceLedger`: `9` trusted rows
- `sourceReviewRows`: one `SL1` review-only CourseIR row
- `courseIR.sourceRefCoverage.totals`: `50/50` atoms with sourceRefs
- `courseIR.sourceRefCoverage.sourceLedgerRows`: `1`

That means the ZIP exported real source rows and full-looking atom coverage, but
the coverage proof still said those atoms were wired through one CourseIR source
row rather than through the trusted concept-linked rows.

## Fix

Package export now applies a narrow source-proof bridge after the trusted source
ledger is assembled:

1. the package must have multiple trusted source rows,
2. those rows must carry concept links,
3. CourseIR sourceRef coverage must already be complete,
4. the old coverage proof must report one CourseIR source row,
5. the old row must be review-only fallback proof.

When all five conditions hold, export replaces the review fallback proof with
the trusted ledger rows, updates `courseIR.sourceRefCoverage.sourceLedgerRows`,
and writes a `courseIR.sourceRefBridge` disclosure that records trusted rows,
concept-linked rows, and replaced review rows.

## Verification

Focused exporter coverage recreates the live v0.15.42 shape:

1. three concept-linked trusted source rows,
2. one review-only `SL1` CourseIR row,
3. complete atom sourceRef coverage,
4. `sourceLedgerRows: 1` before bridge.

The test proves the ZIP manifest exports the trusted rows, omits the replaced
review row, preserves complete sourceRef coverage, and discloses the bridge.

The source-ledger grader tests remain green, so the P1 truth gate for unbridged
packages is still armed.

## Carry Forward

This patch fixes the package proof bridge, not the whole research architecture.
The next deeper source layer should write trusted source row ids into the full
CurriculumV1/CourseIR atom graph before compilation, then compile teaching
materials from those atom refs. Ambiguous licenses must remain findings until
the retrieval adapters can prove license terms from reliable provider metadata.
