# V0.15.135 Course FAQ Feedback Texture Roadmap

## Goal

Remove the remaining CourseMapper-owned Course FAQ feedback-transfer texture
shingle without weakening the pedagogical requirement that students reuse
feedback in later course work.

## Evidence

- Fresh deployed audit:
  `verification-output/edutool-audit-loop/20260629T165140Z-v015132-fresh`
- Course: User Experience Design Studio
- App version: v0.15.132
- Local regrade: 99/100, grade A
- Texture: 95
- Follow-up v0.15.133 addressed the scored Course Map assessment-identity
  mismatch.
- Follow-up v0.15.134 addressed the repeated lesson-plan publication-review
  and workshop shingles.

The remaining deterministic texture evidence included this Course FAQ shingle:

- `evidence move into the next source-based artifact discussion or synthesis task`

That wording came from CourseMapper compiler fallback copy, not from provider
model randomness.

## Diagnosis

`buildFeedbackCycle` emitted one fixed `nextUse` sentence:

`Carry the revised ... evidence move into the next source-based artifact,
discussion, or synthesis task.`

The compiler copied that sentence into `lesson.feedbackMoment`, and
`compileCourseFaq` used `lesson.feedbackMoment` as the answer for:

`How should I use feedback from this lesson?`

With a 12-lesson course, the concept token varied but the long surrounding
shingle stayed identical enough for the strict texture metric to flag it across
Course FAQ documents.

A smaller related fallback in ready-to-teach support also preserved `next
source-based artifact` language and could reintroduce the same texture problem
in support surfaces.

## Lane

1. Vary Course FAQ feedback transfer copy
   - Keep the feedback-to-next-work bridge explicit.
   - Rotate the surrounding wording by lesson so 12 FAQs do not share the same
     long shingle.

2. Clean the related support fallback
   - Replace the fixed `next source-based artifact` support sentence with
     lesson-specific transfer variants.

3. Update tests that protected the old phrase
   - Require transfer intent: next or later artifact, discussion, synthesis, or
     source-backed task.
   - Stop requiring the exact repeated phrase.

4. Prove with a focused UX regression
   - Compile a 12-lesson User Experience Design Studio Course FAQ with six
     questions per lesson.
   - Confirm every feedback question is populated.
   - Confirm the old source-based artifact shingle is absent from FAQ text and
     texture evidence.

## Fix

V0.15.135 makes the repair at the compiler layer:

1. `buildFeedbackCycle.nextUse` now uses `lessonVariant` to rotate the
   feedback-transfer sentence by lesson.
2. Ready-to-teach support `transferTask` fallback copy now rotates the related
   next-use sentence.
3. Existing compiler assertions now protect transfer meaning instead of the old
   literal phrase.
4. `tests/v015135-course-faq-feedback-texture.test.js` reproduces the UX FAQ
   shape from the audit target and proves the repeated feedback shingle stays
   out of compiled FAQ text and texture evidence.

## Release Boundary

- This release fixes one CourseMapper-owned texture path from real ZIP/log
  evidence.
- This release does not weaken source, license, report, export, digest, or
  quality-grader standards.
- This release does not claim the next package is 100/100 until fresh deployed
  v0.15.135 ZIP/log evidence proves it.
