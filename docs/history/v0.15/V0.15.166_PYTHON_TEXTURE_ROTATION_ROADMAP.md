# V0.15.166 Python Texture Rotation Roadmap

## Evidence

- Fresh deployed v0.15.165 GPT-5.4-mini Python audit:
  `verification-output/edutool-audit-loop/20260630T212300Z-v015165-fresh/`.
- Visible app result was Quality 100 and Texture 95. The downloaded ZIP locally
  regraded at 100/A with 0 P0, 0 P1, and 0 P2 findings.
- Source truth was clean in the package:
  - `QUALITY_REPORT.md`, `PACKAGE_MANIFEST.json`, `SOURCE_REPORT.md`, visible UI,
    and local regrade agreed on a clean source-backed result.
  - Source refs were covered, trusted rows were concept-linked, and metadata-only
    review rows did not count as trusted proof.
- The remaining quality target was texture, not source truth. Static ZIP
  inspection found deterministic CourseMapper-side Python scaffolds repeating
  across assessment and evaluate-design text, including:
  - `predict output and explain the state change`
  - `runnable Python artifact or trace`
  - `same input/output evidence used in grading`

## Goal

Move Python fallback text from "one acceptable phrase repeated many times" to
"validate, vary, then export":

- Repaired weekly assessments should vary by lesson and section.
- Repaired evaluate-design support text should not repeat the same generic
  evidence phrase across the package.
- A sparse Python Course Map should still export lesson-specific, usable
  assessment prompts without relying on model luck.

## Lane

Deterministic texture repair for Computer Science/Python Course Map fallback and
repair text. This is not a grader relaxation, source-ledger change, model
upgrade, or broad UI redesign.

## Release Boundary

This release may claim deterministic CourseMapper-side reduction of repeated
Python scaffold phrases. It may not claim a new provider score for v0.15.166
until a fresh deployed GPT-5.4-mini ZIP/log audit exists.

## Product Diagnosis

The v0.15.165 package already passed the deep quality grader, but repeated
repair templates still made some exported materials feel mechanically generated:

1. The model produced enough usable Python structure to reach a clean score.
2. CourseMapper fallback/repair templates filled sparse Course Map fields.
3. Several fallback phrases were themselves too narrow and repeated across many
   sections.
4. The problem is fixable from our side because the repeated text is emitted by
   deterministic CourseMapper templates, not only by provider randomness.

## V0.15.166 Scope

- Broaden Computer Science/Python weekly-assessment repair variants.
- Broaden Python async, synchronous, supporting-resource, objective, and
  evaluate-design fallback variants where the same wording could repeat.
- Make sparse Course Map fallback rotation section-aware across the full lesson
  map.
- Keep repaired assignment titles concise when the source assessment prompt uses
  a colon followed by detailed task instructions.
- Add a regression using a 12-week, 3-section Python map with repeated
  GPT-style assessment scaffolds.
- Keep the quality bar unchanged: local regrade and provider audit must still
  report real caveats instead of hiding texture issues.
