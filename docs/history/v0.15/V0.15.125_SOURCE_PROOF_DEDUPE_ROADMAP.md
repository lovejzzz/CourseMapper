# V0.15.125 Source Proof Dedupe Roadmap

## Goal

Prevent duplicate identifiers for the same real source from inflating trusted
source coverage, while preserving distinct licensed, on-topic, concept-linked
source proof.

## Evidence

- App version: `0.15.124`
- Audit folder:
  `verification-output/edutool-audit-loop/20260629T102044Z-v015124-ux-fresh`
- Visible and local package result: `100/100 (A)`
- P findings: `0 P0`, `0 P1`, `0 P2`
- Export verification passed, enrichment coverage was complete, and the package
  reports Texture `95/100`.
- Strict source-ledger review found two trusted Crossref rows for the same
  Margret Plank prototyping work:
  - `10.65527/sfxsp-76774`
  - `10.65527/4gsph-jk398`
- Both rows were real, licensed, on-topic, and concept-linked, but they should
  count as one trusted work, not two independent proof sources.

## Diagnosis

The previous merge logic trusted DOI and URL as strong identity keys. That was
too literal for source-finder output: Crossref can surface DOI variants for the
same article, and those variants can consume multiple trusted-source slots
inside a topic before another distinct source is considered.

The model cannot reliably guarantee citation uniqueness. CourseMapper needs a
deterministic source-ledger invariant: source counts represent distinct trusted
works, not repeated identifiers for the same work.

## Lane

1. Same-work fingerprinting
   - Keep DOI and URL as strong identity keys.
   - Add conservative title/author/evidence fingerprints for duplicate work
     detection.
   - Decode common HTML entities before fingerprint comparison.

2. Source-finder topic cap correctness
   - Deduplicate trusted source-finder candidates before applying the per-topic
     trusted-source cap.
   - Let the next distinct trusted source fill the slot instead of letting a
     duplicate DOI variant crowd it out.

3. Concept-link preservation
   - When duplicate works are merged, retain the stronger row and merge concept
     links so source proof remains connected to all covered concepts.

4. Regression coverage
   - Reproduce the v0.15.124 UX duplicate-prototyping shape.
   - Prove `PACKAGE_MANIFEST.json`, `SOURCE_REPORT.md`, and CourseIR sourceRef
     bridge counts use distinct trusted works.

## Release Boundary

- This release targets source truth and source-count honesty.
- This release does not weaken source trust, license gates, UX false-friend
  quarantines, texture grading, report truth, or export verification.
- This release does not claim strict-clean provider output until a fresh
  deployed v0.15.125 ZIP/log audit proves source proof remains distinct and
  Texture reaches `100/100` or records the next concrete texture target.
