# v0.15.53 Ready Notes Workflow Roadmap

_Written June 26, 2026. Target app version: `0.15.53`._

## Goal

Fix the browser-workflow and agent-receipt gaps exposed by the v0.15.52 test
round. A package with non-blocking caveats can be downloadable and amber at the
same time. The automation should recognize that state, and the agent panel
should name real failed materials instead of hiding them behind a generic count.

## Lane

Recorded workflow truth and compact agent receipt clarity. This release does
not change quality thresholds, grader scoring, or the source/research pipeline.

## Evidence

The focused browser round on v0.15.52 produced two actionable findings:

- Playwright export checks were still expecting green `Ready to download` for
  local downloadable packages that now intentionally show `Ready with notes`.
- `npm run quality:browser:smoke` failed after finalization even though the
  export card showed `Ready with notes`, quality `99 · A`, and an enabled
  `Download ZIP` button.
- A mixed built-in/custom package could show `1 issue to fix` without naming
  the selected failed custom deliverable in the package summary.

## Release Boundary

In scope:

- Treat `Ready with notes` plus a visible `Download ZIP` action as a
  downloadable recorded-workflow state.
- Keep the caveated-package workflow assertion strict against green
  `Ready to download`, `Done`, or emerald styling.
- Pass current deliverables into the package-receipt summary so selected failed
  custom deliverables are named.
- Update E2E contracts to assert the v0.15.52 amber/collapsed-notes UI, not the
  older clean-green copy.

Out of scope:

- Claiming the latest package is 100/100.
- Weakening source-ledger, prompt-artifact, texture, or export checks.
- Hiding blockers or raw evidence from reports.
- Solving the remaining source-ledger/research bridge quality loss.

- `npm run bundle:check`
- `npm run audit:release-history`

  that script intentionally refuses dirty worktrees.

After deploy, continue fresh ZIP/log audits against the real quality loss:
source-ledger/research bridge first, then prompt-artifact leakage.
