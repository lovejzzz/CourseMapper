# v0.15.49 Trust Status Spine Roadmap

_Written June 26, 2026. Target app version: `0.15.49`._

## Goal

Make every package-status surface tell the same truth. A package with quality
findings, texture loss, export warnings, source/genome caveats, or any other
review-required condition may stay downloadable, but it must not look like a
clean green all-clear.

## Lane

Product trust and recorded-workflow automation. This release should align
header, agent, export, and automation status rules around one shared caveat
model. It should not weaken the grader, hide findings, or change package
quality thresholds to make scores look better.

## Release Boundary

In scope:

- create one shared package-caveat helper for UI trust decisions,
- use it in the workspace header quality chip, export package card, agent
  summary card, agent working-set headline, and progress header,
- make green mean clean: `100/100`, no P0/P1/P2 findings, no texture loss, no
  export warnings, and no hidden source/genome caveats,
- keep non-blocking caveated packages downloadable while rendering amber review
  state,
- broaden recorded browser workflow assertions beyond the right export card so
  header and agent surfaces cannot remain green while the package is caveated,
- keep the existing assertions for:
  - no Course Map ready tick while the build ribbon is unfinished,
  - caveated package card is amber `Review before download`, not green ready.

Out of scope:

- changing source-ledger/research retrieval,
- changing provider prompting or spending a fresh generation before a deployed
  code change needs validation,
- weakening deep-quality scoring,
- claiming the existing v0.15.47 Project Management artifact is fixed by UI
  work,
- fixing Lesson 10 study-guide kernel coverage or the PPTX repeated-phrase
  export warning in this trust-surface slice.

package but not a clean one:

- local package score: `97/100 (A)`,
- texture: `93/100`,
- findings: `0 P0`, `2 P1`, `0 P2`,
- export verification: `38` checks, `0` failures, `1` warning,
- final digest: ready with export warnings,
- source ledger rows: `1`,
- genome linker: `0/12` genome-linked lessons.

The product-specific browser checks improved in v0.15.45 and v0.15.46:

- Course Map did not show a ready tick while the build was unfinished,
- the right package card rendered amber `Review before download` for the

The remaining trust gap is cross-surface:

- the header still rendered a green `Quality 97 · Texture 93` chip,
- the agent/export conversation surface still included `Ready to download` and
  `Done`,
- the right export card correctly said `Review before download`.

That means the product has one truthful status surface and several softer
surfaces that can still imply "clean ready."

## First Product Change

Change the status model before changing layout polish.

The current implementation has multiple independent readiness rules:

- `WorkspaceQualityChip` treats A/B grades with zero P0 findings as healthy,
  so P1/P2 findings, score loss, texture loss, and export warnings can still
  render green.
- `ExportSidePanel` already has the better caveat rule and switches the package
  card to amber when package review issues exist.
- `PackageSummaryCard`, `ProgressHeader`, and `AgentWorkingSetPanel` still use
  broad `ready` or `everythingDone` language that can conflict with the export
  card.

v0.15.49 should collapse these into one shared decision:

- `clean`: green, ready/download wording, no caveat language,
- `review`: amber, downloadable when non-blocking, `Review before download` or
  `Review before export`,
- `blocked`: red, no download until fixed or acknowledged,
- `running`: slate/pulse progress state,
- `not-graded`: slate with reason.

## Implementation Plan

1. Add a package trust helper.
   - Inputs: quality result, package receipt/export verification, digest gates,
     source/genome caveats where available, readiness blockers/warnings.
   - Output: `{ state, tone, title, reason, issueSummary, canDownload }`.

2. Replace duplicated UI rules.
   - `WorkspaceQualityChip` should use amber when the shared helper returns
     `review`.
   - `QualityStamp` should match the containing package card tone instead of
     independently returning green for A/B zero-P0 grades.
   - Agent cards and progress headers should not say `Ready to download` when
     the shared helper returns `review`.

3. Preserve download availability.
   - Non-blocking caveats should not disable ZIP download.
   - The call to action can remain `Download ZIP`, but nearby status must be
     amber and explicit.

4. Tighten browser automation.
   - Keep the existing export-card assertion.
   - Add assertions that a caveated package does not show green header chip
     classes and does not show clean `Ready to download` / `Done` in agent
     summary surfaces.
   - Save a compact DOM evidence JSON for each checked surface so future audits
     show exactly which surface passed or failed.

5. Update tests that currently encode the softer rule.
   - `WorkspaceQualityChip` tests should expect amber for any P1/P2 finding,
     any score below 100, or texture below 100.
   - Export panel tests should keep the existing `Review before download`
     behavior.
   - Agent-summary tests should distinguish clean-ready from review-ready.
