# v0.15.47 Source Ledger Recovery Roadmap

_Written June 25, 2026. App version: `0.15.47`._

## Goal

Recover trusted, concept-linked source ledger rows from real package evidence
when the export graph is sparse but the generated syllabus still carries
source-bearing weekly readings.

## Lane

Export truth, compiler cleanup, and recorded browser workflow hardening.

## Release Boundary

In scope:

- promote only concrete URL/DOI weekly-reading entries from structured syllabus
  data into source-ledger recovery proof,
- attach recovered rows to the matching lesson concepts before CourseIR
  sourceRef bridging,
- keep CourseIR review fallback rows out of trusted bibliography proof,
- block Course FAQ source-review placeholders such as "Existing course map
  fields" from student-facing answers and related concepts,
- add recorded-workflow assertions for unfinished Course Map ticks and caveated
  package review state.

Out of scope:

- changing provider retrieval ranking,
- claiming the existing v0.15.44 ZIP now regrades differently,
- hiding off-discipline OpenAlex rows,
- weakening source-ledger grading standards.

## Evidence

The Project Management audit saved under
`verification-output/edutool-audit-loop/20260625T144230Z/` regraded the
downloaded package at `96/100` with these source-related facts:

- digest: `19 open resources (openalex: 11, source-finder: 8)`,
- manifest: zero trusted `sourceLedger` rows,
- CourseIR fallback: one review-only row, "Existing course map fields",
- local grader: P1 sourceRef coverage relied on zero trusted source rows.

The same package's syllabus contained concrete OpenAlex source strings in
weekly readings and the Sources & Licenses appendix. The export path was losing
that proof before `PACKAGE_MANIFEST.json` and `SOURCE_REPORT.md`.

## Fix

Package export now builds an additional conservative source-ledger recovery
bundle from `syllabus.weeklySchedule[].readings`:

1. split weekly reading strings on semicolon boundaries,
2. keep only entries with URL/DOI/provider/license source signals,
3. drop placeholders such as "Existing course map fields",
4. attach each recovered source row to the matching lesson's first section,
5. let the existing source-ledger normalizer infer provider, URL/DOI, license,
   and concept links,
6. bridge complete CourseIR sourceRef coverage only when more than one trusted
   concept-linked row exists.

Course FAQ generation now treats CourseIR/source-review placeholders as unsafe
evidence cues and removes internal "rubric criteria" / "anchor examples" labels
from the related-concept list rendered in Course FAQ exports.

The recorded browser-quality loop now fails if:

- the Course Map tab shows a ready tick while the build ribbon is still active,
- a caveated package card shows green "Ready to download" instead of amber
  "Review before download".

## Verification

Focused verification covers:

- exporter recovery and CourseIR bridge regression,
- finalizer/Course FAQ placeholder regression,
- recorded workflow assertion helpers,
- existing tab truth and package review UI regressions.

The release gate uses targeted tests plus the normal release-history, build,
bundle, lint, and smoke-quality checks. A fresh EduTool.dev provider generation
should resume after this release deploys.
