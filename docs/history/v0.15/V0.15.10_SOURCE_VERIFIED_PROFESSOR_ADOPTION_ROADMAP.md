# V0.15.10 - Source-Verified Professor Adoption Judge

## Why this exists

The 30-case professor-adoption gate is useful, but a large manifest can still
become self-referential if the project never proves that the manifest itself is
grounded in public course sources. v0.15.10 makes source provenance executable:
the engine checks public source pages, reports unsupported claims, and tells
the next repair action without a human interpreting the ledger.

## Definition of done

1. `npm run audit:professor-adoption:sources:smoke` verifies the smoke source
   cases and writes Markdown, JSON, JSONL, and autonomous-action reports.
2. `npm run audit:professor-adoption:sources` verifies the full 30-case source
   pack.
3. MIT OCW cases use the official course `data.json` metadata as the source of
   truth for course title, instructors, resource types, description, topics,
   term, and year.
4. Non-MIT public pages are checked from their source-page text.
5. Source failures become autonomous findings with:
   - severity,
   - source expectation,
   - observed output,
   - failure class,
   - suspected owner file,
   - repair action,
   - acceptance criteria,
   - proof command.
6. The normal professor-adoption report includes a coverage dashboard with
   discipline-family counts, source-host counts, cluster counts, thin coverage,
   and next expansion focus.
7. Release and report wording says "public-source benchmarked" or
   "source-provenance verified"; it never says professor-approved,
   instructor-endorsed, or external validation complete.

## What this fixes

| Weakness                                                        | Fix                                           | Proof                                                   |
| --------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------- |
| Manifest claims could drift from official source pages          | Add live source-provenance verifier           | `npm run audit:professor-adoption:sources`              |
| MIT OCW source pages have structured metadata we were not using | Verify MIT cases against `data.json`          | source audit checked URL ends in `/data.json`           |
| Adding more professors could hide discipline imbalance          | Add coverage dashboard to the adoption report | `verification-output/professor-adoption/latest.md`      |
| Source findings could still need agent interpretation           | Emit JSONL and autonomous actions             | `latest-ledger.jsonl`, `latest-autonomous-actions.json` |
| Source access failures could be confused with quality failures  | Mark them as `blocked-source-access`          | source audit decision block                             |


## Expansion rule

Do not expand from 30 to 60 cases until:

1. the full source-provenance audit passes,
2. the full professor-adoption audit passes,
3. the 100-round mutation loop passes,
4. the coverage dashboard names the weakest remaining discipline/source areas.

The next 30 cases should become a rotating or nightly pool, not an always-on
local gate, unless runtime stays low enough for normal development.

## Claim boundary

Allowed:

> CourseMapper benchmarks generated packages against public professor-taught
> course artifacts and verifies that benchmark manifests are grounded in public
> source pages.

Forbidden:

1. "professors approved CourseMapper",
2. "the course authors endorsed the output",
3. "external validation complete",
4. "university-ready without instructor review",
5. "all disciplines are solved."
