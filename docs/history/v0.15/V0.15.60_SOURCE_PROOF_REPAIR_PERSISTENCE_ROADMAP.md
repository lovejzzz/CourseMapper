# v0.15.60 Source Proof Repair Persistence Roadmap

_Written June 26, 2026. Target app version: `0.15.60`._

## Evidence

The fresh deployed v0.15.59 Project Management ZIP/log audit regraded at
98/100 (A), but it still exposed a concrete source-bridge failure:

- The run digest reported `3 open resources (source-finder: 3)`.
- The exported `SOURCE_REPORT.md` and `PACKAGE_MANIFEST.json` only contained
  `syllabus` and `openlibrary` source rows.
- Two exported rows carried ambiguous licenses, costing citation quality.
- The package had 3 safe repairs, so post-generation map repair was a likely
  place where retrieved source-finder/OpenAlex proof was dropped.

## Goal

Keep source-finder/OpenAlex proof attached when the app re-derives a graph
after safe course-map repairs. If generation found source-backed resources,
safe repair and export should not degrade those resources into weaker
syllabus-derived rows.

## Lane

Research/source bridge. This release is a narrow persistence fix for source
proof across graph re-derivation. It does not claim the next fresh package will
reach 100/100 until ZIP/log evidence proves it.

## Changes

1. Add a source-proof preservation helper that carries source-backed resources,
   source-finder mini-shards, and reading-list decisions across graph
   re-derivation without changing non-native entity-id behavior.
2. Use that helper when AppFlow re-derives a prose/fallback graph after visible
   course-map repairs.
3. Pin the failure shape with a focused regression where a later repair removes
   rendered source text but the source-finder/OpenAlex row remains linked to
   the lesson.
4. Re-run package-export, source-ledger, source-ledger grader, and Study Guide
   artifact-firewall coverage to ensure the fix does not weaken existing
   quality gates.

## Release Boundary

In scope:

- Preserve already-retrieved source-backed rows and source-finder mini-shards.
- Keep source-finder/OpenAlex rows available for package source-ledger assembly
  after safe repairs.
- Avoid broad native-authoring, texture, or grader changes.

Out of scope:

- Inventing license proof for metadata-only rows.
- Hiding native-authoring fallback caveats.
- Claiming texture 100/100 or a clean 100/100 package without fresh deployed
  ZIP/log evidence.
