## Goal

Prevent kernel-marked slide decks from reaching export with too little
instructional body. If CourseMapper has enough lesson data to mark a deck as
enriched/depth-bearing, the deck must also include at least five concrete
teaching slides tied to the lesson title and key concepts.

## Lane

Slide-deck compiler and export texture. This is not a grader weakening, score
inflation, model upgrade, source-ledger relaxation, or UI-only change.

## Release Boundary

This release may claim a deterministic CourseMapper-side repair for sparse
kernel/depth slide decks. It may not claim a clean v0.15.170 package until a
fresh deployed GPT-5.4-mini ZIP/log audit proves the package exports or blocks
honestly and no slide-deck content-floor P1 remains.

## V0.15.170 Scope

- Detect decks that claim kernel/depth support through enriched slide content,
  worked examples, common pitfalls, or MC walkthroughs.
- Count only teaching-body slides (`keyTerm`, `content`, `example`) against a
  strict lesson-title/key-concept vocabulary so scaffold slides do not satisfy
  the floor.
- Add deterministic lesson-specific content slides when a kernel-marked deck is
  below five content-bearing teaching slides.
- Preserve those deterministic slides through the same export passthrough path
  as existing kernel worked-example and common-pitfalls slides.
- Add a regression based on the Python sparse-walkthrough shape.

## Why This Is CourseMapper-side

A stronger model may produce richer slide decks, but CourseMapper already knows
the lesson title, key concepts, objectives, artifacts, and source cues. When the
model returns a sparse kernel, the compiler should deterministically fill the
known teaching gap before export instead of presenting a deck whose title count
looks complete but whose instructional body is thin.
