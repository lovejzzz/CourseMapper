## Goal

Stop blocking legitimate computing courses for notebook lab assets while still
blocking stale data-science/model-card language in non-ML/non-governance
packages.

## Lane

Readiness semantic gate precision. This is not a model upgrade, score inflation,
source-ledger weakening, export bypass, or UI redesign.

## Release Boundary

This release may claim that notebook/starter-notebook assets are allowed for
explicit computing courses such as Python, programming, debugging, modules and
libraries, scripts, terminals, and code-review workflows. It may also claim that
unsupported model-card language remains blocked outside machine-learning,
data-science, and model-governance contexts.

It may not claim a clean v0.15.174 ZIP score until a fresh deployed GPT-5.4-mini
ZIP/log audit proves the package exports and local regrade agrees across ZIP,
manifest, reports, digest, and UI.

## V0.15.174 Scope

- Add a computing-course classifier for notebook-readiness decisions.
- Allow hard notebook/starter-notebook references when the course map is
  explicitly computer-science, Python, programming, debugging, modules/library,
  script, terminal, or code-review oriented.
- Keep model-card references blocked unless the course is data-science,
  machine-learning, or model-governance.
- Add regressions using the v0.15.173 Python blocker shape and a guard case for
  non-ML computer-science model-card leakage.

## Why This Is CourseMapper-side

The provider did not make a bad package by mentioning notebooks. CourseMapper's
readiness validator treated all notebook language outside data science as
wrong-discipline leakage. That heuristic was too narrow for programming
courses, so the app blocked a legitimate Python package before ZIP export.
