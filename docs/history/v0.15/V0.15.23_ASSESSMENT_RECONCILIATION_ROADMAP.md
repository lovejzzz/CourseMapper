# V0.15.23 - Assessment Reconciliation

## Goal

The 2026-06-20 UTC EduTool.dev audit generated a fresh deployed
Introduction to Psychology package from v0.15.22. The package was complete,
export-verified, genome-linked, and locally regraded 99/A, but the only finding
was not a missing formal deliverable:

`8 course-map assessments are only covered as in-class lesson-plan activities, not dedicated artifacts`

The Course Map rows had one formal 25% assessment per lesson plus two formative
classroom checks per lesson, such as quick evidence checks, exit tickets, and
practice responses. Those formative checks belong in lesson plans; they should
not require their own assignment, quiz, or rubric files.

v0.15.23 fixes that false caveat without lowering the standard for real missing
artifacts.

## Lane

This is a narrow artifact-audit repair slice. It touches assessment-kind
classification, package finalizer reconciliation, focused regression coverage,
and release metadata. It does not change provider-call routing, CourseIR
authoring, export file formats, genome shards, or the quality constitution.

## Fix

The assessment registry now separates formal artifacts from classroom checks:

1. Quick evidence checks, exit tickets, and practice responses classify as
   `in-class`.
2. Explicit percentage-weighted evidence checks, such as
   `Lesson 1 evidence check: Learning (25%)`, remain `graded-artifact`.
3. Reconciliation skips true `in-class` registry entries because they are
   satisfied by lesson plans and carry zero grade weight.
4. Missing exams, finals, portfolios, and other high-stakes promises still
   become warnings.
5. Low-stakes unknown assessment promises still produce the digest info line.

## Why This Matters

The old behavior forced a bad choice:

1. Leave a good full package at 99/100 because classroom activity rows looked
   like missing exported artifacts.
2. Generate unnecessary assignment/quiz files for every formative check.
3. Weaken the grader.

The right design is the fourth option: keep the grader strict, but make the
registry precise about what kind of assessment each Course Map row represents.

This moves the project closer to honest 100/100 packages. A package should
only lose points when a real promise is missing, not when a lesson-plan activity
correctly stays in the lesson plan.

## Release Boundary

The first post-deploy automation run should generate a new package on
`0.15.23` and confirm whether the same Psychology prompt now reaches 100/100.
This release does not claim that live post-fix provider rerun until Pages has
deployed and the automation captures new ZIP/log evidence.

## Acceptance

This slice is acceptable when:

1. Formative evidence checks classify as `in-class`.
2. Percentage-weighted evidence checks classify as `graded-artifact`.
3. Reconciliation does not emit a missing-artifact caveat for in-class checks.
4. Formal missing artifacts still warn or score exactly as before.
5. Focused reconciliation and registry tests pass.
6. Normal release gates pass before push.
