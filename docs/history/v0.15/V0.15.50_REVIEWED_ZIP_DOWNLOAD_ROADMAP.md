# v0.15.50 Reviewed ZIP Download Roadmap

_Written June 26, 2026. Target app version: `0.15.50`._

## Goal

Fix the deployed v0.15.49 package-download loop without weakening quality
truth. When a package has already finished and produced a terminal quality
receipt, the visible `Download ZIP` action must save the audited package instead
of rerunning finish/export verification forever.

## Lane

Export truth and package handoff reliability. This release fixes the UI state
machine between finalization and ZIP download; it does not change grading,
content generation, retrieval, or the standard for clean readiness.

## Evidence

The Project Management browser run on v0.15.49 reached a terminal package
receipt:

- app version: `0.15.49`,
- run id: `run-1782479172102`,
- quality: `74/100 (C)`,
- findings: `1 P0`, `1 P1`, `0 P2`,
- texture: `92`,
- export verification: `38` checked, `0` failed, `1` warning,
- final status: `blocked`.

The saved console log at `/Users/tianxing/Downloads/edutool.dev-1782480197137.log`
showed repeated `[CM][FINISH]` cycles with `source:"export"` after download
click attempts. It did not show a `saveAs` or ZIP-builder exception. The
button was reachable, but the export panel chose `onFinishPackage` again before
entering `downloadCourseMaterialsZip`.

## Release Boundary

In scope:

- Treat a terminal package-quality receipt as a valid handoff to ZIP download,
  including a `blocked` receipt when it carries quality/report evidence.
- Keep structural readiness blockers on the finish/review path.
- Keep P0/P1/P2 findings, export warnings, and caveats visible in the trust
  surface and bundled `QUALITY_REPORT.md`.
- Pin the failure with an `ExportSidePanel` regression.

Out of scope:

- Changing quality thresholds or the deep-quality grader.
- Hiding blocked/caveated package state.
- Fixing the actual content quality defects from the 74/C Project Management
  artifact.
- Spending another provider generation before this download fix deploys.

## Implementation

1. Add a small `hasFinishedPackageReceipt` gate in `ExportSidePanel`.
2. Skip the pre-download `onFinishPackage` call when the all-package scope has
   no structural readiness blockers and the package already has a terminal
   receipt.
3. Still run finish when a readiness-confirm retry is explicitly requested,
   when no package receipt exists, or when structural blockers remain.
4. Add a component regression where a `blocked` package with a graded 74/C
   quality receipt clicks `Download ZIP`, does not call `onFinishPackage`, and
   does call `downloadCourseMaterialsZip`.
