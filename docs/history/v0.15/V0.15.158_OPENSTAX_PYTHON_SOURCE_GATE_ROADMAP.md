# V0.15.158 OpenStax Python Source Gate Roadmap

## Evidence

Current local regrade of existing GPT-5.5-pro Introduction to Computer Science
with Python ZIPs under
`verification-output/edutool-audit-loop/20260630T141808Z-v015157-existing-python-zips/`
showed a source-gate false positive:

- `zip2` contains `kr1`, a linked and licensed OpenStax Introduction to Python
  Programming row from the genome provider.
- The row has `https://openstax.org/books/introduction-python-programming`,
  `CC BY 4.0`, and concept links for dictionaries and file input.
- The stricter local grader still flagged it as off-discipline for
  Computer Science/Python because dictionaries and file input are ambiguous
  concept labels unless a source carries topic-specific anchor wording.

That finding is not a model-quality issue. It is CourseMapper-side source-truth
logic: canonical OER rows should stay trusted while weak source-finder bycatch
remains quarantined.

## Scope

V0.15.158 keeps the change narrow:

1. Recognize canonical OpenStax Introduction to Python Programming rows from
   `openstax`, `genome`, and `genome-prerequisite` providers as
   discipline-appropriate Computer Science/Python OER proof.
2. Apply the same rule in production source-ledger filtering and the local deep
   quality grader.
3. Preserve strict false-friend failures for source-finder/Wikipedia/Crossref
   rows such as Environment variable, Function (mathematics), File Explorer,
   String theory, and No Strings Attached.
4. Add regressions using the exact `kr1` false-positive shape from the
   regraded Python ZIP.

## Goal

Make legitimate linked, licensed, concept-linked OpenStax Python source rows
survive both export and local regrade without weakening source relevance gates
for noncanonical bycatch.

## Lane

Source-truth and grader parity. This is not a provider-prompt change, texture
cleanup, source-score inflation, or new provider-score claim.

## Release Boundary

This release may claim canonical OpenStax Introduction to Python Programming
rows are no longer marked weak solely because they link to ambiguous CS concepts.
It may not claim GPT-5.5-pro, GPT-5.4-mini, or any deployed package now reaches
100/100 until a fresh funded v0.15.158 ZIP/log audit proves it.

## Verification Target

Ship only after focused source-ledger/source-grader regressions, release-history
audit, and normal local gates pass. The next evidence step is a same-version
model comparison run once browser/provider capture is available.
