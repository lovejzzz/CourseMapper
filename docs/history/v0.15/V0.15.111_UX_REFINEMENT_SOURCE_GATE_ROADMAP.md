# V0.15.111 UX Refinement Source Gate Roadmap

## Goal

Stop UX false-friend sources from passing trusted source-ledger proof merely
because they contain the word `refinement` or `critique`.

The fresh deployed v0.15.110 User Experience Design Studio audit showed why the
target is still not clean. The UI and exported quality report said `100/100`,
but `SOURCE_REPORT.md` trusted two linked, licensed, real Crossref rows that
were not UX sources:

- `Relating Data Refinement and Failures-Divergences Refinement`
- `Vehicle refinement: purpose and targets`

This is CourseMapper-side retrieval, ledger, and grader work. A stronger model
may suggest better candidates, but it cannot reliably guarantee that every
source row is discipline-appropriate after retrieval.

## Failure

The source pipeline treated bare `refinement` as UX-relevant. That let two
real but wrong Crossref records become trusted, concept-linked source rows:

- Formal-methods/data-refinement research linked to UX refinement concepts.
- Automotive vehicle-refinement material linked to UX refinement concepts.

Both rows were source-like, URL/DOI-backed, and licensed, but they were not
discipline-appropriate. That is exactly the class of false-clean result this
release targets.

## Lane

1. Tighten UX source anchors.
   - Do not accept bare `refinement` or bare `critique` for UX proof.
   - Require contextual terms such as design, prototype, studio, interface,
     interaction, portfolio, UX, or user experience around refinement/critique.
   - Keep legitimate UX sources such as iterative design and prototyping
     eligible.

2. Quarantine known false friends.
   - Reject data refinement and failures-divergences refinement.
   - Reject vehicle refinement and automotive engineering sources.
   - Reject unrelated critique metadata such as Marxism/critique-and-struggle
     results.

3. Keep retrieval, ledger, and grader in agreement.
   - Source finder should filter bad candidates before cache.
   - Source ledger export should not promote bad candidates to trusted rows.
   - The deep quality grader should flag exported bad rows as P1 citation debt.

## Release Boundary

- This release changes UX source relevance filtering and source-ledger grading.
- This release does not weaken citation standards, sourceRef coverage, texture
  scoring, export verification, or readiness truth.
- This release does not claim strict-clean provider output. A fresh deployed
  v0.15.111 ZIP/log audit must prove the bad source rows stay out of real
  provider output.
- Texture remains a carry-forward strict-clean target until repeated compiler
  shingles reach the full target.
