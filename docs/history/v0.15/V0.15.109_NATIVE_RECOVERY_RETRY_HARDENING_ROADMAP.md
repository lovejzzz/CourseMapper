# V0.15.109 Native Recovery Retry Hardening Roadmap

## Goal

Close the partial-enrichment reliability gap from the fresh deployed v0.15.108
User Experience Design Studio audit. That run proved the v0.15.108 PPTX visual
notes cleanup in real output, but the package still stayed below strict clean
because lesson 1 fell back to template after a native Pass B recovery retry.

This is CourseMapper-side recovery reliability. A stronger model might avoid a
short retry response, but the app should make the repair prompt explicit and
spend the already-reserved second recovery call before accepting partial
enrichment.

## Remaining Failure

The package was still not strict-clean. Native Pass B enriched `11/12` lessons and left lesson 1 on template fallback after one repair retry. The current-run log showed the retry response was only `548` characters, then the run digest correctly blocked clean export:

```text
partial enrichment (11/12) - lesson 1 fell back to template after 1 repair/retry call
```

This is CourseMapper-side reliability work. A better model might answer the retry better, but the product should make the recovery prompt explicit and spend the already-reserved second repair call when the first retry makes no progress.

## Fix

- Add recovery-only Native Pass B prompt instructions that require strict JSON for the missing lesson ids.
- Explicitly demand complete kernel atoms: facts, keyTerms, scenario, discussion prompt, assignment core, slide content, and MC items.
- Explicitly demand native authoring fields: goal, outcomes, async activities, and sync activities.
- Allow Native Pass B recovery to use the second reserved recovery call after a no-progress retry.

## Lane

1. Harden the recovery prompt.
   - Name the exact missing lesson ids.
   - Require complete kernel atoms instead of allowing a short acknowledgement.
   - Require native authoring fields so Course Map cells stay aligned with the recovered kernel.

2. Use the reserved second recovery call.
   - Keep the two-call cap.
   - Do not stop after the first no-progress recovery response when call budget remains.
   - Keep the digest truthful if recovery still fails.

3. Preserve the strict quality bar.
   - Do not weaken partial-enrichment scoring.
   - Do not hide readiness blockers.
   - Require a fresh deployed v0.15.109 ZIP/log audit before claiming 100/100.

## Release Boundary

- This release changes only native Pass B recovery prompting and retry-loop behavior.
- This release does not change source-ledger trust rules, source relevance gates, texture scoring, readiness scoring, or ZIP report truth.
- This release does not claim strict-clean provider output. A fresh deployed v0.15.109 ZIP/log audit must prove full enrichment coverage and no readiness blocker.
