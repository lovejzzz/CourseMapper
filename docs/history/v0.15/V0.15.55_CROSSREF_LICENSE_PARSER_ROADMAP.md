# v0.15.55 Crossref License Parser Roadmap

_Written June 26, 2026. Target app version: `0.15.55`._

## Goal

Remove the remaining source-ledger parser loss exposed by the post-push
v0.15.54 browser package. The package improved to 99/A with one P2 finding:
a syllabus-derived Crossref row contained a specific publisher rights URL, but
CourseMapper exported it as `license=missing`.

## Lane

Source-ledger parser fidelity. This release recognizes concrete rights/license
URLs already present in rendered source text. It does not treat generic
`open access` as a sufficient license, invent missing rights metadata, or
weaken source-ledger grading.

## Evidence

The v0.15.54 live browser smoke passed and produced:

- `verification-output/cron-browser/2026-06-26T16-01-24-567Z/report.md`
- `verification-output/cron-browser/2026-06-26T16-01-24-567Z/01-startup-finance-and-venture-strategy/startup-finance-and-venture-strategy-package.zip`

`QUALITY_REPORT.md` showed 99/A with one P2:

- `source ledger row syllabus-src-1-1 has ambiguous or missing license`

`SOURCE_REPORT.md` showed the row had a Crossref DOI plus a concrete Elsevier
TDM license URL in the citation text, but the exported ledger lost that URL and
also truncated the DOI URL at the DOI's parenthesized suffix.

## Release Boundary

In scope:

- Recover publisher rights/license URLs from rendered citation text when no
  Creative Commons or public-domain label is present.
- Prefer a normalized DOI URL when the text URL extractor truncates DOI URLs
  containing parentheses.
- Pin the exact Crossref/Elsevier live output shape with focused source-ledger
  tests.

Out of scope:

- Marking generic `open access` as clean license proof.
- Claiming provider rows are clean when no rights URL or explicit license is
  present.
- Changing the quality grader's ambiguous-license policy.
