# v0.15.77 Run Digest Retry Truth Roadmap

## Evidence

The v0.15.75 Project Management ZIP/log audit regraded at 97/100 (A), but the
run digest created a misleading summary line:

- DevTools logs showed two native enrichment recovery calls:
  `Author lesson batch (native recovery 1/2)` and
  `Author lesson batch (native recovery 2/2)`.
- The same digest gate line still said `0 retry calls`.
- The package remained partial at 11/12 enriched lessons, with lesson 1 on
  template fallback after those repair attempts.

That is a CourseMapper report-truth defect. The quality loss itself remains
real, but the digest must not make the automation or reviewer think no recovery
was attempted.

## Lane

Report and audit truth. Fix the diagnostic surface before spending another
provider run or chasing the wrong product slice.

## Scope

- Count repair-stage retry calls from the API budget in the digest gate summary.
- Preserve finish-stage retry counts as a separate field for later audit tools.
- Add the repair/retry count to partial-enrichment flagged-check text when a
  fallback remains after recovery.
- Keep the partial-enrichment gate failed; do not weaken the grader or hide the
  blocker.

## Non-Goals

- Do not claim partial enrichment is fixed.
- Do not claim v0.15.77 is a clean 100/100 package without a fresh deployed
  ZIP/log audit.
- Do not alter source-ledger scoring, export verification, or provider retry
  budgets.
- Do not spend another EduTool.dev generation just to prove this text-only
  digest fix before deployment.

## Release Boundary

In scope:

- Run-digest retry-count truth.
- Partial-enrichment caveat text that names repair/retry attempts.
- Release metadata for the narrow report-truth patch.

Out of scope:

- New provider generation before deploy.
- Full enrichment recovery architecture.
- Source relevance changes beyond the v0.15.76 Project Management source gate.
- Export-panel UI redesign.
