# V0.15.13 - Native Fallback Audit Truth

## Goal

The 2026-06-19 EduTool audit loop recovered a deployed Introduction to
Microeconomics package and its Chrome DevTools digest. The visible package was
mostly healthy: 8/8 materials, exports verified, 99/A in the app, and one
assessment-coverage observation in the report.

The same digest contained a stronger caveat:
`nativeAuthoring: fell back to prose: degenerate-skeleton (1 assessment for 8 lessons)`.
That fallback did not appear in `PACKAGE_MANIFEST.json` and did not become a
quality-report finding. The package therefore looked cleaner than the run that
created it.

## Lane

This is an audit/report truth patch, not a generation architecture change.

In scope:

1. Read `pipeline.nativeAuthoring` from the run digest and the in-app honesty
   object.
2. Score prose fallback as a P2 honesty finding so a ready ZIP cannot hide the
   caveat behind an A badge.
3. Use different finding text when the manifest discloses the fallback versus
   when the fallback only exists in the digest.
4. Bump the grader version stamped into package manifests.
5. Add a regression that builds a package with a digest-only native fallback,
   verifies `QUALITY_REPORT.md`, and regrades the ZIP path.

Out of scope:

1. No CourseIR default flip.
2. No provider-call routing or batching change.
3. No claim that a native-authoring fallback makes the package unusable.
4. No claim that the live Microeconomics package is perfect; this release only
   makes the existing caveat visible and scored.

## Release Boundary

v0.15.13 ships only after local release gates pass and the pushed commit clears
Fast verification plus GitHub Pages deploy. It does not claim a post-fix
deployed live-provider rerun before Pages deploy.

## Acceptance

The release is acceptable when:

1. A digest-only `pipeline.nativeAuthoring` prose fallback creates a P2 honesty
   finding.
2. The finding says the fallback is missing from `PACKAGE_MANIFEST.json` when
   the manifest omits it.
3. `QUALITY_REPORT.md` includes the fallback evidence string from the digest.
4. Regrading the downloaded-ZIP path reproduces the fallback finding.
5. Release metadata, changelog, roadmap, app version, package version, and
   grader version all agree on v0.15.13.
6. Local tests, lint, build, bundle check, release-history audit, gold audit,
   and the changelog browser check pass before push.

## Carry Forward

CourseIR remains the right long-term architecture for reducing provider calls
and improving whole-course coherence. A dense canonical course IR should let the
model author the course brain once, then let the compiler render artifacts
deterministically. v0.15.13 does not move that default; it makes the current
package report honest enough to judge the existing path while CourseIR waits
for deployed side-by-side proof.

Gold proof should move with that architecture. Routine release loops should not
need the full 40-case broad corpus for every narrow grader or report patch. The
next proof design should use a small, fixed set of high-signal CourseIR and
digest fixtures for fast compiler/audit invariants, keep the larger gold corpus
for scheduled broad regression, and reserve live EduTool.dev generations for
discovering fresh defects rather than re-proving every commit.

The target is a constitutional gold standard, not a pile of examples. The
standard should be a compact contract for what a teacher-ready package must
always satisfy: coherent course identity, complete artifact structure,
assessment coverage, source/caveat honesty, discipline fit, export validity,
and clear handoff language. A small number of canonical fixtures should probe
distinct structural risks against that constitution; additional cases only
belong when they cover an obligation the existing fixtures cannot exercise.
