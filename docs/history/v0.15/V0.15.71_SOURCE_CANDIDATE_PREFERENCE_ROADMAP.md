# v0.15.71 Source Candidate Preference Roadmap

_Written June 27, 2026. Target app version: `0.15.71`._

## Evidence

The latest completed Project Management ZIP/log audit still regraded below the
`100/100` target. The remaining source-loss evidence included ambiguous Open
Library public-metadata rows in the exported source ledger while the broader
source-finder bridge had already proven it could recover trusted,
concept-linked rows from retrieved resources.

This release does not claim the deployed site now reaches `100/100`; a fresh
deployed ZIP/log audit is still required. It fixes one deterministic source
ledger failure mode: when a source-finder topic contains multiple candidates,
the exported ledger row should not blindly preserve the first metadata-only
candidate if a stronger trusted candidate is available in the same topic.

## Lane

Source-ledger product quality. Keep trust standards strict while selecting the
best available source-finder candidate for each topic.

## Changes

1. Rank source-finder topic candidates before ledger export.
   - Accessible sources with explicit non-ambiguous licenses now beat
     metadata-only rows.
   - Trust-eligible academic, OER, and licensed background providers receive
     priority over review-only metadata providers.

2. Preserve strict Open Library handling.
   - Open Library public metadata remains review-only evidence.
   - The fix does not mark ambiguous metadata as trusted and does not weaken
     source-ledger grading.

3. Pin the audited failure shape.
   - The focused regression builds a topic where Open Library appears first and
     OpenAlex appears second.
   - The exported ledger row must be the trusted, concept-linked OpenAlex row.

## Non-Goals

- Claiming package quality is now `100/100` before a fresh deployed audit.
- Promoting Open Library public metadata into trusted bibliography proof.
- Solving partial enrichment coverage, texture, or PPTX echo warnings.

## Release Boundary

In scope:

- Rank source-finder topic candidates before writing the one recovered
  mini-shard row per topic into the source ledger.
- Prefer accessible, non-ambiguous, trust-eligible candidates when they are
  available in the same topic.
- Keep metadata-only Open Library rows visible as review evidence, not trusted
  source proof.

Out of scope:

- Increasing source counts by exporting every candidate from every topic.
- Treating ambiguous public metadata as trusted bibliography evidence.
- Claiming the next generated package will be clean without a fresh ZIP/log
  audit on the deployed release.
