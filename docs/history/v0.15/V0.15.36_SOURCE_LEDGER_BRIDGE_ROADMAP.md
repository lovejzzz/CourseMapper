# v0.15.36 Source Ledger Bridge Roadmap

## Evidence

The hourly EduTool.dev audits on June 20, 2026 found the same failure twice on
deployed v0.15.35:

- `verification-output/edutool-audit-loop/20260620T160412Z/report.md`:
  digest reported 8 open resources, but the ZIP exported 1 trusted
  OpenLibrary row and 1 CourseIR review row.
- `verification-output/edutool-audit-loop/20260620T170412Z/report.md`:
  digest reported 9 open resources, but the ZIP again exported only 1 trusted
  OpenLibrary row and 1 CourseIR review row.

The grader was right to keep both packages below 100. The product defect was
not the score; it was the bridge between retrieved source evidence and the
exported source ledger.

## Design

This release takes the smallest bridge slice before the larger ResearchSession
architecture:

1. Source-backed graph resources are durable. If native stable-id re-derivation
   runs after a map repair and the new map no longer contains the rendered
   citation, CourseMapper preserves unmatched OpenAlex/OpenStax/OpenLibrary,
   genome, and source-finder resources.
2. Preserved session-backed resources are relinked to the matching session's
   first section. That lets `buildSourceLedgerFromCourseGraph` recover
   concept-linked rows instead of orphan source rows.
3. `sourceFinderMiniShard` is a source-ledger recovery input. When resource
   cells are sparse, the export path can still normalize the retrieved provider,
   title, URL/DOI, license, snippet, and lesson concept context for the top
   attached source per topic into trusted source-ledger rows.
4. Dedupe prefers stable URL/DOI/id identity so a source recovered from both a
   graph resource and the mini-shard appears once.

## Lane

Narrow source-ledger bridge and export-proof durability. This release preserves
real retrieved source evidence through existing CourseGraph and source-finder
handoffs. It does not introduce a new provider call, a new paid research stage,
or the full atom-level ResearchSession planner.

## Non-Goals

This is not the full constitutional research brain. It does not claim every
CurriculumV1 atom has a semantically best source yet. It keeps the existing
source-thinness and review-row checks armed so weak coverage remains visible.

The next architecture step is still the ResearchSession planner: research once,
cache a normalized ledger, assign sourceRefs to CurriculumV1 atoms, then compile
many deliverables from those refs.

## Release Boundary

Ship only if the focused native graph/source-ledger regressions, full test
suite, gold smoke, build, bundle check, release-history audit, and browser
verification pass locally. After push, Fast verification and GitHub Pages deploy
must complete before the release is claimed.
