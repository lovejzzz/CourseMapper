# V0.15.133 Assessment Registry Bridge Roadmap

## Goal

Make Course Map assessment promises compile into matching downstream artifacts
when the visible Course Map carries a richer assessment registry than the native
course graph.

## Evidence

- Fresh deployed audit:
  `verification-output/edutool-audit-loop/20260629T165140Z-v015132-fresh`
- Course: User Experience Design Studio
- App version: v0.15.132
- Run id: `run-1782751463409`
- Finish id: `finish-mqzgd48r-15s7u`
- Local regrade: 99/100, grade A
- Scored finding: 1 P2 identity finding
- Digest finding:
  `23 course-map assessments are only covered as in-class lesson-plan activities,
not dedicated artifacts`
- Specific alignment warning:
  `Final UX case study portfolio studio checkpoint: defend one prototype or
case-study move with evidence. -- promised in course map (Lesson 11), no
matching assignment or exam was generated`

## Diagnosis

The ZIP was not failing because the model wrote weak prose. The Course Map,
manifest, and grader saw 36 assessment rows, but the compiler authored only 12
assignment briefs from the native graph assessment registry.

That meant the product promised weekly assessment checkpoints in the Course Map
without exporting dedicated assignment artifacts for most of those checkpoints.
The quality grader was correct to hold the package at 99/100 because the
artifact set did not fully match the map.

## Lane

1. Bridge richer Course Map assessment rows into compilation
   - Derive a Course Map-backed assessment registry from the visible Course Map.
   - Use that registry only when it has more rows than the native graph.
   - Keep the native graph as the lesson/content backbone.

2. Preserve strict compiler contract truth
   - Allow registry-mode lessons to compile multiple graded assessment anchors.
   - Keep blocking if a gradeable registry lesson has no compiled anchor.
   - Do not treat in-class activities as dedicated assignment artifacts.

3. Prove the exact mismatch shape
   - Reproduce a native one-assessment graph with a visible three-assessment map.
   - Prove compilation emits three assignment briefs.
   - Prove assessment reconciliation clears against the visible Course Map graph.

## Fix

V0.15.133 adds a narrow assessment-registry bridge:

1. Generation derives a Course Map assessment registry before blueprint
   compilation.
2. When the visible Course Map registry is richer than the native graph registry,
   the compiler receives the Course Map registry so promised graded rows produce
   downstream artifacts.
3. The run log records an `Assessment registry bridge` pipeline decision with
   the native and Course Map assessment counts.
4. The semantic compiler contract now has a registry mode that permits multiple
   assessment anchors per lesson while still blocking gradeable lessons that
   lack compiled anchors.
5. Focused registry tests prove three visible Course Map assessment rows compile
   into three assignment briefs and clear the reconciliation check.
