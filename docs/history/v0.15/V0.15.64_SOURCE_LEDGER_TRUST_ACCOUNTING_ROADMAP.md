# v0.15.64 Source Ledger Trust Accounting Roadmap

_Written June 26, 2026. Target app version: `0.15.64`._

## Evidence

The latest completed Project Management ZIP/log audit is still the v0.15.62
artifact. It regraded at 96/100 (A), with texture 88/100, two P1 findings, and
two P2 findings. v0.15.63 repaired the visible generic Course Map focus defect,
but no fresh deployed v0.15.63 ZIP/log audit has proven the package is clean.

The source-proof loss is CourseMapper-side. A stronger model can improve prose,
but it will not turn retrieved resources into trusted, concept-linked source
ledger rows unless CourseMapper preserves provider identity, license status, and
sourceRef coverage through export and grading.

## Goal

Make source trust accounting strict and useful:

1. A trusted source row must be accessible, non-ambiguous, and come from a
   trust-eligible provider.
2. CourseIR review rows, instructor placeholders, Open Library metadata, and
   public-metadata-only records must not inflate trusted source counts.
3. Licensed source-finder rows, including Wikipedia background sources and
   Crossref DOI records with explicit reusable rights, should preserve provider
   identity and be eligible for concept-linked source proof.

## Lane

Source/research bridge and grader truth. This release tightens trust accounting
and source-finder provider preservation. It does not claim 100/100 package
quality until a fresh deployed ZIP/log audit proves source proof, slide depth,
and texture are all clean.

## Changes

1. Source ledger summaries now compute `trustedCount` from a row-level trust
   predicate instead of provider name alone.
2. Crossref rows are normalized as academic metadata, but public-metadata-only
   Crossref records remain license-ambiguous and do not count as trusted.
3. Wikipedia rows with accessible URLs and Creative Commons licenses normalize
   as licensed background sources, preserving concept links from source-finder
   mini-shards.
4. Rendered Crossref/Wikipedia citations now infer their real provider instead
   of falling back to generic syllabus proof.
5. The source-ledger quality checker now reports sourceRef thinness using the
   same trusted-row definition, so review-only or metadata-only proof shows as
   zero trusted rows.

## Release Boundary

In scope:

- Trust-count accuracy in `sourceLedgerSummary`.
- Provider identity preservation for Crossref and Wikipedia source-finder rows.
- Grader wording and P1 sourceRef thinness checks that match trusted-row reality.

Out of scope:

- Claiming public metadata as reusable source proof.
- Hiding source review rows or weakening sourceRef coverage checks.
- Fixing slide-deck depth or texture repetition.
- Claiming current deployed package quality without a fresh v0.15.64 ZIP/log
  audit.
