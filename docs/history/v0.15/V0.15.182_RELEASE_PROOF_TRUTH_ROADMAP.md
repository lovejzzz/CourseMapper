# V0.15.182 Release Proof Truth Roadmap

## Evidence

- v0.15.181 was pushed to `main` at `33718c258c6604328fe2d788129e239f1fbcc195`.
- GitHub Actions Fast verification failed at `npm run audit:release-history` before unit tests,
  proof smoke, build, or bundle budgets ran.
- The deployed site still served `APP_VERSION 0.15.180` after the v0.15.181 push because Pages
  deploy was skipped when Fast verification failed.
- The same release-history audit passed locally because `release-contracts/v0.15.181.json`
  referenced ignored files under `verification-output/`, and those local audit artifacts existed on
  this laptop.
- GitHub Actions uses a clean checkout, so ignored `verification-output` artifacts are absent there.
  A current release contract cannot use those local-only files as required anchors.

## Goal

Make release-history proof deterministic in a clean checkout so CI and the local machine validate the
same committed evidence.

## Lane

Release contract and proof-ledger truth. This is not a compiler, grader, source-ledger, or export
behavior change.

## Release Boundary

This release may claim that:

- v0.15.181 failed Fast verification because the current release contract anchored ignored local
  audit files;
- the v0.15.181 historical contract no longer requires ignored `verification-output` files to pass;
- v0.15.182 current proof uses committed docs, source, tests, and release-contract files;
- deployment of the discussion texture rotation is unblocked once Fast verification and Pages pass.

It may not claim that the v0.15.181 discussion texture fix has been verified in live provider output.
That still requires a fresh deployed GPT-5.4-mini ZIP/log audit after Pages serves v0.15.182.
