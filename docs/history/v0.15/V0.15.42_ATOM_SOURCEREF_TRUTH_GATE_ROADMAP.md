# v0.15.42 Atom SourceRef Truth Gate Roadmap

_Written June 20, 2026. App version: `0.15.42`._

## Goal

Keep the source-quality score honest after the v0.15.41 source-proof fallback.
The downloaded ZIP may now include a `SOURCE_REPORT.md`, but complete-looking
atom sourceRef coverage must not look clean when those atom refs still route
through a single CourseIR/review source row while trusted external source rows
sit beside it.

## Lane

Source-ledger grader truth. This lane changes only the quality gate and its
regression coverage. It does not change source retrieval, source selection,
license normalization, compiler prompts, or export assembly.

## Release Boundary

In scope: flagging complete atom-level sourceRef coverage that is not wired to
the exported trusted source ledger, release manifest, release contract, roadmap,
and focused grader regression coverage.

Out of scope: declaring ambiguous OpenAlex/OpenLibrary rows safe, inventing
licenses, changing source-finder scoring, or completing the broader
research-once source ledger architecture.

## Evidence

The 20260621T000414Z EduTool.dev audit ran against deployed v0.15.41
(`7d0facf`). Fast verification and Pages deploy were green before the run. The
fresh Genetics and Society package exported successfully and downloaded as:

- `verification-output/edutool-audit-loop/20260621T000414Z/Genetics and Society - Course Materials (7).zip`

Local regrade reproduced the package report:

- quality: `98/100` (`A`)
- texture: `94/100`
- findings: `0 P0`, `0 P1`, `5 P2`
- export verification: passed

v0.15.41 made real progress:

- `SOURCE_REPORT.md` shipped.
- `PACKAGE_MANIFEST.json` exported `9` trusted source rows and `1`
  review-only row.
- `SOURCE_REPORT.md` listed the research policy and concept-linked sources.

The remaining honesty gap is atom wiring, not missing files:

- `courseIR.sourceRefCoverage.totals`: `55/55` atoms with sourceRefs.
- `courseIR.sourceRefCoverage.sourceLedgerRows`: `1`.
- `sourceReviewRows`: `SL1`, `Existing course map fields.`
- `sourceLedger`: `9` exported trusted rows.

That means the report can say all outcomes, activities, examples, assessments,
rubric criteria, and factual claims have sourceRefs while the coverage proof
still routes through one CourseIR source row instead of the trusted external
ledger rows.

## Fix

The source-ledger grader now adds a P1 citation finding when all of these are
true:

1. atom sourceRef coverage covers at least 12 atoms,
2. the package exports more than one trusted source ledger row,
3. the coverage proof says those atoms rely on one or zero CourseIR source rows,
4. review-only source rows are present.

The finding is explicit:

`sourceRef coverage is not wired to trusted source ledger rows`.

## Verification

Focused regression coverage recreates the live v0.15.41 artifact shape:

1. multiple exported trusted source rows,
2. one review-only CourseIR row,
3. `55/55` atom sourceRef coverage,
4. `sourceLedgerRows: 1` in the CourseIR coverage proof.

The regression proves the grader reports the wiring gap as P1 without changing
license ambiguity policy or hiding review-only source proof.

## Carry Forward

This release raises the truth bar; it does not complete the source architecture.
The next real quality work is to connect retrieved OpenAlex/OER/source-finder
rows to CurriculumV1/CourseIR atom sourceRefs before compilation, so outcomes,
activities, examples, assessments, rubric criteria, and factual claims point to
the actual trusted source ledger rows rather than a review fallback.
