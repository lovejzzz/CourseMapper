# V0.15.11 - Prompt Artifact Firewall

_Written June 19, 2026. This roadmap records the live EduTool.dev audit that
turned a generated-package defect into a narrow shipped repair and grader
contract._

## Goal

Requested package deliverables must never become course content. If a user asks
for lesson plans, slide decks, assignment briefs, rubrics, discussion prompts,
quizzes, study guides, course FAQ, worked examples, misconceptions, and
instructor handoff notes, those phrases describe artifacts to render. They are
not lesson concepts for Environmental Science, Calculus, History, or other
normal disciplinary courses.

The release goal is a small but hard rule:

1. Repair prompt artifact labels out of Course Map topic/content cells before
   the compiler fans them into every deliverable.
2. Make the package grader flag the old failure shape as unsafe when an export
   still contains it.
3. Keep legitimate instructional-design courses allowed to teach rubrics,
   assignment briefs, slide-deck design, and related artifact genres.

## Evidence

The 2026-06-19 EduTool.dev audit generated an 8-lesson environmental-science
package from this prompt shape:

> Include evidence-rich lesson plans, slide decks, assignment briefs, rubrics,
> discussion prompts, quizzes, study guides, course FAQ, worked examples,
> misconceptions, and instructor handoff notes.

The exported Course Map then used those deliverable labels as lesson sections:

- `1.2: evidence-rich lesson plans`
- `1.3: slide decks`
- `4.2: assignment briefs`
- `5.2: course FAQ`
- `8.2: instructor handoff notes`

The contamination propagated into study guides, slide decks, rubrics, the
syllabus, and assignment briefs, while the package still reported `Quality 99`
and `Texture 92`. Regrading the same ZIP after this patch produces a P0
substance finding and caps the package at 74/C.

## Reason

The current fallback/repair path had a bad assumption: short noun phrases found
near the generated course map were acceptable topic candidates. That was useful
for sparse maps but unsafe when the prompt included a deliverable list. Once a
deliverable label became a topic, deterministic compilation faithfully reused
it everywhere, making the downstream package look structurally complete while
teaching the wrong thing.

This is exactly the kind of issue the CourseIR plan is meant to reduce, but the
current shipped path still needs a direct guard. The product cannot wait for the
full CourseIR default flip to stop obvious prompt-request leakage.

## Lane 1 - Course Map Repair

`repairCourseMapReadiness` now treats prompt artifact labels as invalid topic
candidates for non-instructional-design courses. It strips common lesson/section
prefixes such as `1.2:` before comparison, rejects generic fallback sentences as
topic candidates, and repairs contaminated topic, goal, objective, assessment,
resource, and design cells from the real lesson topic.

The guard is intentionally scoped. Courses whose title or manifest clearly
indicates instructional design, course design, curriculum design, assessment
design, teacher education, teaching methods, pedagogy, or education may still
teach artifact genres as real content.

## Lane 2 - Package Grader Truth

The Crucible grader now scans exported Course Map cells and lesson-rooted
documents for numbered prompt artifact topics and lesson-focus prose built
around artifact labels. A single weak case is a P1; multi-label or Course Map
contamination is a P0 because the resulting package is not safe for instructor
handoff.

The grader version bumps to `1.7.0` so manifests name the stricter rule that
produced the package quality report.

## Lane 3 - Regression Proof

The release pins two tests:

- `tests/v0141-phase1-finalizer.test.js` proves a contaminated Environmental
  Science course map repairs `evidence-rich lesson plans` and `slide decks`
  back to `ecosystems` before compilation.
- `tests/v0154-linear-algebra-output-quality.test.js` proves a synthetic
  exported package with the old contamination shape receives a P0 substance
  finding, while an instructional-design course is not falsely blocked.

## Lane 4 - Audit Loop Use

The recurring EduTool audit should keep generating from deployed code, but a
run like this is now release-worthy only when it reveals a defect that the local
repo can fix and prove. No-op audits should keep writing evidence under
`verification-output/edutool-audit-loop/<timestamp>/` without bumping or
pushing.

## Release Boundary

v0.15.11 does not ship the CourseIR default path and does not claim the
one-call architecture is production-default. It only hardens the current path
against prompt artifact contamination and records the CourseIR work as
carry-forward.

The CourseIR default flip still requires side-by-side 5-, 8-, and 15-lesson
quality/cost proof with equal or better package quality, lower call count or
token cost, clean export verification, and current remote CI/deploy evidence.
