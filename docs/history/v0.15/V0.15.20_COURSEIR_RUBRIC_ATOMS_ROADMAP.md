# V0.15.20 - CourseIR Rubric Atoms

## Goal

v0.15.19 made learner work first-class by requiring CourseIR outcomes and
activity atoms. The next missing piece in the structured curriculum brain was
rubric structure. Assessments still carried mostly loose `rubricDimensions`
strings, which helped final prose but did not prove that the brain knew how
student work would be judged.

v0.15.20 makes rubric criteria part of CourseIR:

1. Every assessment needs `rubricCriteria[]` atoms.
2. Every criterion needs concept links, outcome links, and performance levels.
3. Compiler repair can synthesize missing criteria for explicit CourseIR input.
4. Direct provider acceptance rejects repaired or level-less rubric structure.

## Lane

This is a CourseIR contract and compiler-projection slice. It does not add new
domain genome shards, does not claim a fresh live EduTool.dev package audit,
and does not make direct CourseIR unconditional. It tightens what counts as a
dense accepted curriculum brain.

## Why This Matters

Rubrics are where the curriculum brain becomes accountable. Without rubric
atoms, the system can produce polished assignment and rubric prose while the
pre-compile object only says "accuracy" or "evidence use." That is not enough
for the target architecture.

The stronger chain is:

`concept -> outcome -> activity -> evidence -> assessment -> rubric criterion -> deliverable`

That chain lets the compiler render consistent rubrics, assignment briefs,
lesson plans, and handoff notes from one structured source instead of asking
later prose to invent the scoring standard.

## Fix

CourseIR now normalizes, validates, repairs, and projects:

- `assessment.rubricCriteria[]`
- criterion descriptions
- criterion concept links
- criterion outcome links
- criterion performance levels

Legacy `rubricDimensions` remain compatible, but they are not the final
standard. For explicit CourseIR input, deterministic repair turns them into
criteria with performance levels. For direct provider authoring, repaired
rubric structure is rejected as direct-authoring proof and surfaced as fallback
evidence.

## Release Boundary

v0.15.20 ships only after focused CourseIR and native-authoring regressions,
formatting, lint, build, bundle check, full unit suite, browser verification,
constitution audit, gold smoke audit, and release-history audit. Remote Fast
verification and Pages deploy are claimed only after push.

## Acceptance

This slice is acceptable when:

1. Missing rubric criteria are CourseIR validation blockers.
2. Criteria without performance levels repair before deterministic compile.
3. Repaired rubric criteria reject direct provider acceptance.
4. CourseIR coverage counts lesson assessment rubric criteria.
5. Native authoring stays green under the stricter CourseIR contract.

## Carry Forward

The remaining source-truth work is to make source citations and feedback loops
first-class CourseIR atoms, then add more domain genome shards so fewer common
courses rely on assumption repair. Live EduTool.dev ZIP/log audits still need
to compare accepted direct CourseIR against the legacy native/prose path on the
same briefs before claiming broad quality improvement.
