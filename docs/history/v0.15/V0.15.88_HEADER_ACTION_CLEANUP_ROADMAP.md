# v0.15.88 Header Action Cleanup Roadmap

## Goal

Make the working/generation page's top controls feel like a calm workspace
toolbar: one primary package action, one project/file disclosure, and no repeated
Agent review notes.

## Evidence

The live v0.15.87 working page showed the header overflow acting as a mixed
action drawer: package finishing, save, new project, add materials, and undo/redo
were all grouped under one "More" control while the export panel, deliverable tab
row, and edit toolbar already had clearer ownership for those verbs. The same
audit showed a zero-count custom-tools pill and repeated Agent "Worth a look"
cards, which made a ready-with-notes package feel noisier than the underlying
state.

## Lane

UI/UX surface cleanup. This release moves controls to the surface that owns the
action; it does not change quality scoring, grader standards, provider prompts,
or export package contents.

## Scope

1. Keep the header disclosure project/file-only and label it `Project`.
2. Leave package finishing/download ownership with the primary CTA and export
   panel.
3. Leave material creation and edit history with the deliverable/editing rows.
4. Hide empty custom-tools chrome unless a sync error requires attention.
5. Render only the latest Agent digest and deduplicate observations inside that
   digest.

## Release Boundary

The release is useful if the top row no longer exposes package finishing,
material upload, or undo/redo through the project disclosure, and if repeated
Agent digest cards stop stacking on ready-with-notes pages.

## Verification Plan

1. Targeted component/source tests for header action ownership, digest dedupe,
   message-list latest-digest rendering, and empty custom-tools visibility.
2. Normal local gates before release: format check, lint, test suite, build,
   bundle check, release-history audit, and gold smoke.
3. After deploy, use a fresh browser pass to confirm the top row no longer shows
   a junk-drawer `More` menu and the Agent panel does not stack duplicate notes.

## Carry Forward

- This release is UI-surface cleanup. It does not claim to solve the remaining
  package-quality losses from v0.15.87 provider evidence.
- Continue fresh ZIP/log audits after deploy to verify quality, export, source,
  and local-storage behavior on real generated packages.
