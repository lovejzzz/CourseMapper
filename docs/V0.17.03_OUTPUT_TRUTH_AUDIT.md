# V0.17.03 Output Truth Audit

## Outcome

V0.17.03 replaces unresolved assignment configuration in the shared compiler
with concrete file, extent, citation, submission, and exception defaults. It
also prevents a structurally complete package from receiving a clean
content-verification result when imported or provider-authored directions still
defer required format, length, or citation rules. Deep grader V1.11.4 makes the
same defect score-bearing and reports an exact artifact defect once.

## Goal

Make the quality result match what a learner can actually use. A package may be
exportable for instructor review without being called clean when essential
assignment logistics still require an unstated decision.

## Lane

This is a deterministic assignment-content, export-verification, and deep-grader
lane. It does not train or promote a model and does not broaden network access.

## Release Boundary

The release includes concrete shared assignment defaults, semantic deferral
detection, export warning propagation, score-bearing deep grading, exact finding
deduplication, regression coverage, and release evidence. Factual review, human
evaluation, accessibility certification, model-weight changes, and production
deployment remain outside this release.

## Review method

Roundtable v0.0.0.32 was launched against the EDUTOOL repository with an
explicit code-only instruction. The room was steered with a real retained
package as regression evidence rather than with release prose. Codex completed
its sealed source review and identified a reproducible false-clean path. The
Claude role could not join the discussion because its CLI rejected the saved
credential with HTTP 401 even though its local status command reported a logged
in account. That limitation is recorded rather than presented as consensus.

Codex then independently traced the finding through current source, wrote
focused counterexamples, and regraded the retained package. Documentation is a
record of that work; the source, regressions, and release gates are the proof.

## Evidence

### Current code path

Current assignment emitters in `src/lib/nativeGraphAuthoring.js` and
`src/lib/courseBlueprintCompiler.js` can produce finished-looking directions
such as “the medium listed for the task,” “the word, page, or time limit
listed,” and “the course citation format.” The existing publishability scanner
did not recognize that semantic handoff. Consequently, content verification
could report `passed`, and package conformance could show 99/A with zero encoded
findings, even though the assignment was not fully actionable from the exported
artifact. Enabling the new check against the unchanged compiler reproduced this
warning in 117 of the 132 real-scenario compiler-matrix cases; that result drove
an emitter repair rather than a test-expectation change.

### Retained real package

`docs/instructor-review/world-lit-package.zip` is an older 128-entry World
Literature package retained in the repository. Its embedded report recorded
100/100, A, and zero findings. The current pre-release grader regraded the same
archive at 74/C with 66 findings: 14 P0, 19 P1, and 33 P2. This comparison is a
regression corpus, not a claim that V0.17.03 newly introduced those historical
defects.

The regrade exposed two useful current measurement problems. First, several
assessment-registry rows pointed to the same comparative-paper artifact, so one
artifact defect appeared three times. Second, an early detector draft treated
course-site and late-policy wording as missing configuration too broadly.

## Decisions

### Accepted: the compiler should finish the logistics it can own

Native fallback assignment cores now state concrete PDF, slide, and recording
forms plus bounded word, slide, or time ranges. The shared compiler selects a
concrete extent from the artifact type and workload, supplies an inspectable
source-credit rule, names a usable submission route with fallback, and states
that no automatic late exception is assumed. These are safe operational
defaults that an instructor can edit; they do not pretend a missing local policy
was verified.

### Accepted: unresolved essential logistics must remain visible

`findInstructorConfigurationDeferrals` now recognizes strong unresolved
submission-format, length, and citation deferrals. Assignment content checking
scans the learner-facing instructions, parameters, and format requirements.
`verifyPackageExports` therefore returns warnings rather than a clean pass when
the defect is present. Export remains available for instructor review.

### Accepted: the deep score must agree with export verification

Deep grader V1.11.4 emits
`assignment-instructor-configuration-deferral` as a P1 format finding. This
prevents the deeper report from restoring an A-shaped result after the export
verifier already found the unresolved handoff.

### Accepted: one artifact defect should count once

Exact duplicate findings with the same code, severity, dimension, artifact,
detail, and quoted evidence are retained once. Multiple assessment rows may
describe stages of one assignment, but they do not turn one physical defect
into three independent learner-facing failures.

### Rejected: broad policy-language penalties

The final detector does not flag “Official course site,” a posted deadline, or
a local late-work policy by themselves. Those phrases may be concrete enough in
the surrounding course context and are not always required to make an exported
assignment usable. The score-bearing rule is limited to absent submission
format, length, and citation decisions. Concrete directions such as “Submit a
1,200-word PDF memo in Canvas using APA 7” remain clean.

## Claim boundary

This work proves encoded behavior for assignment-deferral detection, export
warning status, deep-grader severity, and exact finding deduplication. It does
not prove every assignment is factually correct or instructionally optimal,
that an instructor approved the package, that accessibility needs are met, or
that classroom outcomes improved. Gemma weights and the inactive adapter are
unchanged.

## Roundtable follow-up

The audit also exposed two Roundtable product issues: an iCloud-backed source
checkout could leave the web process alive without binding its port, while a
clean detached runtime started normally; and the Claude health probe could
report logged in immediately before the model rejected the credential as
revoked. Those are Roundtable reliability findings, not EDUTOOL claims, and are
tracked separately from this release contract.
