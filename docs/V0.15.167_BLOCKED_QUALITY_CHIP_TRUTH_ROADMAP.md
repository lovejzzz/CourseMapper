# V0.15.167 Blocked Quality Chip Truth Roadmap

## Evidence

- Fresh deployed v0.15.166 GPT-5.4-mini Python browser audit:
  `verification-output/edutool-audit-loop/20260630T221931Z-v015166-fresh-blocked/`.
- The run completed generation but blocked before ZIP export:
  - UI showed `Needs review - 1 blocker`.
  - No `Download ZIP` action was available.
  - Digest recorded `finalStatus: blocked`, `blockers: 1`, `exportStatus: warnings`,
    `exportFailed: 0`, and `qualityScore: 100`.
- The workspace header still foregrounded `Quality 100 - Texture 94`, which could
  make a blocked package look clean even though the export panel correctly
  refused download.

## Goal

Keep the primary header state aligned with package trust:

- Clean packages can show the quality score.
- Caveated but downloadable packages can show an amber score.
- Blocked packages must show action needed first.
- The detailed score can remain available in the quality report and tooltip, but
  it must not be the main visible state when export is blocked.

## Lane

UI truth and release-report agreement for blocked package states. This is a
narrow product-surface fix, not a grader relaxation or model-quality change.

## Release Boundary

This release may claim that the workspace header no longer foregrounds a clean
quality score when the finalizer blocks ZIP export. It may not claim a clean
v0.15.167 exported package, source proof, or texture improvement until fresh
deployed ZIP/log evidence exists.

## Scope

- Update `WorkspaceQualityChip` to read `getPackageTrustStatus` before choosing
  its copy and tone.
- Render blocked packages as red `Needs review` or `Fix required` chips.
- Preserve grade and texture details in accessible labels/tooltips for audit and
  instructor context.
- Add a regression for the exact blocked v0.15.166 shape: finalizer blocked,
  one blocker, grade 100/A, Texture 94.

## Out Of Scope

- This release does not claim a clean ZIP score for v0.15.167.
- This release does not change the deep grader scoring rules.
- This release does not weaken blockers or make blocked packages downloadable.
- The remaining readiness-retry gap should be investigated from fresh deployed
  evidence or recovered in-memory deliverables; it should not be guessed from
  the header fix alone.
