# V0.15.21 - CourseIR Source Trace

## Goal

v0.15.19 made outcomes and activities first-class CourseIR atoms. v0.15.20
made rubric criteria first-class atoms. Those changes made the curriculum brain
more structured, but a model could still author plausible atoms without proving
where their factual and instructional grounding came from.

v0.15.21 closes that gap for the core teaching chain:

1. Every lesson outcome needs `sourceRefs`.
2. Every learner activity needs `sourceRefs`.
3. Every rubric criterion needs `sourceRefs`.
4. Each source ref must resolve to the CourseIR source ledger.
5. Direct provider acceptance rejects source-link repair instead of counting it
   as native structured authorship.

## Lane

This is a CourseIR traceability and direct-authoring boundary slice. It does
not claim a fresh live EduTool.dev package audit, a new provider-cost routing
change, or a completed planetary curriculum genome. It makes the existing
CourseIR v1 object stricter so the compiler can distinguish source-linked
curriculum structure from polished but ungrounded prose.

## Why This Matters

“Genome-linked” is important because the target architecture is not just a
better prompt. The product needs a curriculum object whose important atoms can
be checked, repaired, compiled, audited, and eventually improved against a
domain genome.

The current minimum chain is:

`source ledger -> concept -> outcome -> activity -> evidence -> assessment -> rubric criterion -> deliverable`

Without source links on outcomes, activities, and rubric criteria, a native
model can still drift into prose: the visible package may read well, but the
compiler cannot prove that the learning work and scoring standard came from
the same source-grounded curriculum model.

## Fix

CourseIR now validates source refs for:

- lesson `outcomes[]`
- lesson `activities[]`
- assessment `rubricCriteria[]`

Missing source refs and dangling source refs are blocking validation issues.
Compiler repair can restore refs for explicit CourseIR input by using
lesson-level factual anchors, constraints, linked concept factual anchors, and
the source ledger as fallbacks. That repair is recorded as
`added-atom-source-refs`.

Direct provider acceptance treats that repair as evidence that the model did
not actually author the dense curriculum brain. The same repaired object may
still compile deterministically, but it cannot claim accepted direct CourseIR
authorship.

## Release Boundary

v0.15.21 ships only after focused CourseIR and native-authoring regressions,
formatting, lint, build, bundle check, full unit suite, browser verification,
constitution audit, gold smoke audit, and release-history audit. Remote Fast
verification and Pages deploy are claimed only after push.

## Acceptance

This slice is acceptable when:

1. Missing outcome, activity, and rubric source refs are validation blockers.
2. Dangling outcome, activity, and rubric source refs are validation blockers.
3. Compiler repair restores atom source refs and records
   `added-atom-source-refs`.
4. Direct provider acceptance rejects repaired atom source refs.
5. CourseIR validation stats expose source-linked outcome, activity, and rubric
   counts.
6. Native authoring remains green under the stricter CourseIR source contract.

## Carry Forward

The next CurriculumV1 improvements are not more prose. They are deeper
compiler-visible structure:

1. Make citations and feedback loops first-class CourseIR atoms, not just
   source refs and handoff notes.
2. Add domain genome shards for common courses so source refs can point to
   richer concept kernels instead of broad source-ledger rows.
3. Add side-by-side EduTool.dev ZIP/log audits comparing accepted direct
   CourseIR against native skeleton/prose fallback on the same course briefs.
4. Tune provider planning so the largest capable models attempt one compact
   whole-course CourseIR call, while smaller models use block compilation
   without losing the same traceability contract.
