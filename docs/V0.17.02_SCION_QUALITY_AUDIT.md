# V0.17.02 Scion Quality Audit

## Outcome

V0.17.02 makes two contracts exact: how many questions a lesson receives and
which lesson each generated artifact belongs to. It also makes the adaptive
evidence route report empty or failed composition honestly. The release changes
the deterministic Scion/CourseMapper system; it does not change Gemma weights
or promote the inactive adapter.

## Goal

Make Scion's generated-output contract internally consistent: requested quiz
counts must be exact, each learner-facing row must retain the lesson it covers,
and an empty adaptive composition must remain visibly incomplete.

## Lane

This is a deterministic compiler, retry, validation, and diagnostic-metadata
lane. It does not train or promote a model and does not broaden network access.

## Release Boundary

The release includes shared quiz planning and compilation, specialized
deterministic frames, materialized-scope identity, targeted retry merging, final
quiz/FAQ coverage validation, adaptive composition metadata, regressions, and
release evidence. Streaming browser-runtime digest enforcement, model-weight
changes, adapter promotion, human evaluation, and production deployment remain
outside this release.

## Method

The review used Roundtable as a visible, steerable code-review room. Codex,
Claude, and Antigravity were explicitly directed to inspect source and tests,
not release documentation. The first discussion identified contradictions and
risks in the then-current implementation. Codex independently reproduced each
candidate finding in the repository before accepting it. A second code-only
audit reviewed the completed patch and was instructed to report only
reproducible blockers. The follow-up reached consensus that all five reproduced
counterexamples were closed and found no remaining release blocker in the
working tree.

Documentation records the result; executable source, focused regressions, the
full unit suite, lint, formatting, the production build, the pinned browser-base
audit, and release-history validation are the proof.

## Findings and disposition

### Accepted: the configured quiz target was not one contract

The UI and configuration allowed up to eight questions, but planning and
several deterministic paths were still shaped around six. Retry and readiness
could therefore disagree with compilation.

V0.17.02 adds `resolveQuizQuestionTarget` as the single bounded resolver for
values three through eight. Prompt planning, CourseIR, deterministic
compilation, post-processing, retry, validation, readiness, and the generation
hook now consume that value. Underfilled and overfilled results both enter
targeted retry, and final validation requires equality rather than treating the
target as a minimum. Generic compilation is exercised at every target from
three through eight; a nine-question result fails an eight-question contract.

### Accepted with a stronger implementation: eight must not mean padding

One Roundtable position proposed lowering the complete-product target to six.
The direct code audit instead retained the product's declared range and made
seven and eight real. The last two quiz-plan roles are evidence limitation and
revision transfer. Generic compilation, source-bound recovery, Bayesian
reasoning, music theory, language instruction, and review-week generation each
carry eight distinct frames. Optional authored-bank extensions replace those
slots only when the requested count reaches seven or eight; they do not create
an accidental ninth item.

### Accepted: aggregate row counts hid lesson-identity defects

A partial retry could compact a scope and then merge by position or a weak
title heuristic. A result with the right number of rows could still duplicate
one lesson and omit another.

V0.17.02 exports one canonical lesson-number resolver, preserves valid original
lesson numbers in materialized scopes, uses the same identity for retry merging
and missing-index detection, and sorts identified results numerically. It
rejects contradictory numeric and title identities instead of choosing one,
and canonicalizes every identity-bearing field when a compact scope is mapped
back to its source lesson. Final quiz and FAQ validation receives the exact
expected source lesson-number set and rejects conflicting, unkeyed, duplicate,
missing, and out-of-scope rows.

### Accepted: integration paths also had to honor the exact contract

The first follow-up audit found that source-scoped generation was still
comparing a materialized Lesson 5 result with compact expected Lesson 1.
Expected identities now derive from the same resolved source scope used to
patch generated rows. It also found that authored bank extensions inherited
their reserve indices and therefore minted `q9`/`q10`; replacements now use
the actual slots 6 and 7 for IDs and answer rotation while retaining the bank
index only as provenance. Review-week deduplication now repairs a colliding stem
before selecting the requested count instead of filtering after the target was
already sliced.

### Accepted: adaptive fallback metadata overstated completion

The evidence compiler could return empty text after an empty or failed
composition while still reporting a normal `stop`. Deterministic downstream
parsing already rejected the empty kernel, but the route receipt was
misleading.

The stream result now records `adaptiveComposition` as `composed`, `empty`, or
`failed`. Only composed text reports `finishReason: stop`; empty or failed
composition reports `finishReason: fallback` with zero model requests. The
telemetry event is the neutral `scionEvidenceComposition` and carries the same
explicit outcome. A regression proves that empty text does not parse as a
completed lesson kernel.

### Deferred and explicitly not claimed: browser-runtime digest enforcement

The pinned model URL, revision, identity, and declared file metadata are
auditable. The current browser runtime does not yet recompute and enforce every
declared SHA digest across the complete model byte stream. V0.17.02 therefore
does not describe that boundary as cryptographic runtime verification. Adding a
streaming digest gate remains separate security work because it changes
startup cost, cache migration, and failure recovery.

### Rejected as release blockers

Historic adapter and base-freeze scripts that require old arguments are not
current release gates. Documentation wording is not accepted as evidence for a
code claim. No Roundtable suggestion was implemented until it was reproduced
in current source or a focused test.

## Claim boundary

This work proves deterministic count, identity, retry, validation, and route
metadata behavior under the encoded tests. It does not prove that every
question is factually correct or instructionally optimal, that an instructor
approved the package, that accessibility needs are satisfied, or that classroom
outcomes improved. Scion remains a constrained system around the pinned public
Gemma base; no new weights or adapter victory are claimed.
