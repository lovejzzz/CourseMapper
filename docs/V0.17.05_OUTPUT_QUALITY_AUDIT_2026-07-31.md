# EDUTOOL v0.17.05 Output Quality Audit

**Audit date:** 2026-07-31

**Scope:** student- and instructor-facing content, visual formatting, accessibility, package integrity, and the trustworthiness of EDUTOOL's own quality proof
**Audit mode:** production download, current-code deterministic package, automated gates, rendered Office-file inspection, and code-grounded Roundtable review

## Executive verdict

**Not at a quality checkpoint.** The package is complete, opens cleanly, uses consistent visual styling, and preserves useful source-ledger evidence. It is not yet safe to present its current `99/A · 0 findings` seal as current release evidence.

The decisive problem is not merely awkward prose. The production ZIP downloaded from EDUTOOL v0.17.05 reused a grader v1.11.0 result from 2026-07-28. Regrading the identical 35-file package with the repository's current grader v1.11.6 changes the result to **89/B with four P1 findings** and lowers automated readiness from **69 to 59**. The ZIP export path accepts any precomputed graded result without requiring the current grader version.

The human-facing artifacts also reveal defects the automated score does not represent well: incomplete and formulaic slide language, repeated generic evidence-boundary prose, one fully blank Study Guide page, an 11-page syllabus for a four-lesson course with a one-row final page, and missing semantic table-header markup. These do not make the package unusable, but they make the quality seal overconfident.

## Findings

### P1 — Exported quality proof can be stale across grader versions

The production manifest says:

- grader v1.11.0
- package conformance 99/A
- zero findings
- automated readiness 69
- graded at 2026-07-28T16:51:20.313Z

Current grader v1.11.6 over the identical extracted files says:

- package conformance 89/B
- four P1 format findings
- format dimension 68
- automated readiness 59
- five texture advisories

All four P1 findings are assignment briefs that defer required submission logistics to configuration absent from the artifact, for example “submission format listed for” or “medium listed for the task.”

The defect is already detected in both finalizer/export checks and the deep grader, but there is no corresponding repair in `contentQualityRepair.js`. The current pipeline therefore knows this copy is defective without having a fix-forward path.

**Code cause:** `normalizePrecomputedPackageQuality()` in `src/lib/packageZipExporter.js:263` preserves an arbitrary `graderVersion`. The reuse branch at `src/lib/packageZipExporter.js:2264` checks readiness blockers and missing referenced files, but does not require `precomputed.graderVersion === GRADER_VERSION` or a matching package/content digest. Roundtable confirmed that the existing predicates address pre-repair staleness, not a persisted result crossing an application deploy. Because `GRADER_VERSION` is currently obtained inside the lazy grader import, the freshness comparison must either happen after that import or use a small statically imported version module.

**Impact:** the same package can truthfully report two materially different grades depending on which grader version last touched the workspace. That makes the seal auditable in metadata but not release-current.

**Acceptance criterion:** a ZIP finalized by v0.17.05 must either be regraded with the current grader/texture policy or explicitly carry a visible `stale proof` state that cannot be shown as clean. Regrading the downloaded ZIP and in-app finalization must be deterministic and agree on score, findings, readiness, grader version, and texture version.

### P1 — Automated excellence claims do not cover required teaching evidence deeply enough

Roundtable found a separate production artifact in which a lesson assignment required a recording/transcript excerpt, narrator-context note, and consent boundary even though no lesson source or referenced material supplied them. The package still received 99/A and zero findings.

**Code cause:** `assessmentCoherenceScore()` in `src/lib/quality/automatedReadinessSignal.js:206` is only a 60/40 average of substance and consistency conformance. Citation inspection in `src/lib/quality/deepQualityGrader.js:1974` scans syllabus and lesson-plan files, not whether each assignment, quiz, rubric, and slide has the evidence/materials it requires.

**Impact:** source retrieval can be incomplete, but the deterministic application still exports and certifies assessments that refer to unavailable evidence.

**Acceptance criterion:** each lesson should carry a required-material/evidence contract. Finalization must flag or block any assessment surface that refers to an unresolved source, artifact, transcript, dataset, prototype, or instructor-only configuration.

### P1 — Student-facing prose passes structural gates while remaining incomplete or procedural

Observed production examples include:

- “Students may assume students often treat ...”
- “Debrief: Use feedback to separate a solid WCAG principles and conformance.”
- “Today: Choose how ... evidence should shape the design decision for Evidence.”
- repeated cross-document phrasing about a cited passage, two competing interpretations, and the documented limit
- a slide source atom ending in an ellipsis instead of a complete inspectable claim

The current compiler also emits definitions such as “names the evidence focus” and “helps students separate description from evidence-backed reasoning” (`src/lib/courseBlueprintCompiler.js:18788-18792`). These explain how to use a term rather than what the disciplinary term means. Both `contentQualityChecks.js` and `deepQualityGrader.js` already identify these patterns, yet a direct current-code export still contained them.

**Impact:** outputs are superficially specific—course and lesson names are inserted—but learners receive thin disciplinary explanation and instructors must rewrite visible copy.

**Acceptance criterion:** add sentence-completeness, duplicated-subject, empty-object, and semantic-definition gates across slides, Study Guides, assignments, discussions, and speaker notes. A domain term definition must state domain meaning before any instructional-use sentence.

### P1 — The 14-lesson gold gate is currently blocked by repeated quiz distractors

`audit:gold:smoke` reports three repeated long-string groups in the community-health quiz bank. One option repeats four times and two options repeat three times, all at Question 8 across different lessons.

**Impact:** long courses expose deterministic option cycling that shorter gold samples do not reveal. The release's own curated quality gate is red.

**Acceptance criterion:** all 5-, 8-, and 14-lesson gold samples pass copy-specificity limits, with quiz stems, distractors, and answer rationales included in cross-lesson diversity checks.

### P2 — Layout is consistent but inefficient and sometimes empty

Rendered production artifacts show no obvious DOCX overlap or clipped body text. Branding, color, headings, and tables are consistent. However:

- The four-lesson syllabus occupies 11 pages; page 11 contains only one continuation row.
- The Lesson 1 Study Guide renders four pages, but page 4 is entirely blank except for header/footer furniture.
- The three-page assignment brief is dense and repetitive for a single evidence-explanation task.
- Current-code samples show the same pagination tendency: sparse final pages and long tables that are readable but hard to scan.

Roundtable traced the syllabus behavior to unconditional page breaks and policy-section emission in `src/lib/exporters/docxExporter.js`; page count is driven substantially by boilerplate rather than course length. The blank Study Guide page is the same class of deterministic export-layout behavior, not provider variance.

**Acceptance criterion:** no content-empty final page; no orphaned one-row continuation page when the preceding page can be reflowed safely; and a page-density warning for documents with extreme empty-area or table fragmentation.

### P2 — Slide format tests and visual inspection are not reconciled

The production Lesson 1 deck has a coherent theme. `slides_test.py` reports overflow on slides 1, 4, and 11, but full-resolution inspection of all three shows no student-visible text or content clipping; the flagged geometry corresponds to intentional decorative circles, backgrounds, or edge-to-edge footer shapes. Actual content problems remain on other slides: incomplete statements, generic prompts, excess empty space, and a source atom shortened with an ellipsis.

**Acceptance criterion:** classify decorative background bleed separately from semantic content overflow. The format score should fail only on content-bearing objects outside the canvas, clipped text, or unsafe margins; intentional full-bleed shapes should be explicitly marked or filtered.

### P2 — OOXML table accessibility is incomplete

The DOCX accessibility audit found:

- Study Guide: one medium `table_no_header_row` finding.
- Syllabus: two medium `table_no_header_row` findings.

Not every two-column key/value table needs a header row, so these counts require semantic interpretation. The Study Guide's term/definition table does represent column semantics and should expose headers.

**Acceptance criterion:** tables with column semantics use real marked header rows; key/value layout tables use a documented accessible alternative and are not blindly auto-fixed.

### P2 — Source reporting contains a trust-message contradiction

The production manifest reports six trusted, concept-linked sources and complete 48/48 structural source-reference coverage. `SOURCE_REPORT.md` later says trusted per-reference coverage proof is unavailable. These can both be technically true—aggregate trusted ledger rows versus absent per-reference proof—but the package does not explain the distinction clearly.

**Acceptance criterion:** source reports must distinguish structural refs, trusted ledger rows, and trusted per-reference resolution in one consistent matrix, with no reader-facing “complete” implication when per-reference proof is absent.

## Roundtable decision

After two rounds across Codex, Claude, and Antigravity, the synthesized decision ranked the work this way:

1. **Release blocker:** stale quality-proof reuse across grader versions. A clean current-release seal is not trustworthy until export requires a current grader identity and regrades on mismatch.
2. **Next structural quality fix:** a worst-lesson dependency matrix for all required evidence and materials. Aggregate grounding percentages alone cannot prove that each lesson is teachable from the package.
3. **Fix-forward P1:** assignment-configuration deferrals need a repair transformer or strict export gate, but the four findings alone were not classified as release blockers.
4. **Formatting debt:** deterministic page-break economy and semantic table accessibility should be corrected and rerendered.
5. **Quality-system expansion:** consumed-slot repetition should be measured across more file families, and representative 5-, 8-, and 14-lesson packages need external instructor evidence.

Claude and Antigravity confirmed the grader-version gap after the owner's steering note. Codex's recorded position, written before that evidence entered its turn, treated missing per-lesson learning evidence as the release blocker. This audit makes the final prioritization above: proof freshness first because it invalidates the visible seal, followed immediately by per-lesson dependency completeness.

The room did not settle whether aggregate grounded-fraction floors should become score-bearing; this audit favors the per-lesson dependency gate as the primary completeness control and grounded fraction as a supporting signal. PDF glyph and metadata risks remain code-level hypotheses until a current real PDF artifact is generated and inspected. The slide-overflow uncertainty was resolved after the discussion: slides 1, 4, and 11 use intentional decorative bleed and show no visible content clipping.

## What is working

- ZIP integrity and folder organization are reliable.
- Lesson coverage and file naming are consistent across the sampled package.
- DOCX/PPTX files render successfully in LibreOffice.
- The Office visual system is restrained, readable, and consistent.
- Source URLs, attribution, licenses, provider names, and concept links are preserved in the package.
- The quality report states an appropriate claim boundary: automated signals do not prove factual accuracy, accessibility, teachability, or instructor validation.
- Current texture auditing catches real cross-package repetition, and the current grader newly catches the assignment-logistics defect missed by v1.11.0.

## Recommended checkpoint gate

Do not freeze the next quality checkpoint until all of these are true:

1. Export rejects or visibly downgrades stale grader/texture proof.
2. Regrading the same ZIP in-app and out-of-app yields the same quality result.
3. The 5-, 8-, and 14-lesson gold audit passes.
4. Every assessment's required evidence and logistics resolve to package content or an explicit instructor-confirmation blocker.
5. Semantic prose gates reject incomplete sentences, procedural definitions, duplicated subjects, and unresolved placeholders across every student-facing file family.
6. Render QA has zero blank content pages, zero content-bearing slide overflow, and no unreviewed semantic-table accessibility findings.
7. At least one external instructor review is attached to each representative course length before claims move beyond automated readiness.

## Audit limitations

- The production course content was originally generated by v0.16.91 and re-exported by v0.17.05. It is valid evidence about current export/proof behavior, but not a clean-room v0.17.05 generation comparison.
- Provider-backed fresh generation was unavailable because no API key was present.
- Automated accessibility scripts do not replace screen-reader or keyboard testing.
- The deterministic harness's missing production registry bridge invalidates its identity/weight findings as product defects; those findings are excluded from the verdict.
- Roundtable's older package observations are used only where their code-backed mechanism remains present in the current tree.
