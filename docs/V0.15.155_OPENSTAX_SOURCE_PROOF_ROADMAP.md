# V0.15.155 OpenStax Source Proof Roadmap

## Evidence

The v0.15.147 GPT-5.5-pro Introduction to Computer Science with Python ZIP/log
evidence captured at
`verification-output/edutool-audit-loop/20260630T064106Z-v015147-gpt55pro-python/`
showed concrete OpenStax section rows being treated as review-only because the
generated row kept the textbook label but not the duplicated URL/license fields.

- Exported report: 93/A, texture 92, 0 P0, 2 P1, 12 P2
- Current-rule regrade: 94/A, citations 67, texture 92, 1 P1, 12 P2
- Source review examples: `OpenStax introduction python programming §4.2 (open textbook)`
  and sibling section labels
- These rows were real OER section labels, but `SOURCE_REPORT.md` rendered them
  as `license=missing; access=missing-url-or-doi; trustedBibliography=false`

The run is not a fair model comparison because the main P1 came from the older
GPT-5.5-pro `reasoning.effort: low` incompatibility, which later releases fixed.
This release targets the separate CourseMapper-side source-proof hydration seam.

## Scope

V0.15.155 keeps the release narrow:

1. Detect concrete OpenStax section labels that include a section marker or
   open-textbook cue.
2. Recover the canonical OpenStax book URL from the textbook title.
3. Attach CC BY 4.0 license proof to those rows when no explicit license was
   present.
4. Keep course-aware false-friend and topic-anchor gates intact, so a hydrated
   source still must be concept-linked and on-discipline.
5. Keep vague placeholders such as generic `OpenStax chapter` language out of
   trusted proof unless they carry concrete source evidence.

## Goal

Prevent real OpenStax textbook-section evidence from being downgraded to
review-only solely because CourseMapper lost duplicated access/license metadata
while preserving strict source truth for weak, metadata-only, or off-topic rows.

## Lane

Source-ledger normalization and grader truth. This is not a provider-model
prompt change, scorer-threshold change, source-trust broadening for arbitrary
publishers, or a new provider-score claim.

## Release Boundary

The release may claim concrete OpenStax section labels hydrate into licensed,
accessible, concept-linked source-ledger rows after focused source-ledger and
source-grader regressions pass. It may not claim a clean 100/100 package until
a fresh deployed v0.15.155 ZIP/log audit verifies real provider output.

## Verification Target

Ship only after focused source-ledger/source-grader tests, release-history
audit, and normal local gates pass. The next evidence step is a fresh deployed
v0.15.155 provider ZIP/log audit that confirms CS/Python OpenStax sections no
longer appear as missing-license review rows.
