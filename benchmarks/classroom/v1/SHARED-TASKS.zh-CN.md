# 共用教学任务：第二轮 compiler 改进

日期：2026-09-05（纽约）。基线：`f1c029317975597d184040926263d53f8b75e96d`。保留 0.18.7 界面、十项材料和本地 AI 路线。

本轮解决的是“每份材料分别拼接模板，题目、答案和评分依据没有共同核心”。现在先从同一课的已接纳事实建立任务，再投影为各份材料。四个单课案例的既有缺陷检查通过；两课时案例仍有五项失败。**这是一项有明确边界的 compiler 改进，不是通用任务生成已经完成，更不是模型训练或学习效果验证。**

## 实际管线

```text
来源与学习目标 → 已接纳、归属于本课的事实
                         ↓
共用任务：输入、问题、推理、答案、错误、反馈、评分条件、时间
                         ↓
教案 / 幻灯片 / 作业 / rubric / 讨论 / 测验 / 指南
课程图的活动与任务链接 / syllabus 的任务安排 / FAQ
                         ↓
既有语言整理与导出器 → 检查可见内容、真实 Word 与 PowerPoint
```

任务在各材料轮换来源事实之前选择，不会因为某份材料拿到另一段事实而改变答案。`taskId` 标识同一课的任务；`taskRevision` 覆盖内容。修改输入后重编会更新问题、答案与 rubric：回归测试把 `16/20` 改成 `3/8`，保留任务身份，修改 revision，验证不残留 `80%`。这是 compiler 重编的同步测试，不是一次新录制的浏览器 Smart Sync 全链路测试。

当前实现三种有明确来源关系的操作：确切比例计算、创作与入藏记录比较、带有明确混淆因素及修复原则的实验比较。它们从来源提取数字、事件或变量，不根据课程名称填入固定的年代、肥料或光照。缺少必要记录、关系不明确、多个实验混在一起时不生成该任务。已有作者作业、活动或更强 worked example 保留。尚未让 Scion 为任意学科稳定写出这个完整契约；不支持的输入仍走原有管线。

编号事实中的分号曾切断“分组条件—结果指标—因果限制”，还可能漏掉 `Use only these supplied facts.` 后的整个来源段。本轮修复这个入口，并保留完整的编号记录。历史日期必须与对应事件匹配，不能把前面的四位馆藏编号当作年份。

## 任务、答案和 rubric 的实质变化

| 案例     | 现在可核查的任务与答案                                                                     | 区分理解程度的依据                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| 比例课   | `16/20 = 0.80 = 80%`，反算 `0.80 × 20 = 16`；解释志愿者记录与夜班人员缺席的边界            | 分母颠倒、只有正确百分比而没有过程、转换正确但缺反算、把观察比例推广到全体，是不同的缺口                             |
| 历史记录 | 1921 对应创作，1978 对应入藏；说明为何不矛盾；维修年份未知，旧字迹不证明完整历史           | 区分事件与来源、解释两日期关系、区分观察与无依据推断，分别评分                                                       |
| 实验设计 | 施肥/不施肥与八小时/四小时光照同时变化；两周株高是结果；随机分组、光照相等、种子和水量一致 | 只背变量定义、只指出光照不同、解释替代原因、完整指定修复方案，分别落入不同档位；“多加植物但保留原条件”不能获得修复分 |

四档不是换成不同程度的“清晰、深入、充分”。例如修复设计的 Proficient 档要求变量控制和随机分组正确，但遗漏结果测量；Developing 档遗漏随机分组或既定控制；Beginning 档仍保留系统性的条件差异。完整答案和典型错误也直接进入 rubric 的评分校准区。

对 `reference-tasks.json` 中的对比答案进行了人工判断：比例的无依据总体推广必须落在 scope 的 Beginning；倒置分母落在 part-whole 的 Beginning。历史“不同日期所以一份必假”落在 relationship 的 Beginning；把入藏年份当维修年份落在 inference-limit 的 Beginning。实验“增加样本但保留不同光照”落在 repair 的 Beginning；只写 dependent variable 定义不满足实际条件识别。这里记录的是 Codex 对指标区分能力的判断，没有外部教师一致性数据，也没有给真实学生自动打分。

quiz 保留配置题数、作者题、选择题及机器评分边界，将可确认属于 compiler 的书面题位替换为完整任务、错误诊断、分步问题与检查。实验案例的八题中六题共用任务，另两道作者题保留。学生题面同时包含来源记录，并明确这是已教案例的练习。重复同一案例的六种提问不能当成六个独立迁移测验。

## 同一 benchmark 的结果

输入、独立 checker 和参考任务均未改写；仍是五个小型英文案例、50 个“案例 × 材料”组合、295 项缺陷检查。本轮零次新模型调用。历史与实验案例继续使用先前保存的模型 kernel；不能称作新的本地 Scion 生成。

| ------------------------- | -------: | -------: |
| local-proportions         |        1 |        0 |

| historical-sources        |        3 |        0 |

295 项中没有命中 critical 探针。这个数字不是教育质量百分比。严格模式仍必须返回失败。完整检查摘要、输入与输出哈希见 [本轮结果](results/shared-tasks-2026-09-05.json)。基线是真实改动前保存的输出，没有用新 compiler 重建基线。

本轮 runner 对冻结课程图调用了产品实际 reconciliation 路径，因此 Course Map 现在也是被编译的输出。旧报告中的 Course Map 是捕获输入。两种模式在 receipt 中区分；本次减少的八项失败均不来自 Course Map。耗时只代表蓝图编译及 reconciliation，不含模型、导出和浏览器。

| Course FAQ         | 3 / 3 / 3 / 3 | 一页、六个简短答复，提交物、三项权重、修订方式和时间一致。课程制度以教师实际设置为准。                                                          |

三个案例合计导出 24 份 Word 与 3 份 PPTX，串行渲染并审阅其中 14 份 Word（31 页）及全部 38 页幻灯片。比例课和历史课也各生成全部八份 Word 与一份 PPTX，重点渲染作业、rubric、指南及幻灯片；没有把未渲染的其他文件标成版式通过。完整私有输入、JSON 输出、DOCX、PPTX、PDF、PNG 与渲染日志保存在 `.audit-work/shared-task-2026-09-05/`，不进入网站包。

导出检查实际发现并修复了 Word 类型契约错误（数组字段被赋成字符串等），以及 PPTX 的旧布局残留。自动回归测试直接打开八种 Word 的可见 XML 和 PowerPoint 的 slide XML，检查来源、答案与字段契约；这和人工看渲染页面是两种不同的检查。

## 验证与明确未完成的能力

本地完成：类型检查、lint、58 项 Studio、129 项兼容性、649 项 Scion 相关测试、8 项 checker 变异测试、生产构建与 bundle 检查。发布流程中的 Chromium 与 adapter 测试另由 CI 执行，发布结果以对应提交的 workflow 为准。

两课时案例仍失败于教师检查答案、幻灯片密度、自学可答性、第二课时完整例题与 FAQ 简洁性。上游将第一课时诊断目标泛化，并丢失/分配不全实际分组条件，任务不能安全接纳。把整段全局来源强行复制给所有课会掩盖跨课污染，故没有以此清零检查。

下一步应让 Scion 在作者层产生完整、带来源归属的任务契约，并为诊断→修复→陌生情境迁移建立跨课任务依赖。这个契约需要更广的独立案例、无答案练习和外部教师评分校准。当前有界规则不构成“前无古人”的技术证据，也不能替代这些工作。

发布验证另发现 Pages 的取消组按整个仓库共享：分支 CI 结束触发的 skipped 部署会取消 main 的正式部署。已按来源分支隔离该组。浏览器测试更新为六道共用练习，并定位可见的检查题；单条本地重生成回归及完整 33 项 Chromium 回归已通过，没有请求模型。

本轮发布版本为 **0.18.8**，界面基线仍为 0.18.7。上线复查另外暴露了新建入口提前删除上一课程恢复记录的问题：进入材料选择时保留原存档，取消后可以恢复原课程；为 localStorage、IndexedDB 和 compact pointer 三条路径补上浏览器回归。此修复不会找回此前已经删除的恢复记录。
