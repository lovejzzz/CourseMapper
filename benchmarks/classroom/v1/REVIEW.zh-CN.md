# 课堂材料 benchmark 与第一轮改进

日期：2026-09-05。基线 compiler：`379e5e62`。本轮保留 0.18.7 界面、十项材料、本地推理与原有导出选项。

**结论：目前最需要加强的是教学任务本身。材料数量、内容长度、来源引用和格式字段齐全，不能证明学生能学会、教师能教会。** 比例课的演算和学习指南已经有实际用途，但 rubric、开放题、讨论、作业样例仍有严重模板化。本轮修复了一批共因，没有达到 v0.19.0 的发布标准。

## 评估范围与方法

- 冻结五个输入：真实本地 Scion 比例课、两份已保存的模型课程 kernel，以及改变数字和增加第二课时的两个构造案例。所有案例均是短篇英文课程；没有证据支持跨年龄、跨语言、全学期的质量结论。
- 每个案例编译十项材料，共 50 个“案例 × 材料类型”组合、295 项缺陷检查。原始课程图是冻结输入，不会因下游改进获得额外评价。
- 本轮 **零次新模型调用**。历史和实验设计 kernel 来自先前已保存的在线生成，不能称作这次的本地 Scion 测试。重放用于隔离 compiler 效果，不能证明 adapter 或基础模型变强了。
- 独立 checker 不导入产品内的质量 grader。另用四项 0–4 分判断：正确性、教学实质、可用性、对齐与一致性。不计算总分；未知项记 `null`。三份真实输入的 30 项材料有逐项评语和字段证据，见 [人工评审记录](results/manual-review-2026-09-05.json)。两个构造扩展案例只有自动回归与局部审查，未冒充完整人工评分。
- [参考任务](reference-tasks.json)给出按输入事实独立编写的答案、必需推理、错误学生答案及反馈。它们不传入生成器。例：rubric 应能区分“算出80%但泛化到所有成人”和“计算正确且说明排除夜班人群”。
- 使用项目实际 exporter 导出比例课的八份 DOCX 和一份 PPTX；渲染并查看全部 18 页 Word、12 页幻灯片。Course Map 本轮审查内容，没有新增 XLSX 视觉验证；其他案例的渲染表现仍未知。未声称在 Microsoft Word/PowerPoint 或所有 Google 导出格式中实测。

完整输入、输出、检查日志和渲染文件保存在本地 `.audit-work/output-benchmark-2026-09-05/`。可提交的 corpus、检查器、参考任务、结果和评审均位于本目录及 `scripts/benchmarks/`。

本轮完整重放中，单案例的 blueprint 构建及衍生材料编译约 0.11–0.89 秒；这不包括模型生成、启动、导出或浏览器交互耗时。

历史课的学习指南尤其暴露问题：所谓 worked result 是“判断第二条是否 reinforces、qualifies 或 conflicts”，并没有给出1921年创作与1978年入藏为何不矛盾的解答。实验课教师检查只问 dependent variable 定义，却声称对应“识别混淆并提出设计修复”。这是教学需求失配，不是多加几句解释能解决的问题。

两个历史 kernel 的纠错句本身已有缺主语问题，例如实验课的“It is incorrect that the result of the experiment”。本轮没有把重放包装成修好了模型作者层。实验课原始 kernel 的五条 facts 还省略了输入中具体肥料/光照分组与两周结果的两条事实；下游拥有输入来源仍不足以保证会选择这些关键事实来构造任务。

## 本轮已经实现的改进

1. 修复事实投影场景的虚构材料，并重新生成明确标记为 compiler 所有的旧场景。实际作者场景保留。
2. 短比例课的 compiler 作业 fallback 使用计算、转换、反向检查和简短解释；讨论针对结论范围，避免把已验证等式包装成事实立场争论。
3. 普通重复说明仍可压缩，但参考答案、评分指引和教师检查中的完整事实不再被替换成空泛提示。来源隔离检查仍先执行。
4. 教学程序读取真实 schema 的 `correction` 字段，练习数量达到上限时仍保留来源限制题。
5. 单课 syllabus 描述与meeting保留单课范围及主题；教案课后反馈不再指向不存在的学期最终综合任务。这不是全部单课模板清理完成。
6. 比例幻灯片显示四个完整计算动作。修复依赖标题选择布局的错误，实际PPTX不再把计算步骤换成另一份证据表；也不把decimal、percentage、count放在同一条形图比较。
7. 适用的确切比例课用共享教学程序替换一个通用 quiz 席位，生成真实计算与答案。保留题数、作者题及机器评分配置边界。直接检查DOCX可见XML中包含题目和答案。

已运行类型检查、lint、58项Studio测试、129项兼容性测试、642项Scion相关测试、8项独立checker错误样例测试、生产build及bundle检查。类型/测试通过不等于教学通过；严格benchmark仍因13项已知缺陷返回失败。

## 我建议的核心技术方向

**把“可验证的教学任务”作为材料共用的数据单位。** 现有compiler擅长扩展材料外壳，但许多部位仍独立拼接“主题＋证据＋决策＋修订”。结果是十份材料都很长，却没有共同的具体问题与答案。继续增加句式库会加重这一点。

可以在已有 `compilerTeachingProgram` 的小范围能力上建立明确契约，而不是再建第二套平行管线：

```text
用户目标 + 来源中的必要事实
             ↓
Scion构造少量教学任务
目标、所需输入、问题、推理、参考答案、典型错误、评分条件、预计时间
             ↓
校验输入是否齐备、推理和答案是否成立
             ↓
同一任务编译为教案、幻灯片、作业、rubric、测验、指南
             ↓
核对实际导出的可见内容；编辑后只重编受影响的任务与材料
```

Scion应把有限token用于选择关键事实、设计问题、给出可验证解答，少写制度、排版和重复扩展文字。Compiler负责可确定的变换、数值验证、版面分配和依赖同步。它不会因此变成能自由推理的小模型；真正可积累的价值是任务契约、可审计的学科操作、错误反馈与编辑后的一致性。

具体改进顺序及验收：

1. **答案与任务绑定。** 历史课必须明确给出两个日期对应不同事件；实验课必须展示光照混淆及真实修复方案。缺解答的任务保持“需要教学内容”，不能用过程描述当答案填满字段。
2. **Rubric先接受学生答案检验。** 以参考文件中的正确、部分正确和错误回应校准等级；评分必须随具体错误变化，不能只看source traceability或措辞成熟度。
3. **统一时间与提交量。** 同一task ID决定课堂活动、讨论时长、作业范围与rubric要求。单课不能继续产生学期综合、周常政策或不相称负担。
4. **导出保真成为回归门槛。** 对每个重要问题/答案检查Word和PPTX的可见内容；实际渲染检查孤立标题、长表格、字号和书写空间。当前新增的计算导出测试是第一步。
5. **扩大评估，不用训练题自证。** 下一批增加小学、语言课、多节课、缺来源及错误来源案例；在看结果前写好参考要求。两个现有扩展案例已经被使用，不能再称为永远未见的测试集。
6. **再做本地模型对照。** 固定设备、温度、token上限和来源，串行比较基础模型与候选adapter的任务正确率、完整参考答案率和端到端时延。当前证据不足以断言adapter必要、无效或已经达到最佳水平。

这一方向保留蓝图后快速编译和本地运行的优势，也把质量目标落实到可检查的教育行为。首要验收是教师和学生能用这些问题、答案和反馈完成学习任务，而不是生成更多页数或获得更高的内部总分。
